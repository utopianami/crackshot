## 목적

**Non-Top200 ~600종목에서 돈 벌기.** 그게 다.

- 모델: 뭐든 상관없음 (CS-MLP, TabM, 새 모델 등)
- Feature: 뭐든 상관없음 (105feat, alpha101, 새 feature 등)
- 학습 유니버스: 뭐든 상관없음 (837 전체든 600이든, 결과만 좋으면)
- 평가 기준: **Non-Top200 백테스트 실제 alpha**

---

## 현재 상태

| 모델 | 대상 | 실제 alpha | 비고 |
|------|------|-----------|------|
| AG CLS baseline | Non-Top200 | **+33.2M** | 105feat, 종목별 독립 학습 |
| CS-MLP (모든 변형) | Non-Top200 | **-1.7M ~ -21.5M** | cross-sectional z-score → beta만 학습 |

## 확인된 사실

1. **Non-Top200에 signal이 있다** — feature-label 상관이 Top200보다 2.2~3.8배 높음
2. **AG CLS가 같은 105feat으로 +33.2M alpha** — 종목별 독립 학습으로 성공
3. **CS-MLP의 cross-sectional z-score가 beta를 만든다** — vol_rank 등이 대형/소형 구분 인코딩
4. **Sim CumAlpha와 실제 alpha가 무관** — sim beta(837 equal-weight) ≠ backtest beta(cap-weighted)
5. **105feat은 핸드크래프트** — 더 좋은 feature가 있을 수 있음
6. **Non-Top200 89%(567종목)는 active** — 데이터 품질 문제 아님

---

## 가설 + 실험 계획

### H1: 종목별 독립 학습이면 Non-Top200에서 alpha 가능

**근거**: AG CLS가 증명. cross-sectional 묶음이 문제지, 종목별로 하면 됨.

| # | 실험 | 구체 내용 |
|---|------|---------|
| H1-1 | **TabM + 105feat 837종목** | per-sample 학습, PLE binning으로 스케일 흡수. CS 없음 |
| H1-2 | **TabM + 105feat 600종목** (Top200 제외) | 학습 유니버스에서 Top200 빼도 되는지 |
| H1-3 | **TabM + alpha101 837종목** | Top200에서 best였던 feature가 TabM에서도 먹히는지 |

### H2: Cross-section을 유동성 버킷 내로 제한하면 alpha 가능

**근거**: Top200끼리 CS-MLP가 잘 됨 = 균질한 그룹 내 cross-section은 유효. 600종목도 유동성 비슷한 그룹끼리 묶으면?

| # | 실험 | 구체 내용 |
|---|------|---------|
| H2-1 | **Bucketed CS-MLP** (3 bucket: 대/중/소) | 유동성 기준 3그룹, 각 그룹 내 CS z-score |
| H2-2 | **유동성 상위 300종목만** CS-MLP | Top200 빠져도 나머지 중 유동성 높은 종목만 |

### H3: Temporal z-score (종목 내 rolling)로 바꾸면 alpha 가능

**근거**: AG CLS가 종목 내 시계열 패턴을 학습. CS z-score 대신 종목별 rolling z-score를 쓰면 cross-sectional 오염 없이 정규화 가능.

| # | 실험 | 구체 내용 |
|---|------|---------|
| H3-1 | **105feat + per-stock rolling 390-bar z-score** → CS-MLP | NPY 단계에서 temporal z-score 적용 |

### H4: Feature를 개선하면 alpha 가능

**근거**: 105feat은 핸드크래프트. Non-Top200 signal이 있으니 더 좋은 feature로 더 많이 잡을 수 있음.

| # | 실험 | 구체 내용 |
|---|------|---------|
| H4-1 | **105feat + alpha101 novel features** (ret_autocorr, vwap_dev) | 105feat에 없는 group-neutral signal 추가 |
| H4-2 | **105feat에서 group-biased feature 제거** (vol_rank 등) | 105v2 NPY 이미 있음 |
| H4-3 | **raw OHLCV 직접 학습** (TabM으로) | feature engineering 없이 모델이 스스로 추출 |

### H5: Sim 평가를 고치면 실험 효율 대폭 향상

**근거**: 현재 sim에서 좋아 보여도 backtest에서 나쁨 → 매번 backtest 필요. sim beta를 고치면 실험 루프가 빨라짐.

| # | 실험 | 구체 내용 |
|---|------|---------|
| H5-1 | **eval_k200.py beta를 Top200 평균으로 교체** | sim alpha ≈ 실제 alpha가 되도록 |

---

## 실험 순서 (효율 기준)

1. **H5-1**: sim 평가 고치기 — 이후 모든 실험의 효율 향상
2. **H1-1**: TabM 105feat 837종목 — 가장 빠르게 "per-sample이면 되나?" 검증
3. **H1-2**: TabM 600종목 — Top200 유무 효과 확인
4. **H2-1**: Bucketed CS-MLP — CS 방식 살릴 수 있는지
5. **H4-1~3**: Feature 실험 — H1/H2 best 모델로 feature 탐색
6. **H3-1**: Temporal z-score — 위 결과 불충분 시
