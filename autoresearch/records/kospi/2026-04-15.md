## 아키텍처 민감도 — 왜 TabM만 collapse?

FT-T도 PLE bin 사용하지만 sentinel 0.05%. 차이는 PLE 뒤의 encoder 구조.

| 구조 | TabM | FT-T |
|---|---|---|
| PLE bin | 48 | 96 (2x) |
| Encoder | BatchEnsemble MLP (K=32) | self-attention |
| Ensemble | rank-1 scaling + softmax 평균 | 단일 forward |
| block_dropout | 0.35 | — |
| feature 간 mixing | MLP dim mixing | attention token mixing (scaled dot-product) |

유력 가설 (가장 가능성 높은 순):
1. **BatchEnsemble rank-1 cancellation** — 극단 input에서 rank-1 perturbation이 relatively 작아져 K=32 멤버 output이 유사해짐 → 평균 = class prior
2. **MLP saturation** — `dense(extreme_input)`이 ReLU/GELU 포화 영역 진입
3. **block_dropout 0.35** — 극단 feature가 자주 mask되어 학습 부족
4. **PLE 48 bin의 coarse resolution** (부차적)

## 개선 방향 (실험 후보)

우선순위 순:

### A. Feature-side 수정 (간단, 우선)
1. **tv_per_avg 값 clip** — `log1p` 대신 `tanh(log1p(x))` 또는 clip [-3, 3]
2. **Robust scaling** — per-stock z-score로 종목 고유 스케일 제거
3. **Rank/percentile 변환** — 절대값 대신 시장 내 분위수로 (대장주=1.0, 중간=0.5 등)

### B. 모델 아키텍처 수정
1. **block_dropout 낮추기** (0.35 → 0.1~0.15)
2. **PLE n_bins 늘리기** (48 → 96 or 128)
3. **BatchEnsemble 대안** — rank 늘리거나 MiniEnsemble 사용 (TabMmini 클래스)
4. **LayerNorm 추가** — extreme activation 완화

### C. 학습-side (minor)
1. 대장주 upweight (거래대금 상위 N 종목 loss weight ↑)
2. tv_per_avg 고값 구간 oversampling
