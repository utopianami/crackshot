## 배경

현재 153개 feature는 1분봉 OHLCV에서 hand-crafted로 추출:
- 6 Time (sin/cos 시간/요일)
- 12 Volume (정규화, 시장대비, 상승/하락봉비)
- 130 Price (10개 가격쌍 × log diff × 5 window + 정규화 + 꼬리 + std)
- 5 Rank (거래량 순위)

핵심 의문: **딥러닝 시대에 hand-crafted feature가 맞는가?**
- Raw OHLCV 시계열 모델은 전멸했지만, z_score 없이 돌린 것이라 공정 비교 아님
- 153개 feature 대부분이 `log(price_a) - log(price_b)` 형태로, 사람이 미리 정한 조합

## 실험 방향

### dir 1: 기존 방식 개선 — 더 나은 feature 찾기
목표: 153개에 빠진 정보 추가하여 성능 개선
모델: CS-MLP [64] (가벼움, 실제 학습됨, 빠른 실험)

**추가 후보 feature**:

| 카테고리 | feature | 근거 | 현재 상태 |
|---------|---------|------|----------|
| 모멘텀 | 누적수익률 (5/30/120min) | 추세 강도. 현재는 1시점 diff만 있음 | 없음 |
| RSI | 상승폭/(상승폭+하락폭) | 과매수/과매도 신호 | price_inc_per_dec과 유사하나 다름 |
| 변동성 regime | 단기vol/장기vol 비율 | 변동성 확대/축소 국면 | candle_std는 있으나 비율 없음 |
| 수익률 자기상관 | rolling corr(ret_t, ret_{t-k}) | 추세 vs 반전 신호 | 없음 |
| 가격-거래량 상관 | rolling corr(ret, vol_change) | 스마트머니 방향 | 없음 |
| Price rank | 종목간 수익률 순위 | 현재 volume rank만 있음 | 없음 |
| VWAP 괴리 | (close - vwap) / vwap | 기관 매매 방향 | vwap_ratio는 있으나 다른 형태 |
| 거래량 가속도 | vol 변화의 변화 (2차 미분) | 거래량 급증 감지 | 없음 |

실험 방법:
1. 새 feature extractor 작성 (기존 코드 참고, `/src/feature/` 또는 별도)
2. 기존 153 + 신규 feature로 NPY 생성
3. CS-MLP [64]로 빠르게 A/B 테스트
4. 유효한 feature만 남기고 최종 모델([256,128])로 확인

### dir 2: 패러다임 전환 — Raw data + Cross-sectional DL
목표: hand-crafted feature 없이, raw candle에서 모델이 직접 feature 학습
핵심: **cross-sectional z_score는 유지**, 모델이 feature engineering을 대체

**단계적 실험**:

| 단계 | 입력 | 모델 | 핵심 검증 |
|------|------|------|----------|
| 2a | raw OHLCV 6개 × z_score = 18dim | CS-MLP [64] | raw+z_score만으로 신호 있는지 |
| 2b | raw + rolling(5,30,120min) 수익률 = ~30dim | CS-MLP [64] | 시간창 추가 효과 |
| 2c | raw multi-timeframe 전체 | CS-MLP [64] | 어디서 성능이 수렴하는지 |
| 2d | raw candle sequence → 1D-CNN → z_score → MLP | hybrid | 모델이 feature를 학습 |

2a~2c는 코드 변경 최소, 2d부터 새 아키텍처 필요.

**미실험 핵심**: raw OHLCV → cross-sectional z_score → MLP (이 조합을 아직 안 해봤음)

## 새로운 실험 계획

### Phase 1: 조사 — 문제 정의 + 방법론 서베이

목표: "어떻게 feature를 설계할 것인가"에 대한 철학 수립

**1-1. 우리 문제 정확히 정의**
- 입력: 200종목 × 1분봉 OHLCV × ~390분/일
- 출력: 120분 후 상대 수익률 ranking (cross-sectional)
- 제약: 실시간 추론, 거래비용 존재, beta 제거 필수
- 질문: alpha의 원천이 뭔가? (가격 패턴? 거래량 이상? microstructure? 유동성?)

**1-2. 기존 153feat 기여도 분석**
- Feature importance (permutation, SHAP 등)로 실제로 뭐가 기여하는지
- 153개 중 redundant한 것, 실제 유효한 것 분류
- derived7이 왜 잘 작동하는지 근거 확보

**1-3. 문헌 조사**
- Cross-sectional equity factor 설계 (단기 alpha factor 논문)
- 금융 시계열 정규화 전략 (z-score vs rank vs quantile, 시계열+횡단면 결합)
- Feature engineering vs learned representation 비교 연구

### Phase 2: Feature Engineering — 철학 기반 설계

Phase 1 조사 결과를 바탕으로:

**2-1. 정규화 전략 실험**
- 현재: 순수 cross-sectional z_score (현재 시점 200종목만)
- 대안: 시계열 z_score (종목별 rolling window), rank normalization, 결합
- 핵심 질문: "삼성전자의 log_return 0.5%가 평소 대비 큰 건지"를 반영해야 하지 않나?

**2-2. Alpha 원천 기반 feature 설계**
- Phase 1-2에서 확인된 유효 factor 기반
- "이 feature가 왜 alpha를 만드는가"에 대한 가설 → 검증

**2-3. 최종 모델 검증**
- 유효한 feature는 [256,128] pnl=2.0으로 확인 (실제에서 통하는 구성)
- [64]로 스크리닝 → [256,128]로 확인 → 실제 백테스트

### Phase 3: Learned Feature Extraction — 모델이 feature를 학습

목표: `raw OHLCV → 학습 가능한 feature extractor → latent z → CS-MLP`

**3-1. Pre-train 방식**
- Autoencoder: raw candle sequence → encoder → z → decoder (reconstruction)
- Contrastive Learning: 같은 종목 다른 시점 = positive pair
- VQ-VAE: discrete latent code → regime 자동 분류
- 학습된 z를 feature로 고정 후 CS-MLP 학습

**3-2. End-to-end 방식**
- 1D-CNN → z_score → MLP (conv가 feature extraction)
- Temporal Fusion: multi-horizon attention
- raw → feature extractor + prediction을 동시 학습
- 장점: task-specific feature 학습. 단점: 과적합 위험

**3-3. 핵심 설계 질문**
- Cross-sectional z_score를 어디에 넣나? (raw → FE → z_score → MLP? raw → z_score → FE → MLP?)
- Pre-train이 나은지 end-to-end가 나은지 (데이터 양, 과적합 고려)
- Latent dim은 얼마가 적절한지 (현재 derived7=7dim이 최적이라는 단서)

## Phase 3 실험 결과

### 3-2a. End-to-end 1D-CNN → CS z-score → MLP

| # | 모델 | 데이터 | L CumAlpha | L+S CumAlpha | L WR | L Trades | status |
|---|------|--------|-----------|-------------|------|---------|--------|
| 1 | CS-CNN [32,64]→16 seq=30 | derived7 | -114% | -74% | 12.0% | 2,188 | crash |

**실패 원인 분석**:
- Per-stock CNN은 각 종목 독립적으로 temporal feature를 추출
- 추출된 latent를 cross-sectional z-score로 비교하면 각 종목의 latent 의미가 다를 수 있음
- CS-MLP는 이미 정규화된 feature를 받는 반면, CNN은 raw 시퀀스 → latent → 사후 정규화라 비교 부정확
- L WR 12.0%: 거의 anti-predictive → z-score가 의미 없는 비교를 생성

**설계 문제 답변**:
- Q: z-score를 어디에 넣나? → A: CNN 뒤에 넣으면 실패. **CNN 전에** 넣거나, CNN이 모든 종목을 동시에 봐야 함
- 대안 1: 입력을 cross-sectional z-score → CNN (normalized input sequence)
- 대안 2: Transformer with cross-attention (모든 종목 동시 처리 = MASTER 아키텍처)
- 대안 3: CNN feature를 기존 153feat에 concat하여 보조 feature로 사용

### 3-3. MASTER Cross-Stock Attention (Li et al., AAAI 2024)

| # | 모델 | 데이터 | L CumAlpha | L+S CumAlpha | L WR | L Trades | status |
|---|------|--------|-----------|-------------|------|---------|--------|
| 1 | CS-MASTER d=64,h=4,L=2 | 153feat raw_mean_zscore | +206% | +656% | 51.2% | 2,778 | crash |

**실패 원인 분석**:
- epoch 0 best → attention이 학습을 방해. val_loss 1.504 → epoch 5에서 1.572로 즉시 과적합
- L WR 51.2% = 랜덤 수준. attention이 cross-sectional 정보를 효과적으로 활용 못함
- 가능한 이유: (1) aug_dim=459에 d_model=64는 너무 압축, (2) 200종목 self-attention은 O(S²) 계산량, (3) 원래 MASTER는 temporal+spatial attention 결합인데 spatial만 사용
- **CS-MLP의 raw_mean_zscore가 이미 cross-sectional 정보를 잘 요약**하고 있어서, attention 추가가 오히려 noise

### Phase 3-6: FactorVAE (Duan et al., AAAI 2022) — Latent Factor Model

**아이디어**: Feature Encoder → Factor Encoder (K latent factors via VAE) → Factor Decoder (reconstruct returns) + Classifier.
Loss = CE + 0.01*KL + 0.1*Recon_MSE + 0.15*ListNet. raw_mean_zscore 사용.

**Config**: embed_dim=64, n_factors=8, hidden_dim=128, dropout=0.4, pnl=1.0

### Phase 3-7: Contrastive Learning (TS2Vec/SupCon 적응) — Supervised Contrastive Auxiliary Loss

**아이디어**: CS-MLP backbone + projection head → 같은 class label 종목은 embedding을 가깝게 (SupCon loss).
Loss = CE + 0.1*SupCon + 0.15*ListNet + pnl=1.0.

**Config**: hidden=[256,128], proj_dim=64, contrastive_tau=0.1, contrastive_weight=0.1

**분석**: L WR 51.8% 거의 랜덤, L CumRet -84% 음수. Contrastive loss가 classification 학습을 방해.
