## 배경: 03-26~27 실패의 근본 원인

5개 에이전트 리서치 결론 (opus×2 + sonnet×3):

1. **Cross-sectional variance collapse**: NQ 값이 200종목 동일 → alpha label(= 종목수익률 - 시장평균) 예측에 구조적으로 무관
2. **FT-Transformer attention dilution**: 상수 token이 attention budget 소비 → Morning IC -52% 하락
3. **섹터 ETF 7개 버킷으로는 불충분**: 같은 섹터 내 분산 = 0
4. **MASTER gating의 gate output이 전종목 동일**: α_i(t) = α_j(t) → 구조적 실패 + NaN bug

**핵심 원리**: 성공적 cross-market signal은 반드시 `per_stock_signal_i = sensitivity_i × market_signal` 형태여야 한다.

학술 근거:
- "From Macro to Micro" (IRFA 2024): per-stock macro beta가 cross-sectional return 예측
- "NeuralBeta" (ICAIF 2024): 시변 beta 추정에 deep learning 활용
- CSPO (WWW 2025): cross-attention으로 종목별 다른 시장 가중치 학습
- Kwon (2015): 한국 주식은 미국 overnight에 과잉반응 후 장중 되돌림, 큰 움직임에서만 유의미

## 실험 1: Per-Stock Rolling Beta Signal

### 아이디어

종목별 60일 rolling OLS beta를 사전 계산 → beta × overnight return을 feature로 추가.
삼성전자(SOX beta=1.3)와 STX(SOX beta=0.1)이 같은 SOX +2% 날에 다른 signal값을 가짐.

### Feature 설계 (sig111 + 2~3개 = 113~114feat)

| 인덱스 | 피처 | 설명 | CS variance |
|--------|------|------|-------------|
| 0:111 | sig111 base | 기존 그대로 | — |
| 111 | nq_beta_signal | beta_nq[i] × nq_ret[today] | 200 unique values |
| 112 | sox_beta_signal | beta_sox[i] × sox_ret[today] | 200 unique values |
| 113 | nq_beta_raw | beta_nq[i] (종목 특성) | 200 unique values |

### Rolling Beta 계산

```python
# 각 종목의 일봉 수익률 추출 (enriched candle의 마지막 bar close 사용)
# rolling OLS (window=60, min_periods=30):
#   beta_nq[stock_i, date_d] = cov(r_i, nq_ret) / var(nq_ret) over [d-60, d)
#   beta_sox[stock_i, date_d] = cov(r_i, sox_ret) / var(sox_ret) over [d-60, d)
# look-ahead bias 없음: date d의 beta는 d 이전 60일만 사용
# NaN 처리: 첫 30일은 cross-sectional mean으로 fill
# 클리핑: [-0.5, 3.0]
```

### 구현 파이프라인

1. `scripts/compute_stock_daily_returns.py` — enriched candle에서 종목별 일봉 수익률 추출 → `stock_daily_returns.parquet`
2. `scripts/compute_rolling_beta.py` — stock returns × ETF returns rolling OLS → `stock_rolling_beta.parquet`
3. `scripts/create_beta_signal_npy.py` — sig111 NPY + beta signal feature 결합 → `260328_beta_signal_alpha/`
4. config: `configs/ft_transformer_beta.yaml` (113feat)

## 실험 3: CLS Token Conditioning (FT-Transformer 전용)

### 아이디어

NQ를 별도 feature token으로 추가하지 않고, CLS token에 conditioning.
attention matrix 크기 변화 없음 (112×112 유지) → attention dilution 제로.

### 아키텍처 변경

```python
# 현재: CLS는 고정 learnable vector
seq = jnp.concatenate([self.cls_token[None, :], tokens], axis=0)

# 변경: CLS에 market feature conditioning
# market_features = nq_ret, nq_gk_vol, nq_trend_str 등 (3~5개 스칼라)
market_embed = self.market_proj(market_features)   # Linear(n_market → d_token)
conditioned_cls = self.cls_token + market_embed
seq = jnp.concatenate([conditioned_cls[None, :], tokens], axis=0)
```

### 구현

1. `src/models/architectures/ft_transformer_conditioned.py` — FT-Transformer 서브클래스, market_proj 추가
2. `src/config/models/ft_transformer_conditioned.py` — n_market_features 하이퍼파라미터
3. `src/training/trainers/ft_transformer_conditioned.py` — NQ feature를 별도로 분리하여 전달
4. `scripts/create_conditioned_npy.py` — sig111 + NQ 3~5개 append → `260328_conditioned_alpha/`
5. config: `configs/ft_transformer_conditioned.yaml`

## Phase 0: IC 사전 스크리닝 (학습 전 필수)

### 목적

NPY 생성 후, 학습 전에 각 feature의 예측력을 검증.
IC < 0.005인 feature는 drop → 학습 시간 절약, noise 방지.

### 방법

```python
# Python REPL에서 실행 (10~30분)
import numpy as np
from scipy.stats import spearmanr

X = np.load("260328_beta_signal_alpha/X.npy", mmap_mode="r")
y = np.load("260328_beta_signal_alpha/y.npy", mmap_mode="r")
alpha = y[:, 21]  # c2c_120 alpha

# 각 feature별 rank IC (test split만)
for i in range(111, X.shape[1]):
    ic, _ = spearmanr(X[test_idx, i], alpha[test_idx])
    print(f"feat[{i}]: IC = {ic:.4f}")
```

### IC 기준

| IC | 판정 |
|----|------|
| > 0.01 | 강한 신호 → 반드시 포함 |
| 0.005 ~ 0.01 | 약한 신호 → 다른 feature와 결합 시 포함 |
| < 0.005 | noise → drop |

## 실험 1 Sub-experiments

### 1a: Rolling Window 길이

IC 스크리닝 단계에서 비교 (학습 불필요):

| window | 장점 | 단점 |
|--------|------|------|

→ 3개 window로 beta 계산 → IC 비교 → best window 선택

### 1b: ETF 개수

| 구성 | feature 수 | 근거 |
|------|-----------|------|
| NQ만 | +1 | 가장 단순, 시장 전체 |
| NQ + SOX | +2 | 반도체 sector 분리 |
| NQ + SOX + QQQ | +3 | IT/소프트웨어 분리 |
| 전체 7개 ETF | +7 | 최대 분리 (overfitting 위험) |

→ IC 스크리닝에서 각 ETF별 beta signal IC 비교 → 유의미한 것만 선택

### 1c: Feature 구성

| 구성 | feature | 설명 |
|------|---------|------|
| beta × return만 | beta_nq × nq_ret | signal (종목별 expected impact) |
| + beta 자체 | beta_nq | 종목 특성 (sensitivity level) |
| + correlation | corr_nq_60 | beta 안정성 지표 |

### 1d: Univariate vs Multivariate Beta

```python
# Univariate: 각 ETF 따로
beta_nq  = cov(r_i, nq_ret) / var(nq_ret)
beta_sox = cov(r_i, sox_ret) / var(sox_ret)

# Multivariate: NQ + SOX 동시 regression
r_i = alpha_i + beta_nq * nq_ret + beta_sox * sox_ret + epsilon
```

→ multivariate가 NQ-SOX 상관(~0.7) 제거하여 더 clean한 beta 추정 가능

## 추가 Sub-experiment: 비대칭 Beta

NQ 상승 vs 하락에 대한 종목 반응이 다를 수 있음:

```python
# NQ 상승일만으로 beta 계산
beta_up[i] = rolling_reg(r_i, nq_ret, condition: nq_ret > 0, window=60)

# NQ 하락일만으로 beta 계산
beta_down[i] = rolling_reg(r_i, nq_ret, condition: nq_ret < 0, window=60)

# 비대칭 feature
asymmetry[i] = beta_up[i] - beta_down[i]

# 조건부 signal
signal[i] = beta_up[i] × nq_ret  if nq_ret > 0
          = beta_down[i] × nq_ret  if nq_ret < 0
```

→ IC 스크리닝에서 symmetric beta vs asymmetric beta 비교
