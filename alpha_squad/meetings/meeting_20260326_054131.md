## 기존 방식 (baseline)

```
입력: 1종목 × 153 features (시점 하나)
모델: TabM, AE-MLP 등
출력: 1종목의 미래 가격 변화 예측
```

- 종목을 독립적으로 취급
- 종목 간 관계는 학습하지 않음
- feature engineering에 의존 (rolling log diff, vol rank 등)

## 제약 조건

- **primary target: c2c_120 고정**. 다른 horizon은 auxiliary loss로만 활용
- **평가 지표: CumAlpha** (beta 제거 후 누적 alpha)
  - beta = 각 timestamp에서 valid 종목의 mean(c2c_120)
  - Long alpha = return - beta, Short alpha = return + beta
- **우선순위: L CumAlpha > L+S CumAlpha > L AvgAlpha > L+S AvgAlpha**
- **sample_ratio=0.05 기본** (빠른 실험 반복). 가능성 높은 모델은 sample_ratio=0.1로 재실험
- **미래 데이터 참조 금지**: 학습/추론 시점에 알 수 없는 정보(미래 label, 미래 가격 등)를 feature나 필터에 사용하지 않는다. 새 feature/필터 추가 시 look-ahead bias 여부를 반드시 점검.

# KOSPI 모델 문제 재정의 (2026-03-26)

현재 코스피 200/800 모델이 어느 정도 성숙 단계에 접어든 시점에서, 근본적인 문제 구조를 재검토한다.
목표: 모델 아키텍처 개선이 아닌, **데이터/문제 정의 레벨의 미해결 과제** 파악.

---

## 1. 야간 자산 영향 미반영 (Overnight Context Blind Spot)

**문제**: 코스피는 09:00~15:30 운영되지만, 전날 밤 미국 증시(S&P500, NASDAQ), 금, 은, 유가, 달러 인덱스, 선물 등의 움직임이 당일 개장에 강하게 반영된다. 현재 모델은 이 정보를 **전혀** 보지 않는다.

**현상**: 당일 09:00 개장 직후 갭 상승/하락은 overnight 글로벌 자산 흐름으로 상당 부분 설명 가능하다. 모델은 이 정보 없이 전날의 분봉 패턴만으로 당일 움직임을 예측한다.

**영향 범위**: 개장 직후 시간대(09:00~10:30) 예측 품질에 특히 큰 영향. 이 시간대가 거래 기회가 가장 많은 구간이기도 하다.

**잠재적 해결 방향**:
- 미국 선물(S&P500 E-mini) 야간 수익률을 feature로 추가
- 코스피200 선물 야간 시간외 호가 데이터 활용
- 전날 ADR(American Depositary Receipt) 수익률로 섹터별 overnight 신호 구성

---

## 2. 타임프레임 정보 불균일성 (Temporal Window Inhomogeneity)

**문제**: 현재 feature는 t-200분, t-600분 윈도우 기준으로 계산된다. 그러나 이 "200분"이 담고 있는 **실질적 정보**는 예측 시점에 따라 전혀 다르다.

**구체적 비교**:
| 예측 시점 | t-200분 구간 | 실질 의미 |
|-----------|-------------|---------|
| 09:00 개장 | 전날 15:20~16:00 + 그 이전 | 전날 종가 부근 패턴 |
| 11:00 장중 | 09:00~11:00 당일 | 당일 개장 후 2시간 |
| 15:00 마감 전 | 11:40~15:00 당일 | 당일 오후 흐름 |

같은 `t-200`이지만 개장 시점은 "장이 닫힌 구간"을 포함하고, 장중은 "연속적 당일 흐름"을 본다. 모델 입장에서는 같은 feature 구조이지만 **시장 상태가 완전히 다른** 데이터다.

**현재 대응 수준**: `time_in_day` feature가 있어서 시점 정보는 있다. 그러나 모델이 "이 200분이 장 외 구간을 포함하는가"를 implicitly 학습해야 하는 부담이 있다.

**잠재적 해결 방향**:
- 개장 여부(is_open_window) binary feature 추가
- 윈도우 내 실제 거래 시간(분) vs 전체 경과 시간 분리
- 개장 시점 예측에 전날 종가~당일 시가 갭(overnight_gap)을 명시적 feature로

---

## 3. 예측 타겟 경계 문제 (Target Boundary Contamination)

**문제**: 레이블은 항상 "현재 시점에서 120분 후 c2c 수익률"로 고정된다. 그런데 장 마감(15:30)이 가까워질수록 이 120분 후는 **장이 닫힌 이후**가 된다.

**구체적 문제**:
| 예측 시점 | 120분 후 | 실제 의미 |
|-----------|---------|---------|
| 09:00~13:30 | 당일 장중 | 정상적 예측 |
| 13:30~15:30 | 15:30 이후 | 당일 마감 후 → **익일 09:00~11:00** |

13:30 이후 예측의 타겟은 사실상 "내일 아침 미국 증시 영향을 받은 개장가"를 맞추는 것이다. 이는 순수 intraday 패턴 예측과 **근본적으로 다른 문제**인데 같은 레이블로 혼합 학습된다.

**현상**: 모델이 13:30 이후 시점에 대해 체계적으로 낮은 IC를 보일 가능성 있음. 또한 백테스트 전략이 15:30 강제 청산을 하기 때문에 이 시간대의 예측 신호가 거래로 연결되지 않아 평가가 희석된다.

**잠재적 해결 방향**:
- 13:30 이후 예측 행을 학습에서 제외하거나 별도 레이블(overnight_return)로 분리
- 예측 horizon을 time-of-day 조건부로 동적 설정
- 단순히 09:00~13:00 시간대 행만 학습/평가에 사용

## 4. Overnight Gap 정보 부재 (Gap Feature Missing)

**문제**: 전날 종가 → 당일 시가 사이의 갭(overnight return)은 **당일 가장 강력한 단일 신호** 중 하나다. 미국 증시, 기관/외인 야간 주문, 공시 등의 합산 효과가 응축된 정보다.

현재 feature에는 이 갭이 **명시적으로 없다**. 가격 차이 feature가 있지만 이는 분봉 내에서 계산되며 overnight 갭을 직접 캡처하지 않는다.

**잠재적 해결 방향**:
- `overnight_gap = (시가 - 전날 종가) / 전날 종가` feature 추가
- 갭 크기와 방향, 갭 이후 첫 30분 가격 행동(gap fill 여부) 조합

---

## 5. 종목 간 정보 미활용 (No Cross-Asset Context)

**문제**: 모든 종목을 완전히 독립적으로 처리한다. 실제 시장에서는:
- 삼성전자가 움직이면 SK하이닉스가 따라감 (섹터 선행-후행)
- 코스피 인덱스 방향성이 개별 종목 방향성 결정에 큰 역할
- 외국인/기관의 코스피 전체 매수/매도 흐름이 종목별 영향

현재 모델은 종목 A의 특성이 종목 B의 예측에 도움이 될 수 있다는 것을 활용하지 못한다.

**잠재적 해결 방향**:
- 코스피 200 인덱스 수익률을 공통 context feature로 추가
- 시가총액 상위 10개 종목의 움직임을 sector-level feature로 집계
- Cross-sectional normalization (이미 일부 적용) 강화

---

## 6. 시장 레짐 미반영 (Market Regime Blindness)

**문제**: 같은 패턴이 상승장/하락장/횡보장에서 전혀 다른 의미를 가진다. 예를 들어 단기 pullback은 상승 추세에서 매수 기회지만 하락 추세에서는 하락 지속 신호일 수 있다.

현재 모델은 모든 시장 환경을 동일하게 처리한다.

**잠재적 해결 방향**:
- 20일/60일 MA 대비 현재 코스피 인덱스 위치를 regime indicator로
- 최근 N일 변동성(VIX 유사)을 conditioning feature로
- 학습 시 regime-stratified sampling 또는 별도 regime별 모델

---

## 7. 포지션 타임아웃과 예측 horizon 불일치

**문제**: 백테스트 전략은 진입 후 120분 타임아웃으로 포지션을 강제 청산한다. 예측 타겟도 120분이다. 이상적으로 맞아 보이지만 문제가 있다:

- 15:20 직전 진입한 포지션은 120분 타임아웃 전에 15:40 강제 청산된다
- 즉 실제 보유 시간이 120분이 아닌 20분이 됨
- 이 상황에서 120분 예측 신호로 진입하는 것은 정보-행동 불일치

현재 backtest가 15:20 이후 진입 불가 조건이 있는지 확인 필요. 없다면 이 시간대 신호는 잡음.

## 1. Overnight Gap Feature — 동의하지만 구현이 까다롭습니다

Researcher2 말이 맞습니다. overnight_gap이 없는 건 맹점입니다. 그런데 구현 시 **look-ahead bias 함정이 2곳** 있습니다.

**함정 1: 시가(open) 데이터 참조 시점**

```
overnight_gap = (open[t_day] - close[t_day-1]) / close[t_day-1]
```

이 feature는 당일 09:00 이후에만 알 수 있습니다. **09:00 이전 예측 행에 이 값을 채우면 leakage입니다.** 

현재 feature 구조가 1분봉 기반이므로, 09:00봉 이후부터만 overnight_gap을 유효하게 사용할 수 있고, 09:00 이전 행(pre-market이 있다면)은 NaN 또는 전날 값으로 채워야 합니다. **실제 코스피는 09:00부터 거래이므로 이 문제는 없지만**, enricher 파이프라인이 시가를 어느 시점 기준으로 계산하는지 반드시 확인해야 합니다.

**함정 2: Cross-sectional 오염**

`overnight_gap`을 종목별 raw 값으로 쓰면 안 됩니다. **주가 수준 차이가 섞입니다.** 반드시:

```
overnight_gap_cs_rank = cross_sectional_rank(overnight_gap)  # 동일 시점 전 종목 대비 상대 위치
```

로 변환해야 합니다. 액면가 5천원 종목과 5만원 종목의 raw gap은 서로 다른 의미를 가집니다.

**S&P500 야간 수익률에 대해서는 반대합니다.** 데이터 수집 파이프라인이 없고, 전체 코스피에 같은 값이 들어가면 **종목 구분력이 없는 상수 feature**가 됩니다. 코스피 지수 당일 수익률은 이미 간접적으로 반영되어 있을 것이므로 marginal gain이 낮습니다.

## 2. 시간대 특수성 — 13:30 제외보다 더 강한 제안이 있습니다

Researcher2가 제안한 "13:30 이후 제외"는 **맞는 방향이지만 반만 맞습니다.**

제가 더 걱정하는 건 **09:00~09:30 구간**입니다. 이 구간의 feature들은:

- `vol_per_avg` (윈도우 30/120/360분): 전날 데이터와 당일 데이터가 **뒤섞인 윈도우**를 참조
- `price_increase_per_decrease` (윈도우 360분): 9시 기준 360분 전은 전날 **13:00**

이 시간대의 feature 값은 **regime이 다른 두 장의 혼합**입니다. 모델이 이를 학습하려면 "오늘 9시 이전은 전날 데이터"라는 것을 암묵적으로 파악해야 하는데, 이게 사실상 불가능합니다.

**제안: `is_overnight_contaminated` binary feature 추가**

```python
# 장 시작 후 N분 이전인 경우 True
is_overnight_contaminated = time_in_day < max_window_minutes  # 360분봉 기준이면 09:00~15:00 → 전날 포함
```

이것 하나만 추가해도 모델이 "이 feature들이 장 외 데이터를 포함하는가"를 condition으로 학습할 수 있습니다. sinusoidal time embedding보다 **해석 가능하고 구현이 즉각적**입니다.

## 3. Distribution Shift — ReVol에 조건부 찬성, DoubleAdapt는 반대

ReVol의 return/vol 분리 정규화에는 찬성입니다. 그런데:

**현재 `price_difference_normalized` features (index 68-107)가 이미 정규화를 하고 있습니다.** 윈도우 1_60, 2_120, 5_300, 10_600분 기준으로. 그러면 ReVol이 추가하는 것은 무엇인가?

→ ReVol이 진짜 가치를 발휘하는 건 **cross-day 정규화**입니다. 현재 feature는 intra-day 윈도우 내 정규화이고, ReVol은 최근 N일 기준 변동성으로 scale을 맞추는 것입니다. 이 둘은 다릅니다. **단, ReVol을 적용하면 미래 변동성을 쓰지 않도록** rolling window를 철저히 확인해야 합니다.

**DoubleAdapt는 지금 단계에서 시기상조입니다.** test 기간 첫 2주를 adaptation data로 쓴다는 것은 사실상 **test set을 훔쳐보는 것**과 구분이 어렵습니다. CPCV 등 적절한 walk-forward validation 설계 없이는 IC 수치가 부풀릴 위험이 있습니다.

### 1. c2c_120 바이너리 분류가 근본적으로 틀렸습니다

현재 타겟: `c2c_120 > 0` → class 1, `c2c_120 ≤ 0` → class 0.

### 2. 13:30 이후 문제의 진짜 원인을 오진하고 있습니다

Expert1이 "13:30 이후 제외"를 제안하고 Researcher2도 동의했습니다. 저는 이게 **올바른 처방을 위한 잘못된 진단**이라고 봅니다.

진짜 문제는 시간이 아닙니다. **label의 정보집합(information set)이 예측 시점의 information set과 다르다는 겁니다.**

```
13:30 시점 예측:
  - 모델이 가진 정보: 당일 09:00~13:30 intraday 패턴
  - label c2c_120의 실제 결정 요인: 미국 S&P500 당일 야간 움직임 (한국시간 15:30 이후)
  
→ 모델이 어떤 피처를 봐도 예측 불가능한 정보가 label에 들어있음
→ 이건 노이즈가 아니라 **체계적인 정보 부재 구조**
```

13:30 이후를 잘라내는 것은 **증상 치료**입니다. 근본 치료는 **label horizon이 장중에 완결되는 샘플만 사용하는 것**과 동치입니다. 그런데 여기서 더 깊은 질문이 생깁니다:

**09:00~13:30 샘플만 쓰면 하루 거래 기회의 절반을 버리는데, 이게 최선인가?**

아닙니다. 더 나은 설계는 **시간대별로 다른 타겟**을 쓰는 것입니다:
- 09:00~13:30: `c2c_120` (장중 완결, 현재 타겟 유효)
- 13:30~15:10: `c2c_to_close` (당일 종가까지 수익률 — horizon이 가변적이지만 장 내 완결)

이 두 타겟은 **근본적으로 다른 예측 문제**이므로 같은 모델로 학습하면 서로를 방해합니다.

### 3. Overnight Gap Feature — 문제의 성격 오판

Researcher2가 overnight_gap을 feature로 추가하자고 했습니다. Expert1은 CS rank로 정규화하라고 했습니다. 둘 다 맞는 말인데, **왜 이게 필요한지를 잘못 이해하고 있습니다.**

overnight_gap이 중요한 이유가 "당일 방향성을 예측하는 신호"여서가 아닙니다. overnight_gap이 중요한 이유는 **현재 모델이 overnight_gap을 feature 없이도 학습하려 한다**는 데 있습니다.

현재 feature 중 `price_difference_normalized`의 가장 긴 윈도우는 600분(10시간)입니다. 이 안에 overnight 갭이 포함됩니다. 즉 모델이 이미 overnight_gap을 **가격 차이 feature에 녹아든 노이즈 형태로 보고 있습니다**. 명시적 overnight_gap feature를 추가하면 이 정보를 **격리**해서 "이 변화는 overnight 발생"임을 모델이 알 수 있습니다.

이게 중요한 이유: **overnight_gap은 예측 horizon에 따라 신호 방향이 반전됩니다.** 갭 상승 후 되돌림(gap fill)이 흔한 패턴이라면, 09:30 예측과 11:30 예측에서 overnight_gap의 기여 방향이 반대일 수 있습니다. 명시적 feature 없이는 모델이 이 비선형 구조를 학습하기 매우 어렵습니다.

**하지만 이것도 여전히 패치입니다.** overnight_gap이 있어도 없어도, **label에 overnight return이 포함된 샘플**의 근본 문제는 해결되지 않습니다.
