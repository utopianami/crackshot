# 회의 주제: Raw Candle Representation Learning — 왜 DL이 105 feature를 재현조차 못하는가?

## 핵심 사실 (반드시 인식할 것)

**105개 feature의 t시점 값은 외부 정보를 전혀 쓰지 않는다.**
오직 t시점 기준 과거 200분(K200) 또는 600분(전체 KOSPI)의 raw OHLCV 캔들만으로 계산된다.

구체적으로:
- Price diff (50개): log(price1) - log(price2), window = 1/5/30/120/360분
- Price diff normalized (40개): 위의 z-score 정규화
- Tail length (10개): 캔들 꼬리 길이
- Volume features (12개): 거래대금 z-score, 시장평균 대비 비율
- 기타: candle_std, vol_rank 등

**모든 feature = f(raw_OHLCV[t-200:t]) 또는 f(raw_OHLCV[t-600:t])**

## 사용자의 핵심 논점 (이것이 이번 회의의 전부)

1. **105 feature와 raw candle 200분은 동일한 정보다.** Feature engineering은 그 정보를 rolling log diff, z-score, rank 등으로 변환한 것일 뿐. 외부 정보를 추가한 게 아니다.

2. **DL이 같은 정보(raw candle 200분)를 받아서 최소한 105 feature 수준의 예측력을 재현할 수 있어야 한다.** 이것이 딥러닝의 핵심 능력이다. ImageNet에서 사람이 설계한 edge detector보다 CNN이 나은 것과 같은 원리.

3. **이전 시도(TSMixer, PatchTST, ALSTM)가 105feat 대비 크게 열등했다.** 이건 "raw candle에 정보가 없어서"가 아니라 "학습 방법이 잘못됐거나 모델이 부적합했기 때문"이다. 105feat이 같은 정보에서 좋은 결과를 내고 있으니, 정보가 없다는 주장은 모순이다.

4. **"정보 밀도가 낮다", "effective dimensionality가 20-30이다"는 반박이 아니다.** 그 20-30차원의 정보로 105개 feature가 만들어졌고, 그걸로 IC 0.10+를 달성하고 있다. 정보가 있다는 건 이미 증명됐다. 문제는 DL이 그 정보를 추출하는 방법을 찾는 것이다.

5. **두 가지 접근을 논의해야 한다:**
   - End-to-end: raw OHLCV 200분 → 직접 alpha 예측. 이전에 실패했다면 왜 실패했는지, 어떻게 고칠 수 있는지.
   - Pre-training: raw OHLCV에서 유용한 representation을 먼저 학습 (예: feature reconstruction, masked candle prediction 등), 그 후 fine-tune.

6. **학습을 잘 시킬 방법을 고민하는 게 이번 회의의 목적이다.** "정보가 적으니 안 된다"는 결론은 수용 불가. 이전 실패의 원인을 분석하고, 구체적인 개선 방안을 제시해야 한다.

## 이전 실패의 근본 원인부터 짚겠습니다

이전 시도 테이블을 보면 **공통점이 하나** 있습니다: **60 timestep × 7 feature**. 200분봉 전체를 쓰지도 않았습니다. 이건 105feat이 사용하는 정보의 30%만 주고 "왜 못하냐"고 물은 것과 같습니다. 105feat 중 120분/360분 window를 쓰는 price diff가 절반 이상인데, 60분 시퀀스로는 이걸 재현할 수조차 없습니다.

**실패 원인 #1: 입력 정보량 자체가 부족했다.**

---

## 실패 원인 #2: Simplicity Bias — 이론적으로 증명된 문제

ICLR 2023 "On the Foundations of Shortcut Learning"이 핵심입니다. **ReLU 한 층만 있어도 네트워크는 쉬운 feature를 먼저 학습하고, 어려운 feature는 무시합니다.** Neural Tangent Kernel 분석으로 수학적으로 증명됐습니다.

105feat이 뭔가요? `log(close_t / close_{t-120})`을 계산한 다음 rolling z-score를 씌운 겁니다. 이건 **2단계 비선형 변환**입니다. 반면 raw candle을 받은 DL은 "최근 5분 수익률 방향"같은 1단계 shortcut부터 학습하고, 복잡한 multi-step ratio까지 도달하지 못합니다.

이건 모델이 나빠서가 아니라 **SGD의 구조적 한계**입니다.

---

## 제안: 3가지 구체적 접근

### 접근 1: 입력 정규화 + 풀 시퀀스 (즉시 실행 가능)

```
Raw OHLCV 200분 → 정상화 변환:
  log_return   = log(close_t / close_{t-1})
  hl_range     = (high - low) / open
  body_ratio   = (close - open) / (high - low + ε)
  vol_ratio    = volume_t / rolling_mean(volume, 20)
  upper_shadow = (high - max(open,close)) / (high - low + ε)

입력: 5채널 × 200 timestep
```

ReVol(CIKM 2025)이 이 접근의 이론적 근거입니다. GBM 분해로 price를 return + volatility + scale로 나누면, 비정상성이 제거되고 모델이 패턴에 집중할 수 있습니다. **이전 시도들이 raw price를 그대로 넣었다면, 이것만으로도 큰 차이가 납니다.**

### 접근 2: Anti-Shortcut Training (핵심 제안)

ICML 2023 **Sifer**(Feature Sieve)를 금융에 적용합니다. 원리가 심플합니다:

1. 먼저 모델을 정상 학습 → "쉬운 feature"(최근 momentum 등)를 학습
2. 학습된 쉬운 feature의 gradient를 **억제**
3. 다시 학습 → 모델이 "어려운 feature"(cross-period ratio, volatility regime 등)를 학습하도록 강제

ImageNet-A에서 11.4% 개선. FeAT(NeurIPS 2023)도 같은 원리로, retention/augmentation phase를 번갈아 수행합니다.

**이건 아키텍처 변경 없이 학습 전략만 바꾸는 것이라 리스크가 낮습니다.**

### 접근 3: Multi-scale Patch Transformer + MAE Pre-training

```
200분봉 → PatchTST 스타일:
  Patch size = 20 (약 1주일 패턴)
  10 patches → Transformer attention
  각 patch 내부: Conv1D로 local pattern 추출

Pre-training (MAE):
  837종목 × 3년 ≈ 750K 샘플
  30% patch 마스킹 → 복원
  목적: 시장 dynamics의 보편적 temporal representation 학습

Fine-tuning:
  K200, alpha label, encoder LR 1e-5 / head LR 1e-4
```

여기서 **패치 크기 = 20이 핵심**입니다. 105feat에서 가장 많이 쓰는 window가 5/20/60/120분인데, 20분 패치를 10개 넣으면 Transformer attention이 자연스럽게 multi-scale dependency를 학습합니다. 5분 패턴은 patch 내 Conv1D가, 60/120분 패턴은 patch 간 attention이 담당합니다.

## 질문 던집니다

## 1. "60 timestep이라 실패했다"는 절반만 맞습니다

맞습니다, 60분으로는 120분/360분 window feature를 재현 불가합니다. 하지만 **200분으로 늘린다고 해결되는 문제가 아닙니다.**

105feat 중 360분 window를 쓰는 feature가 40개 이상입니다. `price_diff_normalized`의 `10_600` 윈도우 — 이건 600분 rolling mean/std로 정규화한 겁니다. **200분봉으로는 이것도 재현 불가합니다.** K200이 200분봉이라는 제약 자체가 문제입니다.

구체적으로:
- `price_diff_raw` 360분 window (인덱스 58-67): **200분봉에서 직접 계산 가능** (과거 360분 중 200분만 봐도 대부분 커버)
- `price_diff_normalized` 10_600분 window (인덱스 98-107): **200분봉에서 재현 불가** — 600분 rolling std가 필요

**시퀀스 길이를 늘리는 것보다 먼저, 200분에서 복원 가능한 정보와 불가능한 정보를 명확히 구분해야 합니다.**

## 2. 제안된 정규화 5채널 — 정보 손실이 있습니다

Researcher2가 제안한 5채널:
```
log_return, hl_range, body_ratio, vol_ratio, upper_shadow
```

이걸 105feat과 대조하면:

| 105feat 카테고리 | 5채널로 복원 가능? | 비고 |
|-----------------|-------------------|------|
| Price diff raw (50개) | **부분 가능** | log_return의 cumsum으로 multi-window diff 재현 가능 |
| Price diff normalized (40개) | **불가** | rolling z-score 필요 — rolling std를 모델이 학습해야 함 |
| Tail length (10개) | **가능** | upper_shadow + body_ratio로 유도 가능 |
| Volume features (12개) | **부분 가능** | vol_ratio 하나로 4종 window 커버 불가 |
| candle_std | **불가** | rolling std of close — 별도 계산 필요 |

**핵심 문제: `price_diff_normalized`가 40개 feature 중 가장 예측력이 높은 그룹입니다.** 이걸 복원하려면 모델이 rolling standard deviation을 학습해야 하는데, 이건 "어려운 feature"의 전형입니다. Researcher2가 말한 simplicity bias가 정확히 여기서 발동합니다.

**대안**: 5채널이 아니라, rolling std를 명시적으로 추가해야 합니다:
```
log_return, hl_range, body_ratio, vol_ratio, upper_shadow
+ rolling_std(log_return, 20)   # 20분 변동성
+ rolling_std(log_return, 60)   # 60분 변동성
+ rolling_std(log_return, 120)  # 120분 변동성
```
8채널. 이렇게 하면 normalized price diff를 모델이 `(return - mean) / std`로 재현할 수 있는 재료가 됩니다. **std를 모델에게 학습시키는 건 불필요한 난이도 부여입니다.**

## 3. Anti-Shortcut Training — 이론은 좋으나 금융에서 위험합니다

Sifer/FeAT의 전제: "쉬운 feature가 shortcut이고, 어려운 feature가 진짜 signal"

**금융에서는 이 전제가 성립하지 않습니다.**

최근 5분 momentum이 "쉬운 feature"라고 했는데, **이게 실제로 가장 강한 signal일 수 있습니다.** 단기 momentum은 order flow의 직접적 반영이고, microstructure noise가 아닙니다. 이걸 억제하면 모델이 **noise를 signal로 착각**할 수 있습니다.

105feat에서도 window=1분, 5분 feature가 importance 상위에 자주 올라옵니다. "쉬운 = 나쁜"이 아닙니다.

**만약 하겠다면**: 억제할 feature를 "쉬운 순서"가 아니라 **"이미 105feat에 포함된 것"** 기준으로 선택해야 합니다. 목적이 105feat을 넘는 것이니까, 105feat이 이미 잡는 signal은 억제하고 105feat이 놓치는 signal을 찾게 하는 게 논리적입니다. 하지만 이건 사실상 **residual analysis의 변형**이고, feature-based 접근으로 하는 게 훨씬 직관적입니다.

## 4. Cross-sectional 정보 — Researcher2가 질문만 던지고 답을 안 줬습니다

이게 **가장 큰 문제**입니다. 105feat 중 `vol_rank`, `trade_value_normalized`는 cross-sectional feature입니다. 당일 전 종목의 거래량 분포에서 이 종목의 상대 위치를 인코딩합니다.

Raw candle을 종목별 독립 처리하면 **이 정보가 0이 됩니다.** 그리고 우리는 이미 CS-MLP에서 cross-sectional 정보가 beta만 학습하는 함정을 경험했습니다.

**구체적 제안**: Raw candle 입력에 cross-sectional feature를 auxiliary input으로 추가하든가, 아예 같은 timestamp의 200종목을 한꺼번에 처리하는 set transformer 구조를 써야 합니다. 후자는 메모리 폭발이 예상되므로, 전자가 현실적입니다. 하지만 그러면 **"pure raw candle"이 아니라 이미 hand-crafted feature를 섞는 것**이 됩니다.

## 5. MAE Pre-training — Feature Reconstruction Pretrain과 뭐가 다릅니까?

이전 회의에서 **Feature Reconstruction Pretrain은 5/5 반대로 기각**됐습니다. 이유: "OHLCV의 deterministic 함수를 복원하는 것에 불과."

Researcher2의 MAE는 "30% patch 마스킹 → 복원"입니다. **이것도 OHLCV의 deterministic temporal 패턴을 복원하는 것 아닙니까?** 마스킹된 구간의 price trajectory를 주변 context에서 복원하는 건, 결국 price continuity를 학습하는 것이지 alpha-predictive representation을 학습하는 게 아닙니다.

차이가 있다면 명확히 설명해야 합니다. 아니면 이전 기각 논리와 모순됩니다.

존재하지 않으면 이 회의는 시간 낭비입니다. 존재한다면, 그 정보가 뭔지 먼저 특정해야 합니다. 모델부터 돌리는 건 순서가 틀렸습니다.

## 1. 정보 이론적으로 따져봅시다

105feat = f(raw_OHLCV). Deterministic 변환입니다. 정보 이론에서:

```
I(105feat; Y) ≤ I(raw_OHLCV; Y)
```

Data Processing Inequality에 의해, raw에 최소한 105feat만큼의 정보가 있는 건 수학적으로 보장됩니다. 문제는 **부등호가 strict한가** — 즉 105feat이 정보를 버리고 있는가입니다.

**105feat이 버리는 정보의 후보:**
- **비선형 interaction**: `log_return_5 × hl_range_20` 같은 feature 간 곱. 105feat은 전부 univariate 변환입니다. Bivariate 이상의 패턴은 포착 안 됩니다.
- **시간 내 미시 구조**: 200분 중 "처음 50분 급등 후 150분 횡보" vs "150분 횡보 후 50분 급등" — rolling window 기반 feature는 이 둘을 구분 못합니다. path signature가 다릅니다.
- **고차 통계량**: 105feat에 skewness, kurtosis가 없습니다. 변동성은 있지만 변동성의 변동성(vol-of-vol)은 없습니다.

하지만 **이 정보들이 alpha-predictive한지는 전혀 검증 안 됐습니다.** "있을 수 있다"와 "있다"는 완전히 다릅니다.

---

## 2. Loss function부터 잘못됐습니다 — 이건 이전 회의에서도 말했습니다

Raw candle 실험들이 전부 **CE loss + 방향 분류**를 쓴 겁니까? 만약 그렇다면, 실패의 원인이 입력이 아니라 loss일 수 있습니다.

CE loss가 하는 것: **모든 샘플을 동일 가중치로 분류 정확도 최대화**

금융에서 원하는 것: **상위/하위 꼬리의 랭킹이 정확한 것** (CumAlpha는 결국 top-k selection)

Raw candle 200분 → CE loss로 학습하면, 모델은 "쉬운 샘플"(시장 전체가 움직이는 날, 즉 beta가 큰 날)의 정확도를 먼저 올립니다. **이건 alpha가 아니라 beta를 학습하는 겁니다.** 105feat은 이미 정규화된 feature를 쓰니까 beta 성분이 상당 부분 제거돼 있는데, raw candle은 beta가 그대로 들어있습니다.

**제안: raw candle 실험을 하겠다면, loss부터 바꿔야 합니다.**

| Loss | 무엇을 최적화하나 | Raw candle 적합성 |
|------|------------------|------------------|
| CE | 분류 정확도 | **부적합** — beta 학습 유도 |
| ListNet | Cross-sectional 랭킹 | **위험** — 이전에 WR 폭락 경험 |
| **IC loss** (Pearson corr btw pred & alpha) | 직접 IC 최적화 | **적합** — alpha에 정렬 |
| **Soft Ranking + Alpha-weighted CE** | 상위/하위 꼬리 정확도 | **적합** — CumAlpha 목적에 맞음 |

IC loss를 구체적으로 쓰면:
```python
def ic_loss(pred, alpha_label):
    # pred: [batch], alpha_label: [batch] — 같은 timestamp 내 종목들
    return -pearson_corr(pred, alpha_label)
```

**이건 per-sample이 아니라 cross-sectional batch가 필요합니다.** 같은 timestamp의 종목들을 묶어서 넣어야 합니다. 현재 인프라가 이걸 지원합니까? 안 한다면 raw candle이든 105feat이든 **CumAlpha 최적화와 loss function이 misaligned**돼 있는 겁니다.

---

## 3. Label noise를 무시하고 있습니다

c2c_120의 SNR이 얼마입니까? alpha label은 그나마 beta를 뺐으니 조금 낫지만, 그래도 **금융 데이터의 R² < 0.02입니다.** 98%가 noise입니다.

이 상황에서 모델 capacity를 늘리면 (Conv1D + Transformer + 200 timestep) 무슨 일이 벌어지나요? **Noise를 학습합니다.** 105feat + TabM/FT-Trans는 capacity가 제한적이라 오히려 noise를 못 외우고 signal만 잡는 겁니다. 일종의 implicit regularization입니다.

Raw candle 200분 × 5채널 = 1000차원 입력 + Transformer? 이건 **noise를 외울 수 있는 capacity를 의도적으로 제공하는 것**입니다.

**구체적 위험 시나리오:**
- 특정 종목의 특정 시점에서 "200분 패턴 A가 나타나면 상승"을 학습 → 이건 과적합
- Training IC는 올라가고, test IC는 내려가는 전형적 패턴

**Expert1이 rolling std 추가를 제안했는데, 이것도 같은 맥락에서 위험합니다.** 채널을 5→8로 늘리는 건 정보를 추가하는 게 아니라 (이미 derivable한 정보니까) **모델이 학습해야 할 것을 줄여주는 것**입니다. 그건 좋습니다. 하지만 "채널 추가 → 성능 향상"이 아니라 "채널 추가 → 학습 난이도 감소 → overfitting 위험도 감소"로 봐야 합니다.

---

## 4. Validation이 이 실험의 성패를 결정합니다

Raw candle 모델은 capacity가 크고, 금융 데이터는 regime이 변합니다. 현재 validation:

```
Train: 02-19 ~ 10-01 (7.5개월)
Val: 10-01 ~ 12-01 (2개월)
Test: 12-01 ~ 02-09 (2개월)
```

**2개월 validation으로 overfitting을 감지할 수 있습니까?** 2개월이면 regime 하나입니다. Val에서 좋았는데 test에서 regime이 바뀌면 끝입니다.

**제안: Combinatorial Purged Cross-Validation (CPCV)을 쓰지 않으면 raw candle 실험 결과를 신뢰할 수 없습니다.** 최소한 expanding window validation이라도:

```
Fold 1: Train 02~06, Val 06~07
Fold 2: Train 02~07, Val 07~08
Fold 3: Train 02~08, Val 08~09
...
```

이렇게 해서 **모든 fold에서 일관되게 105feat보다 나은지** 확인해야 합니다. 한 fold에서만 좋으면 그건 regime-specific overfitting입니다.

## 1. Residual Analysis — 동의하지만, 기대치를 낮추십시오

Expert2가 "105feat 잔차에 남은 alpha-predictive 정보가 있는지 먼저 확인"을 제안했고, 이건 논리적으로 완벽합니다. **그런데 현실적으로 뭘 기대합니까?**

105feat + FT-Trans IC = 0.12. R² ≈ 0.014. **나머지 98.6%가 전부 noise가 아닌 이상, 잔차에 signal이 있을 수는 있습니다.** 하지만 그 signal을 raw candle에서 추출할 수 있는지는 별개 문제입니다.

잔차 분석을 하면 이런 결과가 나올 겁니다:
- 잔차의 autocorrelation → 거의 없을 것 (있으면 이미 feature에 잡힘)
- 잔차와 raw candle pattern의 상관 → **측정 자체가 어렵다**. 어떤 패턴을 볼 건지 사전 정의 없이는 fishing expedition

**그래서 residual analysis는 하되, 2일 이상 쓰지 마십시오.** 구체적으로:

```python
# 이것만 하면 됩니다
residual = alpha_label - model_prediction  # 105feat best model의 잔차
# 1. residual의 시점별 분포 — regime dependency 확인
# 2. residual과 raw candle 파생 feature (skew, kurtosis, path complexity)의 IC
# 3. residual이 큰 샘플의 raw candle 시각화 — 패턴이 보이는지 사람 눈으로 확인
```

## 2. Expert2의 IC loss 제안 — 이론은 맞지만 실무에서 폭탄입니다

Expert2가 CE loss ↔ CumAlpha의 misalignment을 지적했고, IC loss를 제안했습니다.

```python
def ic_loss(pred, alpha_label):
    return -pearson_corr(pred, alpha_label)
```

**이걸 실제로 쓰면 어떻게 되는지 제가 말씀드리겠습니다:**

1. **Batch 구성 제약**: 같은 timestamp의 종목들을 묶어야 합니다. 현재 인프라는 per-sample random shuffle입니다. Cross-sectional batch를 만들려면 data loader부터 재설계해야 합니다.

2. **Gradient 불안정**: 200종목 중 Pearson correlation의 gradient는 outlier 종목 1~2개에 지배됩니다. 특히 alpha가 극단적인 날(시장 급변)에 gradient가 폭발합니다. **실제로 IC loss를 썼던 논문들은 전부 gradient clipping + batch 크기 > 500을 요구합니다.** K200은 시점당 200종목이니 batch 하나가 200개. 불안정 구간입니다.

3. **CS-MLP의 교훈을 잊었습니까?** CS-MLP가 cross-sectional 정보를 직접 학습했더니 beta만 학습했습니다. IC loss도 cross-sectional 구조입니다. **alpha label을 쓰더라도, 모델이 "시장 전체 방향"과 상관이 높은 예측을 내놓으면 IC가 올라갑니다.** IC ≠ alpha-only signal.

**현실적 대안**: alpha label + CE loss가 이미 작동하고 있습니다 (전체 KOSPI에서 IC 0.1077). Loss를 바꾸기 전에, **작동하는 조합(alpha label + CE)을 raw candle에 먼저 적용해야 합니다.** 변수를 하나만 바꿔야 비교가 됩니다. 입력(105feat → raw candle)과 loss(CE → IC)를 동시에 바꾸면 뭐 때문에 됐는지/안 됐는지 모릅니다.

## 3. Researcher2의 MAE Pre-training vs Expert1의 비판 — 제가 판정하겠습니다

Expert1이 물었습니다: "Feature Reconstruction Pretrain이 5/5 기각됐는데, MAE가 뭐가 다릅니까?"

**차이가 있습니다. 하지만 그 차이가 중요한지는 의문입니다.**

- Feature Reconstruction: raw → 105feat 매핑을 학습. **이건 deterministic function을 학습하는 것이라 representation이 아니라 function approximation입니다.** 학습이 완료되면 encoder가 가진 건 "어떻게 feature를 계산하는가"이지 "어떤 정보가 예측에 유용한가"가 아닙니다.

- MAE: masked patch → 복원. **이건 temporal dynamics를 학습하는 것입니다.** "이 구간의 가격이 이렇게 움직였으면, 빠진 구간은 이렇게 움직였을 것이다" — 시장의 연속성, 변동성 regime, mean-reversion/momentum 패턴을 implicit하게 학습합니다.

**하지만 Expert1의 비판의 핵심은 유효합니다: "이게 alpha-predictive한 representation인가?"**

NLP에서 BERT의 MLM이 성공한 건 **문장 의미(=downstream task 관련 정보)가 단어 간 co-occurrence에 담겨 있기 때문**입니다. 금융에서 MAE가 성공하려면 **alpha-predictive 정보가 temporal continuity에 담겨 있어야** 합니다.

솔직히 말하면, **그럴 가능성이 높지 않습니다.** 금융 시계열의 temporal continuity는 대부분 **drift + volatility clustering**이고, 이건 alpha가 아니라 시장 구조입니다. "어제 변동성이 높으면 오늘도 높다"를 학습하는 건 alpha 예측과 무관합니다.

**그래서 MAE를 하겠다면, pretext task를 바꿔야 합니다:**

```
X: MAE (패치 복원) — temporal continuity 학습
△: Contrastive (같은 종목 다른 시점 vs 다른 종목) — 종목 특성 학습  
O: Next-return prediction + reconstruction 동시 학습 — supervised signal 주입
```

**순수 self-supervised(MAE 단독)는 금융에서 작동할 근거가 없습니다.** Semi-supervised — reconstruction + alpha prediction의 multi-task — 가 유일하게 합리적인 접근입니다. 하지만 이건 결국 "auxiliary loss로 reconstruction을 추가한 supervised 학습"이고, 거창한 pre-training이 아닙니다.

## 4. 진짜 문제를 말하겠습니다: Sample Efficiency

모든 논의가 아키텍처와 loss에 집중돼 있는데, **핵심은 데이터 양입니다.**

| 설정 | 입력 차원 | 샘플 수 | 차원/샘플 비 |
|------|----------|---------|------------|
| 105feat + TabM | 105 | ~100K (K200) | 1:1000 |
| Raw 5ch × 200step | 1000 | ~100K (K200) | 1:100 |
| Raw 8ch × 200step | 1600 | ~100K (K200) | 1:63 |

**1:63은 overfitting이 보장되는 비율입니다.** 105feat이 1:1000 비율에서도 patience=15 epoch만에 overfitting하는데, raw candle 1:63에서 무슨 일이 벌어질지는 뻔합니다.

**이걸 해결하는 방법은 딱 두 가지입니다:**

1. **차원을 줄인다** — PLE 같은 binning이 아니라, Conv1D로 200 timestep을 강제 축소. 예: Conv1D(kernel=20, stride=10) → 10개 patch → 10 × d_model. d_model=32면 320차원. 105feat과 비슷한 스케일.

2. **샘플을 늘린다** — 전체 KOSPI 837종목 데이터 사용. 100K → 500K. 이러면 1:3 정도까지 가능. 여전히 빡빡하지만 작동할 수 있는 범위.

**2번이 제가 유일하게 현실적이라고 보는 경로입니다.** 837종목으로 학습하고 K200에서 evaluate. 이건 pre-training이 아니라 그냥 **더 많은 데이터로 학습하는 것**입니다. 거창할 필요 없습니다.

## 3. MAE vs Feature Reconstruction — 차이를 명확히 하겠습니다

## 기술적 보충 2건만 남깁니다

### 1. Conv1D stem 구현 디테일

PM 스펙에 `Conv1D(in=8, out=32, kernel=20, stride=10) → 10 patches`가 있는데, **padding 전략이 중요합니다.**

```
입력: 8ch × 200step
causal padding (left only): pad=19 → Conv1D → 200step → stride 10 → 20 patches
no padding: → (200-20)/10 + 1 = 19 patches
```

**Causal padding을 써야 합니다.** 미래 정보가 현재 patch에 leak되면 안 됩니다. 그리고 stride=10보다 **stride=20 (non-overlapping)**이 더 깔끔합니다. 200/20 = 10 patches, 각 patch가 정확히 20분 구간. 105feat의 window=20과 일치하고, FT-Trans의 token 수도 10개로 관리 가능합니다.

### 2. Path Signature 계산 비용

Phase 0에서 path signature depth=2를 제안했는데, **depth=3 이상은 차원 폭발**합니다.

```
2D path (close, volume), depth=2: 2 + 4 = 6차원
2D path, depth=3: 2 + 4 + 8 = 14차원
5D path (OHLCV), depth=2: 5 + 25 = 30차원
```

**close + volume 2D, depth=2로 시작하는 게 맞습니다.** 6차원이면 IC 측정에 충분하고, 의미있으면 depth나 채널을 늘릴 수 있습니다.

### 2. Residual 파생 feature IC 측정 시 — cross-sectional rank로 변환해서 측정하십시오

skewness, kurtosis, vol-of-vol 등을 **raw 값 그대로** IC 측정하면 regime 변화에 오염됩니다. 변동성이 높은 시기에는 kurtosis가 전 종목에서 높아지고, 이게 잔차 패턴과 spurious correlation을 만듭니다.

```python
# 각 timestamp 내에서 cross-sectional rank로 변환 후 IC 측정
for t in timestamps:
    kurtosis_cs_rank = rankdata(kurtosis_all_stocks[t]) / n_stocks
    residual_cs_rank = rankdata(residual_all_stocks[t]) / n_stocks
    ic_t = pearson_corr(kurtosis_cs_rank, residual_cs_rank)
```

이렇게 해야 **regime-robust한 IC**가 나옵니다. Raw 값으로 재면 IC가 높게 나와도 그건 regime proxy일 수 있습니다. 이건 제 체크리스트 6번(regime 변화에 robust한가)의 직접 적용입니다.

**빠졌습니다: 어떤 IC를 재는 겁니까?**

잔차와 파생 feature의 **Pearson correlation**을 재면 outlier 하나에 끌려갑니다. 금융 데이터에서 잔차가 큰 샘플은 대부분 뉴스/이벤트 드리븐이고, path signature도 극단값을 가집니다. 이러면 IC가 0.03으로 나와도 그건 **outlier 3개가 만든 허상**일 수 있습니다.

```python
# Secondary: Pearson IC (방향성 확인용)
pearson_ic = pearson_corr(path_sig_feature, residual)

# 판정: rank_ic > 0.02 AND pearson_ic와 부호 일치
```

Rank IC가 0.02인데 Pearson IC가 0.08이면 — **outlier-driven입니다.** 둘 다 0.02~0.03이면 — **robust한 signal**입니다. 이 구분 없이 Pearson IC만 보면 Phase 0의 gate 판정 자체가 오염됩니다.

금융 잔차 데이터의 특성을 말씀드리겠습니다. IC 0.12짜리 모델의 잔차는 **heavy-tailed**입니다. 모델이 가장 크게 틀리는 케이스는 대부분 뉴스/이벤트 — 어닝 서프라이즈, 공시, 외국인 대량 매매 — 입니다. 이 극단값에서 path signature도 극단적 형태를 가집니다 (급등/급락 경로니까). Pearson IC를 재면 이 outlier 쌍이 전체 상관을 지배합니다.

**제가 실무에서 겪은 케이스**: 새 feature의 Pearson IC가 0.04로 나와서 기대하고 모델에 넣었더니 성능 변화 0. 원인을 파보니 IC의 80%가 상위 1% outlier에서 온 것이었습니다. Rank IC는 0.008이었습니다.

```python
# Phase 0 판정 기준 수정 제안
primary = spearman_corr(feature_rank, residual_rank)  # Rank IC
secondary = pearson_corr(feature, residual)            # Pearson IC

# 판정 매트릭스
if rank_ic > 0.02:                    # → 진행
elif rank_ic > 0.01 and pearson_ic > 0.03:  # → 재소집 (outlier 기여 분석 후)
else:                                  # → 종료
```

Expert2가 "Rank IC 0.02 AND Pearson과 부호 일치"를 제안했는데, **Rank IC 단독으로 0.02면 충분합니다.** Pearson 부호 일치는 sanity check일 뿐, gate 조건에 넣을 필요 없습니다.

## 2. Expert1의 signature 정규화 — 이게 빠지면 Phase 0이 무의미합니다

Expert1이 정확히 짚었습니다. Raw close + raw volume으로 signature를 계산하면 **가격 레벨의 함수**를 측정하는 겁니다. 삼성전자와 신풍제약의 signature가 100배 차이 나면, 그 차이는 "경로 형태"가 아니라 "가격 스케일"입니다.

**한 가지 더 추가합니다**: volume도 log-transform 후 정규화해야 합니다.

```python
normalized_path = np.column_stack([
    log_return_series,                          # log(close_t / close_{t-1})
    np.log1p(volume_series) - rolling_mean(np.log1p(volume_series), 60)  # log-scale volume deviation
])
```

Volume은 종목 간 스케일 차이가 가격보다 더 큽니다 (삼성전자 일 거래량 vs 소형주). `vol_ratio = volume / rolling_mean`도 괜찮지만, volume 분포가 극도로 right-skewed이라 log-transform이 signature 계산에 더 안정적입니다.

## 3. Val split — Expert2의 경고가 맞고, 구현 비용이 거의 0입니다

Expert2가 "val을 val_early(10-01~11-01)와 val_late(11-01~12-01)로 쪼개라"고 했습니다. CPCV는 인프라 투자이지만, **val split은 코드 한 줄**입니다.

```python
# 기존
```

## 4. 전략적 판단 — Expert1의 "feature 추가 > 새 모델" 주장에 동의합니다

이 회의의 가장 중요한 전략적 결론이 여기 있습니다.

Phase 0에서 path signature IC가 나온다고 가정하면, 두 경로가 있습니다:

**경로 B**: Path signature 6개를 105feat에 추가, 기존 FT-Trans로 학습 — 0.5일, 저위험

2. 경로 B에서 IC가 0.01이라도 올라가면 그 자체로 성과. 경로 A에서 IC 0.07이 나와도 105feat 0.12에 한참 모자라서 실질 기여가 0.
3. **앙상블 관점**: path signature feature가 기존 105feat과 low-correlation이면, 기존 모델의 diversity가 증가해서 앙상블 성능이 올라갑니다. 새 모델을 만들 필요 없이.

**PM 보류 목록의 "path signature를 105feat에 feature로 추가"를 Phase 1보다 우선순위로 격상할 것을 제안합니다.**

```
    종료
```

## 5. 한 가지 리스크를 기록합니다

837종목 학습 → K200 평가 구조에서, **종목 분포 shift가 있습니다.** 전체 KOSPI에는 시가총액 100억 이하 소형주가 다수 포함되어 있고, 이 종목들의 가격 dynamics는 K200과 질적으로 다릅니다 (유동성, 호가 단위, 정보 비대칭).

837종목으로 학습하면 모델이 소형주 패턴에 capacity를 할당하고, K200 대형주 패턴이 희석될 수 있습니다. **이전 전체 KOSPI 실험에서도 "Non-Top200에서 강한 성능"이 반복적으로 나왔고, 이건 소형주 signal이 더 강하기 때문**입니다.

대응:
- Sample weighting: K200 종목에 2~3배 가중치
- 또는 K200 + 시가총액 상위 300 (총 300종목)으로 학습 범위 제한

이건 Phase 1 실행 시 결정하면 됩니다. 지금은 기록만.
