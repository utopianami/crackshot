# 회의 배경 및 사용자 요구사항 (반드시 반영할 것)

## 핵심 방향 3가지

### 방향 1: 전체 코스피에서 검증된 방법론 → KOSPI200 적용
- 전체 코스피(837종목, 129 enhanced features)에서 alpha label + FT-Transformer가 검증됨
- Alpha label: IC 0.0759 → 0.1077 (42% 향상), 백테스트 +30.8M
- FT-Transformer large: IC=0.1181 (전체 1위), val_loss 최저
- n_bins=96이 48보다 최적 (전체 KOSPI에서 확인)
- Ultimate v2 앙상블 (3 FT96 + 3 TabM): IC=0.1206, WR=73.2%
- **이것들을 아직 KOSPI200에 적용하지 않았음 → 즉시 실험 가능**

### 방향 2: 우리 문제에 적합한 더 나은 모델 탐색
- 현재 TabM, FT-Transformer, CS-MLP 등 시도함
- 더 나은 아키텍처가 있는지 연구 필요

### 방향 3: Raw Candle Representation Learning (사용자가 강력히 주장)

**사용자의 핵심 논점:**

현재 105개 feature는 전부 raw OHLCV + 거래대금에서 파생된 것이다:
- Price diff: log(price1) - log(price2) × 5 window × 10 pair = 50개
- Price diff normalized: z-score 정규화 = 40개
- Tail length: 캔들 꼬리 = 10개
- Volume: z-score, 시장평균 대비, 상승/하락 비율 = 12개
- Candle std, vol rank 등

**즉, 사람이 수작업으로 rolling log diff, z-score, rank 등의 연산을 적용한 것일 뿐이다.**
같은 OHLCV 원천 데이터를 딥러닝에 통째로 넣으면, 사람이 설계한 105개 feature보다 더 좋은 representation을 학습할 수 있어야 한다. 이것이 딥러닝의 핵심 장점이다.

KOSPI200은 200분봉(≈3.3시간), 전체 코스피는 600분봉(≈10시간) 데이터를 사용한다.
이전에 TSMixer, PatchTST, ALSTM 등으로 시도했으나 실패했는데, 그건 모델이 나빠서가 아니라 접근이 잘못되었을 수 있다.

**제안하는 접근:**
1. End-to-end 학습: raw OHLCV 200분 시퀀스 → 직접 alpha 예측
2. Pre-train task 설계: raw candle → engineered feature 복원 (feature reconstruction)
3. Multi-modal: raw candle encoder + engineered features 결합

사람이 뽑은 feature가 최적일 수 없다. Feature engineering은 도메인 지식의 결정체이지만, 딥러닝은 이를 넘어서야 한다.

## Phase 2: Raw Candle Representation Learning — 재설계 제안

이전 시도 (TSMixer, PatchTST, ALSTM)가 실패한 건 **모델이 나빠서가 아니라 학습 설계가 잘못**되었을 가능성이 높습니다. 구체적으로:

### 왜 실패했나 — 진단

1. **Label이 너무 noisy**: raw OHLCV 200분봉 → 바로 alpha 예측은 signal-to-noise ratio가 극도로 낮음
2. **정규화 부재**: 가격 수준이 종목마다 다른데 raw 값을 넣으면 모델이 가격 수준만 학습
3. **Feature 7개로는 부족**: OHLCV + 거래대금 + 거래량 = 7개. 200 timestep × 7 = 1400 input인데, 여기서 120분 후 수익률을 예측하는 건 underdetermined

### 재설계: Multi-Modal Fusion (가장 유망)

```
Branch A: 105 engineered features → PLE binning → FT-Transformer encoder
Branch B: raw OHLCV 200분봉 → per-stock normalize → Conv1D/Transformer encoder
         └→ fusion layer (cross-attention or concat) → alpha prediction
```

**왜 이게 다른가:**
- Branch A가 이미 strong baseline을 제공하므로, Branch B는 **보충 정보만 학습**하면 됨
- Conv1D가 포착하는 것: 캔들 형태(도지, 망치), 연속 패턴(갭, 추세 가속), 거래량 스파이크 타이밍
- 이런 **기하학적/시퀀셜 패턴**은 rolling log diff 같은 통계량으로는 포착이 어려움

### 대안: Feature Reconstruction Pre-training

```
Phase 1: raw OHLCV 200분봉 → Encoder → 105개 engineered feature 복원 (self-supervised)
Phase 2: Encoder freeze → alpha prediction head 학습 (supervised)
```

이건 **label noise 문제를 우회**합니다. 105개 feature는 deterministic하므로 reconstruction loss는 깨끗합니다. 다만 정보 이론적으로, 복원만 잘하면 105개 feature를 압축한 것에 불과 → **Phase 2에서 encoder를 fine-tune해서 105개로는 포착 못한 잔여 패턴을 학습**해야 의미가 있습니다.

---

## 1. Multi-Modal Fusion — "보충 정보"라는 전제를 의심해야 합니다

Researcher2가 Conv1D Branch B가 "기하학적/시퀀셜 패턴"을 포착한다고 했는데, **구체적으로 뭘 포착하는지 열거해 봅시다.**

| Conv1D가 포착한다는 것 | 105feat에 이미 있는가? |
|------------------------|----------------------|
| 도지/망치 캔들 형태 | `tail_length_up/down` (10개 feature) — 있음 |
| 갭 | `price_diff_open_close` 시리즈 — 있음 |
| 추세 가속 | `price_diff` 5종 윈도우 × 10쌍 — gradient 정보 있음 |
| 거래량 스파이크 타이밍 | `vol_per_avg` 1/5/30/120/360분 — 있음 |
| 연속 캔들 패턴 (3연양봉 등) | **없음** — rolling count 류가 빠져 있음 |
| 분봉 내 변동성 클러스터링 | **없음** — `candle_std`가 일부 커버하나 temporal order 없음 |

**결론: Conv1D가 105feat 대비 추가로 줄 수 있는 정보는 "시간 순서가 중요한 패턴" 2-3가지뿐입니다.** 나머지는 이미 feature로 포착됨. 이 2-3가지를 위해 200 timestep × 7 channel = 1,400 차원 입력을 추가하는 건 **parameter 대비 정보량이 극도로 비효율적**입니다.

## 2. 정규화 문제 — Researcher2가 "per-stock normalize"라고 한 줄로 넘겼는데, 이게 핵심입니다

Raw OHLCV를 넣으려면 정규화 스펙을 정확히 못 박아야 합니다:

| 항목 | 선택지 | 권장 | 이유 |
|------|--------|------|------|
| Price | raw → log-return → rolling z-score | **rolling z-score (60분 윈도우)** | raw/log-return은 regime 의존적 |
| Volume | raw → log → rolling z-score | **rolling z-score** | 종목별 거래량 수준 차이 수백배 |
| Cross-sectional rank | 적용/미적용 | **미적용** (per-sample 학습이므로) | CS rank 쓰면 시장 beta 학습 위험 — 이전 CS-MLP에서 확인된 문제 |

**만약 rolling z-score를 60분 윈도우로 적용하면**, 그 결과물은 `price_diff_normalized` feature와 거의 동일한 정보를 담게 됩니다. 즉, **Conv1D 입력이 105feat의 subset을 재구성하는 꼴**이 됩니다.

## 3. Feature Reconstruction Pretrain — 정보 이론적 함정

Researcher2도 인정했지만 더 명확히 합니다:

```
OHLCV (200 × 7 = 1,400 values) → Encoder → 105 features 복원
```

**105 features는 OHLCV의 deterministic 함수입니다.** 따라서 reconstruction loss를 최소화하는 encoder는 단순히 rolling window 연산을 근사하는 것. 여기서 "105개로는 포착 못한 잔여 패턴"이 남으려면, encoder capacity가 105개 feature 복원에 필요한 것 이상이어야 하고, fine-tune 시 그 잔여 capacity에서 alpha 관련 정보를 뽑아야 합니다.

**문제: 잔여 패턴이 있다는 증거가 없습니다.** 만약 있다면, 그건 feature engineering에 추가하는 게 훨씬 빠릅니다.

## 1. K200에서 Alpha Label의 구조적 함정

전체 KOSPI(837종목)에서 alpha label이 IC +42% 향상을 줬다는 건 인상적입니다. 그런데 **K200에 그대로 적용하면 다른 결과가 나올 수 있는 구조적 이유**가 있습니다:

| 항목 | 전체 KOSPI (837) | KOSPI200 |
|------|-----------------|----------|
| Beta 분산 | 높음 — 소형주, 테마주 포함 | **낮음** — 대형주 위주, 시장과 상관 높음 |
| Alpha 분산 | 높음 — idiosyncratic return 큼 | **낮음** — 기관/외국인 flow로 수렴 |
| Beta 추정 오차 | 중간 — 종목 수가 많아 평균이 안정적 | **높음** — 200종목 mean이 시장 beta와 거의 동치 |

**핵심 문제: K200에서 alpha = return - mean(return)을 빼면, 빼는 beta 자체가 noisy합니다.** 837종목 평균은 개별 종목 노이즈가 상쇄되지만, 200종목 평균은 삼성전자·SK하이닉스 같은 mega-cap의 움직임에 지배됩니다. 즉 **alpha label이 mega-cap 대비 상대 수익률**로 변질됩니다.

**검증 방법**: alpha label의 cross-sectional 분포를 전체 KOSPI vs K200에서 비교해야 합니다. K200 alpha의 kurtosis가 전체보다 낮고 mean 근처에 몰려 있다면, **label의 signal-to-noise ratio가 더 나빠진 것**입니다. 이걸 확인 안 하고 "전체에서 됐으니 K200에서도 되겠지"는 **look-ahead bias는 아니지만, selection bias입니다.**

## 2. Loss Function 재검토 — CE-only가 정말 안전한가?

실험 계획에 "CE-only가 ListNet보다 안정적"이라고 써있는데, **이건 전체 KOSPI에서의 결론이지 K200에서의 결론이 아닙니다.**

K200의 구조적 차이를 생각하면:

- **K200은 종목 간 상관이 높음** → cross-sectional ranking이 더 불안정 → ListNet이 불리할 수 있음 (동의)
- **그러나 CE-only는 방향 분류만 학습** → top/bottom 극단값의 순서를 무시 → **alpha가 클 종목과 작은 종목을 구별 못함**

K200에서는 종목 간 alpha 차이가 작으므로, **"방향만 맞추면 된다"가 아니라 "얼마나 맞추느냐"가 중요**합니다. 이건 **regression formulation이나 IC-aware loss가 CE보다 나을 수 있는 상황**입니다.

구체적 제안:
```
Loss = CE(direction) + λ * IC_loss(predicted_score, alpha)
```
여기서 IC_loss = -Spearman_correlation(score, alpha). 이건 ListNet과 다릅니다. ListNet은 softmax 기반 분포 matching이라 temperature에 민감하지만, **IC loss는 순위 상관 자체를 직접 최적화**합니다. Differentiable Spearman이나 SoftSort를 쓰면 됩니다.

## 4. Regime 변화 — 아무도 언급 안 하는 코끼리

- 2025년 10월: 미국 금리 인하 기대 → 성장주 강세
- 2025년 12월~2026년 2월: 금리 인하 지연 + 트럼프 관세 → **regime 전환**

**Test 기간이 train과 다른 regime입니다.** 이 상황에서:
- FT-Transformer의 attention이 train regime의 feature 중요도를 학습했다면, test에서 **feature 중요도가 뒤집힘**
- GFS가 train에서 불필요하다고 gating한 feature가 test regime에서는 중요할 수 있음

**Alpha label이 이 문제를 완화하긴 합니다** (beta를 빼므로 시장 방향 의존성 감소). 하지만 factor rotation — momentum↔value, large↔small 전환 — 은 alpha label로도 해결 안 됩니다.

**제안: 최소한 rolling validation window로 regime robustness를 체크해야 합니다.** Val을 09-01~10-01, 10-01~11-01, 11-01~12-01로 3번 나눠서 IC 편차를 보세요. 편차가 크면 **어떤 모델을 쓰든 test에서 깨질 수 있습니다.**

## 4. IC-aware Loss — 흥미롭지만 실무적 난관이 있습니다

Expert2의 Differentiable Spearman 제안은 이론적으로 타당합니다. K200에서 alpha 분산이 작으니 순위 정확도가 중요하다는 논리도 맞습니다.

**그런데 실무적으로:**

| 문제 | 설명 |
|------|------|
| **Per-sample 학습** | 우리는 종목별 독립 학습입니다. Spearman IC는 cross-sectional metric인데, per-sample prediction에서 어떻게 IC loss를 계산합니까? 같은 timestamp의 200종목을 한 batch에 넣어야 하는데, 현재 DataLoader가 timestamp 단위가 아니라 (stock, time) 단위입니다. |
| **Batch 내 ranking** | Batch를 timestamp 단위로 재구성하면 가능하지만, batch_size=4096일 때 한 timestamp에 200종목이니 ~20개 timestamp. 200개 샘플 내 ranking의 gradient는 noisy합니다. |
| **ListNet과의 차이** | ListNet도 결국 cross-sectional ranking loss였고, "WR 폭락 리스크"가 있었습니다. IC loss가 이 문제를 피한다는 보장이 없습니다. |

**결론: 아이디어는 좋지만, DataLoader 구조 변경이 필요하고 리스크가 있습니다. Phase 1 이후 IC 결과를 보고 판단합시다.** CE-only로 IC > 0.10이 나오면 굳이 loss를 건드릴 필요 없습니다.

## 5. Regime 문제 — 동의하지만 우리가 할 수 있는 게 제한적입니다

Expert2가 "rolling validation으로 regime robustness 체크"를 제안했는데, **체크해서 불안정하다는 결과가 나오면 뭘 합니까?**

- Rolling train? → 데이터가 8개월밖에 없어서 rolling window가 너무 짧음
- Regime-aware model? → Regime label 자체가 look-ahead bias
- Ensemble across regimes? → 각 regime에 맞는 모델을 따로 학습할 데이터 부족

**현실적으로 우리가 할 수 있는 건:**
1. Alpha label (이미 계획에 포함 — beta 제거로 시장 방향 의존성 감소)
2. 강한 regularization (attention_dropout, weight_decay 올리기)
3. 앙상블 (다양한 seed/architecture)

이것들은 이미 Phase 1 실험 계획에 들어있습니다. **Rolling val은 "진단"이지 "처방"이 아닙니다.** 진단만 하고 처방이 없으면 시간 낭비입니다.
