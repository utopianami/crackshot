### Tier 1 — 즉시 수집, 효과 확실

| 자산 | 심볼 | 이유 |
|------|------|------|
| S&P500 선물 | `ES=F` | KOSPI200과 overnight co-movement 가장 강함 |

| USD/KRW | `USDKRW=X` | 외국인 수급 직결. 환율 weak → 수출주 복잡 |
| VIX | `^VIX` | risk-on/off 신호. VIX 급등 = 전 종목 하락 압력 |

수집 방법: **yfinance 일봉** (무료, 즉시, look-ahead bias 없음)

```python
import yfinance as yf

SYMBOLS = {
    'sp500': 'ES=F',
    'nasdaq': 'NQ=F',
    'usdkrw': 'USDKRW=X',
    'vix': '^VIX',
}

def get_overnight_features(trade_date_kst: str) -> dict:
    """
    trade_date_kst: '2025-10-15'
    반환: 해당일 09:00 개장 전에 알 수 있는 전날 미국 종가 기반 feature
    """
    result = {}
    for name, sym in SYMBOLS.items():
        hist = yf.Ticker(sym).history(period='10d', interval='1d')
        # 전전일 → 전일 변화율 (미국 16:00 ET = KST 06:00 다음날)
        # trade_date_kst 기준 "전일 미국 종가"는 이미 확정
        prev2 = hist['Close'].iloc[-2]
        prev1 = hist['Close'].iloc[-1]
        result[f'{name}_ret'] = prev1 / prev2 - 1
        result[f'{name}_level'] = prev1
    return result
```

**Look-ahead bias 점검**: 일봉 기준이므로 KST 09:00 시점에 이미 확정된 값. 안전.

## Feature 설계: 3가지 수준

### Level 1 — 기본 (필수)

```python
# 각 거래일 × 전체 종목에 동일하게 broadcast
features = {
    'sp500_overnight_ret':   float,  # S&P500 overnight return
    'nasdaq_overnight_ret':  float,  # NASDAQ overnight return  
    'usdkrw_overnight_ret':  float,  # 원달러 변화율 (양수 = 원화 약세)
    'vix_overnight_change':  float,  # VIX 변화율
    'vix_level':             float,  # VIX 절대값 (공포 지수)
}
```

### Level 2 — 파생 (권장)

```python
# 방향과 크기 분리 (논문에서 효과적임이 확인됨)
'sp500_sign':      np.sign(sp500_ret)          # 방향
'sp500_magnitude': np.abs(sp500_ret)           # 변동 크기
'us_risk_on':      int(sp500_ret > 0 and vix_change < 0)  # 복합 시그널

# Rolling z-score 정규화 (60일 window)
'sp500_ret_z60':   (ret - rolling_mean) / rolling_std
```

### Level 3 — 아키텍처 연동 (고급, MASTER 방식)

MASTER 논문(arXiv 2312.15235)의 핵심 아이디어:
> 시장 정보(Market Status)로 **gating**을 적용해 종목별 feature를 스케일링

```python
# cs_master.py 구조 참조
# market_context → attention gate → feature scaling
market_gate = sigmoid(W_gate @ market_features)  # (4,) → scalar gate
scaled_stock_feat = stock_feat * market_gate      # broadcast across stocks
```

이 방식이 단순 concatenation보다 효과적인 이유: overnight 정보의 영향이 **종목마다 다르게** 작용하기 때문. 원화 약세는 수출주에 긍정적이지만 내수주엔 부정적 → gate가 이걸 학습 가능.

## 1. Look-ahead bias — yfinance 일봉의 타임존 함정 (치명적)

Researcher2 코드의 이 부분:

```python
hist = yf.Ticker(sym).history(period='10d', interval='1d')
prev2 = hist['Close'].iloc[-2]
prev1 = hist['Close'].iloc[-1]
```

**문제**: yfinance 일봉의 `index`는 **ET 기준 날짜**입니다. `2025-10-14 (ET)` Close = KST 2025-10-15 06:00 종가. 백테스트에서 날짜 매핑을 KST 기준으로 하면 **하루가 엇나갑니다**.

구체적 예: 10월 14일(화) KST 09:00 개장 모델에 넣을 feature는 10월 13일(월) ET 16:00 종가 → yfinance index `2025-10-13 (ET)`. 근데 코드에서 `iloc[-1]`이 10월 14일 ET 데이터를 가져오면 → **미래 데이터 사용**.

**필수 수정**:
```python
# trade_date_kst를 ET로 변환하여 "전전일 ET" 종가를 사용
from datetime import datetime, timedelta
import pytz

kst = pytz.timezone('Asia/Seoul')
et = pytz.timezone('US/Eastern')

def kst_to_prev_et_date(trade_date_kst: str) -> str:
    """KST 09:00 개장 기준 전날 미국 종가의 ET 날짜"""
    kst_dt = kst.localize(datetime.strptime(trade_date_kst, '%Y-%m-%d'))
    # KST 09:00 = ET 전날 19:00 (서머타임 없을 때) 또는 20:00
    # 미국 종가 ET 16:00은 KST 06:00이므로, 전날 ET 날짜 사용
    et_dt = kst_dt.astimezone(et)
    prev_et = et_dt.date() - timedelta(days=1)
    return str(prev_et)
```

**이걸 틀리면 백테스트가 완전히 무의미합니다.**

## 2. Representation — raw return은 regime에 취약 (중요)

Researcher2가 제안한 `sp500_overnight_ret`을 raw float로 쓰면:

- 2025년 평균 일간 변동 ±0.8%
- 2022년 평균 일간 변동 ±2.1%
- 모델이 "S&P500 -1% = 중간 하락"으로 학습 → 2022식 변동이 오면 "극단 하락"으로 해석 오류

**반드시 rolling z-score 정규화 필요** (60일 window는 Researcher2 Level 2 제안과 동일, 동의):

```python
# 백테스트 구간에서 look-ahead bias 없이:
# 각 trade_date 기준 과거 60일 mean/std로 정규화
sp500_ret_z = (sp500_ret - rolling60_mean) / (rolling60_std + 1e-8)
```

단, **VIX level은 z-score 불필요**. VIX 20 이하/30 이상은 절대값 자체가 의미 있는 regime 지표. raw level을 쓰되 clip(0, 80) 정도만 적용.

## 핵심 비판: Market-level feature는 cross-sectional alpha가 아니라 beta를 설명합니다

우리 목적함수가 뭔지 다시 보겠습니다:

```

beta = timestamp별 valid 종목 mean(c2c_120)
```

즉, **우리가 예측해야 하는 건 "왜 이 종목이 시장 평균보다 더 올라가는가?"** 입니다.

```

```

**이건 alpha 예측 모델에 beta 학습 signal을 주입하는 겁니다.**

## 09:00~10:30 IC 65.8%의 진짜 원인 — 반증 확인 필요

**이 분석을 누가 했습니까?** 안 했죠. VIX 급등일 vs 평온일에 IC가 어떻게 다른지 먼저 확인해야 합니다.

## Expert2의 "beta vs alpha" 비판 — 핵심은 맞지만 결론이 틀렸습니다

Expert2가 제기한 구조적 문제를 정확히 짚겠습니다:

실제 모델이 보는 것:

```

"sp500 +2% AND 이 종목의 vol_rank > 0.8 → 오히려 회피"
```

이건 cross-sectional alpha입니다. broadcast feature 자체가 beta를 만드는 게 아니라, **stock-specific feature와의 interaction이 없을 때** beta가 됩니다. 그리고 우리 loss는 cross-sectional ranking이므로 "모든 종목 같이 매수" 패턴에 이득이 없습니다.

## 추가 경고 1: rolling z-score의 look-ahead bias 함정

`sp500_overnight_ret_z60`에서 **60일 rolling mean/std를 계산할 때** 학습/검증/테스트 분리가 제대로 됐는지 반드시 확인:

```python
# 잘못된 방식 (전체 기간 mean/std → look-ahead bias)
z = (ret - ret.mean()) / ret.std()

# 올바른 방식 (expanding or rolling, 현재 시점까지만)
z = (ret - ret.rolling(60, min_periods=30).mean()) / \
    (ret.rolling(60, min_periods=30).std() + 1e-8)
```

`scripts/fetch_overnight_features.py`에서 이 부분이 틀리면 타임존 버그만큼 치명적입니다. **단위 테스트 케이스에 반드시 포함**.

## 이 실험이 실제로 테스트하는 것

overnight feature 추가가 IC를 높인다면, 그건 두 가지 중 하나입니다:

```
(α) overnight 정보가 진짜 종목별 alpha를 예측한다
    → 문제 정의가 맞았고 feature가 부족했던 것

(β) overnight 정보가 beta를 더 잘 제거하는 데 도움됐다
    → alpha label의 beta 추정이 조악했고, 더 정교한 beta 제거가 필요했던 것
```

Researcher1의 "자동 억제" 논리는 **(β) 경로도 차단한다**고 했지만, 저는 확신하지 못합니다.

`beta = timestamp별 200종목 mean(c2c_120)` — 이게 진짜 beta면 overnight +2%인 날 200종목이 평균 +2% 움직여야 합니다. 근데 **외국인 비중, 섹터, 유동성에 따라 beta 반응 속도가 다릅니다.** 삼성전자는 9시 1분에 이미 반영, 중소 K200 종목은 9시 20분에 반영. 단순 평균 beta는 이 차이를 못 잡습니다.

**만약 실험이 성공한다면 — 이 (α) vs (β) 경로를 사후 분석으로 구분하십시오.**

방법: VIX 급등일에 overnight feature가 기여한 종목 분포를 보면 됩니다. 삼성전자·SK하이닉스 같은 high-beta 종목에만 IC 개선이 집중된다면 **(β) 경로**, 섹터 무관하게 고르게 개선된다면 **(α) 경로**.

이게 Phase 2 설계 방향을 결정합니다.
