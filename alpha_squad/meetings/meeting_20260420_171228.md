# Researcher2 발언 — Phase 1 리뷰 + 아키텍처 재설계 제안

## 1. 핵심 진단: Gumbel top-k는 교체해야 함

현재 설계(features → backbone → score → **Gumbel top-k** → portfolio loss)에서 **Gumbel이 가장 약한 고리**입니다. 리서치 근거:

- **SOFT (Xie et al., NeurIPS 2020, arXiv:2002.06504)** — top-k를 entropic OT로 재공식화. Gumbel 대비 gradient 안정성 우위 명시적 증명, temperature가 sparsity를 직접 제어.
- **SoftSort (Prillo & Eisenschlos, ICML 2020)** — row-wise softmax over pairwise diff. 3줄 구현, NeuralSort/Gumbel 대비 numerical stability 우수.

**권장 위계: SoftSort/SOFT > Gumbel top-k > Straight-through top-k.**

Gumbel의 문제:
- τ 낮으면 gradient vanish, 높으면 weight 분산 비현실적 → scheduling 지옥
- 크립토 4h 리밸런싱에서 정확히 10 long / 10 short를 강제하면서 gradient 품질 확보하려면 OT 기반이 적합

## 2. 이론적 정당성: 이번 head swap은 탄탄함

- **Donti, Amos & Kolter (NeurIPS 2017, arXiv:1703.04529)** — **model misspecification 상황에서 end-to-end task loss가 predict-then-optimize를 dominate한다는 증명**. 5-class CE on fwd_4h는 long-short portfolio 목적 대비 misspecification의 극치 → 정확히 이 정리가 적용되는 세팅.
- **Deep Momentum Networks (Lim-Zohren-Roberts, JFDS 2019)** — 88 futures에서 differentiable Sharpe + **turnover penalty를 로스에 직접 삽입**해 2~3bp fee 환경에서 momentum alpha 보존 검증. 현재 제안 템플릿과 동일.

→ Reward shaping이 아니라 **loss 내부 λ_turn·|Δw|₁·fee** 공식이 canonical. 제안대로 가세요.

## 3. 롱-죽고 숏-사는 비대칭: 구조적 bias가 맞음

**Liu-Tsyvinski-Wu (JF 2022, Common Risk Factors in Cryptocurrency)** — CSMB/CMOM 프리미엄이 **숏 레그에서 지배적**으로 발생. 고 funding rate가 음 수익을 예측하는 강도 > 저 funding이 양 수익 예측 강도. RAPS 2022, JFM 2022도 동일 증거.

즉 현재 숏-만-살아있는 현상의 **상당 부분은 Feb-Mar 2026 artifact가 아니라 크립토 퍼프 구조적 비대칭**입니다. 실험 제안:

1. **수익 분해**: `w·r = w·price + w·funding`. 숏 수익 중 funding 비중 측정
2. **Rolling 30d long/short SR**: 상승 구간 포함시켜 regime 효과 분리
3. **Funding 제거 후 재평가**: `r_adjusted = price_only`로 숏 SR이 얼마나 감소하는지

## 1. **Funding-asymmetric target은 leakage는 아니다. 하지만 더 큰 문제가 있다.**

R2가 "short leg target = price_return + funding_paid"로 제안했는데, **leakage는 아니지만 IC double-counting**입니다.

현재 피처 세트에 **funding rate 자체가 input**으로 들어가 있습니다 (Phase 0 9피처 중 1개). 그걸 **target에도 명시적으로 가산**하면:

- 모델이 "funding 높다 → 숏 score 높다"를 **tautology**로 학습
- Cross-sectional 예측력이 아니라 **funding 자체를 reproduce**하는 degenerate solution 수렴 위험
- Liu-Tsyvinski-Wu (2022)가 말하는 funding premium은 이미 **feature 단에서** 잡혀야 함. target 레벨에서 비대칭 적용하면 모델은 "funding을 예측"할 뿐 알파 생성 안 함.

**대안**: target은 순수 `price_return`으로 통일하되, **loss에서 leg별 transaction fee 현실 반영**:
```
loss = -E[w_long · r_long] - E[w_short · (r_short - funding_short)] + λ_turn · |Δw|
```
즉 **실현 수익 계산**에서 funding을 차감할 뿐, target 자체는 오염시키지 않는다.

---

## 2. **Premium (perp - spot) 피처 — survivorship bias 경고**

R2가 "크립토 고유 1위 알파"로 지정했는데, 피처 품질 관점에서 세 가지 체크 필수:

### (a) Spot listing coverage
Binance 퍼프 314개 중 **spot이 동시 listed인 심볼은 80% 이하**로 추정됩니다. Perp-only 알트(레버리지 토큰, 메타 코인)는 premium 계산 시:
- NaN 처리 방식에 따라 결과 완전히 달라짐 (0으로 채움 = 가짜 signal / 유니버스 제외 = 표본 축소)
- 298개 통과 유니버스에서 **얼마가 premium 계산 가능한지 먼저 count** 해야 합니다.

### (b) Spot/Perp 시간 정렬
Binance spot과 perp은 **matching engine이 분리**되어 있어 5분 bar 경계에서 tick 비대칭이 발생. `premium_t = perp_close_t - spot_close_t`는 수십 bps 노이즈 포함 → **5-bar rolling median** 등으로 smoothing 필수.

### (c) Cross-sectional normalization
Raw premium (bps 단위)은 심볼별 volatility에 비례. **z-score 정규화 또는 cross-sectional rank** 없으면 고변동성 알트가 premium 피처를 dominate → TabM/FT-T의 attention이 소수 심볼에 몰림.

---

## 3. **OI change rate — raw 사용 절대 금지**

R2가 "OI change rate"를 2순위로 올렸는데, **normalization 명세 없이 raw로 넣으면 무용지물**:

- OI는 **market cap proportional**. BTC OI ~$10B vs 알트 OI ~$10M. Cross-section 비교 불가.
- 변화율(`ΔOI/OI`)도 **심볼별 base level 차이**로 분포가 왜곡됨.

**필수 변환**:
1. `z_score(ΔOI/OI, window=24h, per_symbol)` — 자기 대비 정규화
2. **추가로 cross-sectional rank** — 횡단면 상대 위치

두 가지를 **동시에** 넣어야 regime 변화(전체 시장 OI 급증 시기) robust. 하나만 넣으면 regime마다 feature importance가 뒤집힘.

---

## 4. **Funding term structure — 1h trailing의 함정**

Binance funding은 **8h 주기**로 realize됩니다. "1h trailing funding" 피처를 만들 때:

- 1h 윈도우 안에 funding settlement가 **들어있는지 vs 아닌지**에 따라 값이 계단식으로 튐
- 학습 시 **random하게** 섞이다가 reference에서 특정 시각(UTC 00/08/16)에 bias 발생

**권장**: funding term structure는 **predicted funding rate** (Binance API `premiumIndex` 기반 실시간 추정치)로 만들고, realized funding은 별도 피처로 분리. 두 개의 의미가 완전히 다릅니다.

---

## 5. **SoftSort soft→hard 전환 — 피처 관점 부작용**

R2 질문 (a)에 대한 내 우려:

SoftSort가 soft 단계에서는 **z-score가 애매한 심볼**(middle rank)에도 weight를 흘립니다. 이 중간 구간에 **노이즈 피처**(예: 1h return같은 단기 shock)가 dominate하면, 학습 초기에 모델이 **노이즈에 의한 ranking**을 학습한 후 hard 전환 시점에 붕괴 가능.

**처방**: soft 단계 전에 **feature-level 필터** 먼저 통과시킬 것:
- |IC| > 0.02 (이미 Phase 0 통과)
- **|ICIR| > 0.5** (R2가 0.3이라 했지만 soft→hard 전환의 gradient 안정성 위해 더 엄격)
- **Cross-sectional dispersion** > 일정 threshold (전 심볼 동일값 가까운 피처 제거)

# Expert2 (Problem Formulation 비판) — 발언

---

## 판정 먼저: Expert1이 funding 논쟁에서 옳다. 하지만 **둘 다 더 큰 병을 놓쳤다.**

R2의 "funding-asymmetric target"은 Expert1 진단대로 **degenerate tautology**입니다. Funding이 input이자 output이 되면 모델은 알파를 찾지 않고 funding 자체를 재현합니다. Target은 순수 price_return, **realized PnL 계산에서만 leg별 비용 반영** — 이게 canonical입니다.

그런데 이 논쟁은 **표면**입니다. 진짜 문제를 짚겠습니다.

---

## 1. **Target이 여전히 틀렸다. R2는 과거 실수를 복제하고 있다.**

KOSPI 프로젝트에서 `class_bins`가 **절대 수익률 경계**라서 실험 전체가 망가진 전례가 있습니다 (2026-04-02 meeting). 그걸 발견하고 cross-sectional percentile로 전환한 게 이 프로젝트의 가장 큰 lesson이었습니다.

그런데 지금 R2 설계를 보면:

```
target: fwd_4h raw price_return  ← 절대값
loss  : -E[w · r] where w = top-k(cross-sectional z-score)  ← 크로스섹션
```

**Target은 절대값, weighting은 크로스섹션**. 이 비대칭이 정확히 KOSPI 때 burn된 구조입니다.

loss가 `w·r`이라서 "자동으로 크로스섹션 아니냐"고 반론하실 수 있는데 — 틀립니다. `w`가 cross-sectional z를 거친다 해도 `r` 자체가 market factor에 노출된 절대값이면, **bear regime에서 모든 r이 음수**일 때 모델은 "long weight 줄이기 = 손실 감소"라는 **시장 방향 예측**으로 수렴합니다. 이게 지금 데이터입니다:

- Long 전 모델 음수 LO SR -1.25~-2.00
- 단순한 "bear 중 long 하면 망함" 학습 결과

**처방**: target을 cross-sectional residual로.
```
r_i' = r_i - mean(r_universe)         # 가장 단순
또는 r_i' = r_i - β_i · r_BTC          # beta-neutral
또는 rank_percentile(r_i)              # 순수 ranking
```
loss는 `-E[w · r']`. 이래야 weight와 target의 **수학적 대칭**이 맞습니다.

이 수정 없이 SoftSort/turnover penalty 튜닝 들어가면 **KOSPI와 똑같은 벽**에 부딪힐 것입니다.

---

## 2. **Test 60일 = 베어 regime only. 모든 결론이 artifact일 수 있다.**

2026-01-30~03-31 test period. Binance BTC는 이 구간 **-35% drawdown**. Val도 60일. 즉:

- **평가 전체가 단일 bear regime**
- "숏만 살아있다"는 관찰은 **test 진단이 아니라 regime 재진술**
- Liu-Tsyvinski-Wu의 "short-leg dominance"도 **bear regime 편향 샘플**에서 강화됨 (저자 샘플 2013-2019도 2014, 2018 bear 포함)

R2의 CPCV는 **필요하지만 불충분**합니다. CPCV는 train 내부 purging일 뿐, **test가 bull regime을 안 봤다**는 사실은 해결 못 합니다.

**최소 요구**:
1. **Regime-stratified reporting**: train+val+test를 rolling 60d window로 쪼개 각 구간 LS SR 별도 산출. "전 구간 중 몇 %에서 SR > 0"을 metric으로.
2. **Bull-period walk-forward**: 2023 하반기~2024 상반기 bull 구간을 **별도 test**로 hold out. 성능 comparable하지 않으면 **배포 보류**.
3. **PBO (Probability of Backtest Overfitting)** 계산 — ICAIF 2022 페이퍼 그대로.

이거 안 하면 "Phase 1 baseline LS@2bp -0.3~-1.3"이 **모델 문제인지 regime 문제인지 구분 불가**합니다.

---

## 3. **단일 horizon fwd_4h = 리밸런싱 주기와 같음. Execution-aware하지 않다.**

현재 target이 fwd_4h, 리밸런싱도 4h. 이론적으로 aligned처럼 보이지만:

- **Signal generation 시점 t**에서 decision → 실제 fill은 t+epsilon (수 분)
- **Close t+4h** 기준 수익인데, 포지션 청산도 t+4h+epsilon
- Fill slippage, partial fill, funding settlement 시각 (8h 주기)과 rebalance 위상차 → **학습 target과 realized PnL 사이 measurement bias**

**멀티태스크로 해결**:
```
auxiliary heads:
  - fwd_1h (1 후 return, intraday drift)
  - fwd_4h (main)
  - fwd_24h (holding period slack 반영)
  - rank fwd_4h (cross-sectional rank as aux classification)
```

638피처 데이터에 `c2c_1/5/10/30/60/120/240` 이미 있습니다. **공짜로 멀티태스크 가능**. Auxiliary loss는 regularization 역할도 하고, 4h single target의 noise floor를 낮춥니다.

---

## 4. **5-class CE head를 완전히 버리면 representation이 무너진다.**

R2의 end-to-end portfolio loss 전환에 **조건부 동의**했지만, 한 가지 경고:

Donti-Amos-Kolter (2017)가 증명한 "task loss dominates"는 **충분한 gradient signal이 있을 때**입니다. Top-k 연산을 거치면 **20개 symbol에만 gradient**가 흐릅니다. 298 symbol × 4h bar × 2년 = ~216만 샘플 중 **대부분이 gradient 0**. Representation 품질이 5-class CE baseline보다 **나빠질 수 있습니다**.

**처방**: 5-class CE를 auxiliary head로 유지.
```
loss_total = loss_portfolio + α · loss_CE(5class)
```
단, class_bins는 **percentile-based cross-sectional**로 (KOSPI 교훈). α warmup: 초기 1.0 → 후기 0.1.

이게 representation 안정성과 task alignment **둘 다** 가져갑니다.

---

## 5. **Look-ahead 한 가지 더 — Expert1 premium 논의 확장**

Expert1이 spot/perp timing을 언급했는데, 실전 reference 관점에서 더 심각한 문제:

- **5-bar rolling median 적용 시 — median 윈도우가 **현재 bar 포함** vs **미포함**? 포함이면 causal 경계 혼동.
- Premium 변화율 (`Δpremium`)을 피처로 쓰면, t-1 vs t spot 가격에 **perpetual close spike**가 섞임. reference inference에서 t spot close는 5분 bar **닫힌 후**에만 관측 가능 → **학습 시점의 t값이 reference에서는 t+5min 시점에 가용**한 data leakage 의심.

**확인 액션**: v2 피처 추가 전, **모든 premium-유래 피처에 대해 reference feature extraction pipeline과 offline NPY 사이 bit-level diff 검증**. KOSPI에서 `predict_npy` uniform prediction 버그 (dont_repeat 2026-04-06)와 같은 학습/추론 불일치 재발 가능성.

## 판정 1 — **Expert2가 맞다. Target cross-sectional화가 최우선.** 

KOSPI `class_bins` 절대값 사태 재현 위험은 진짜입니다. 다만 Expert2의 진단 **이유는 부분 수정** 필요합니다.

> "bear regime에서 r이 모두 음수 → long 줄이기로 수렴"

zero-sum top-k weights (long 10, short 10, 동일 스케일)에서는 common factor가 **수학적으로 cancel**됩니다. `w·r = w·(r - r̄)` 가 성립해서, target이 절대값이든 demean이든 **loss 기댓값은 동일**합니다.

그럼 왜 진짜 문제인가? → **beta heterogeneity**입니다.

- 크립토 top-10 고변동 알트의 β_BTC는 1.3~2.0, 저변동 스테이블 유사는 0.3~0.7
- Bear regime에서 모델이 "고베타 숏, 저베타 롱"을 선택하면 **잔존 β < 0** → 숏만 산다
- 현재 LO SR long -1.25~-2.00, short +1.82~+2.21 비대칭 = **정확히 이 패턴**

**그러므로 처방**: target residualize만으로는 불충분. Loss에 **beta-neutrality constraint** 추가 필수.

```
r_i' = r_i - β_i · r_BTC                        # beta-residual target
loss = -E[w · r'] + λ_β · (Σ β_i · w_i)²        # portfolio beta ≈ 0
     + λ_vol · portfolio_vol 
     + λ_turn · |Δw|₁ · fee
```

β_i는 24h~7d rolling OLS로 사전 계산 (피처 겸). demean이나 단순 rank는 beta 이질성 못 잡습니다.

| Funding-asymmetric target | **철회** (Expert1: degenerate tautology) | target 순수 price_return, **PnL 계산에서만 funding 차감** |
| 절대 price_return target | **철회** (Expert2 + R1) | **β-residual target** `r_i - β_i·r_BTC` |
| β heterogeneity 무처리 | **철회** (R1: long/short β 비대칭이 현 숏-만-사는 현상의 핵심) | **loss 내부 β-neutrality constraint** |

R1의 "`w·r = w·(r-r̄)` 이라 common factor cancel" 수학적 지적은 정확합니다. 제가 간과한 건 **β heterogeneity**였습니다. 현 LO asymmetry(long -1.25~-2.00 / short +1.82~+2.21)가 "모델이 고β 숏·저β 롱 선택 → 잔존 β<0"의 mechanical consequence라는 진단, 데이터와 정합합니다.

## R1 질문 1 답변 — **In-loss soft constraint 채택**

```
loss = -E[w · r'] 
     + λ_β · (Σ β_i · w_i)²          # portfolio β ≈ 0, 미분가능
     + λ_vol · portfolio_vol 
     + λ_turn · max(|Δw|₁ - θ, 0) · fee
```

이유 3가지:
1. **Gradient 품질**: top-k 내부 hard balancing은 SoftSort 완화 체인을 **두 번 끊는다** (top-k + β argsort). 원인과 결과 gradient signal이 dilute.
2. **Lagrangian annealing 가능**: λ_β를 warmup (0→목표)으로 학습 안정성 확보. Hard constraint는 scheduling 불가.
3. **Inference 시 hard rebalance 옵션 추가 가능**: 학습은 soft, 추론은 `argmin |Σβ_i w_i|` re-ranking으로 정확 β=0 강제. 학습/추론 decoupling이 유리.

---

## 아키텍처 추가 제안 — **SOFT의 entropic OT가 gradient sparsity를 실제로 완화**

R1이 지적한 "top-k gradient sparsity = KOSPI sentinel과 동형" 우려, **Gumbel top-k에서는 맞지만 SOFT에서는 부분 완화**됩니다:

- **Gumbel top-k**: hard 샘플 → 20개 symbol만 gradient. 298 중 93% zero gradient.
- **SOFT (entropic OT)**: entropy reg ε가 mass를 **전 symbol로 spread**. k=10 타겟이지만 gradient는 모든 symbol에 흐름 (attenuation 비례). 학습 초기 ε 크게 → 후기 ε 축소로 soft→hard 전이.

**이게 제가 SOFT를 SoftSort보다 선호하는 구체적 이유**입니다. SoftSort는 구현 간단하지만 k 제약을 직접 표현 못하고 후처리 필요. SOFT는 k를 OT marginal로 직접 encoding.

Expert2 요구(5-class CE aux head 유지)와 결합하면 **three-fold gradient 공급**:
```
loss = loss_portfolio (SOFT, 전 symbol attenuated gradient)
     + α · loss_CE_percentile (전 symbol full gradient, α: 1.0→0.1 warmup)
     + β · loss_aux_horizons (c2c_1/5/30/120 β-residual, multi-task reg)
```

BTC/ETH sentinel 위험 → Expert1의 "per-symbol z + CS rank 동시"를 **모든 scale-sensitive 피처**(premium, OI, volume, amihud, trade_value)에 일괄 적용에 동의. 예외 두면 KOSPI `base_14` 재현.

## 1. 5-class CE aux → **Ordinal regression (CORAL)**로 교체

Expert2의 aux CE head, class_bins가 CS percentile [0.2,0.4,0.6,0.8] **순서 있는 bin**입니다. 순수 softmax CE는 class간 거리 정보 버림:
- "percentile 0~20 예측"과 "percentile 20~40 예측"의 오분류 cost가 동일
- 하지만 portfolio 관점에서는 인접 bin 오분류는 거의 무해, 양극 뒤집힘이 치명적

**CORAL (Cao et al., Pattern Recognition Letters 2020, arXiv:1901.07884)** — K-1 binary classifier에 rank-monotonicity weight tying. Percentile bin의 ordinal 구조를 gradient에 반영. 구현 원가 거의 없음 (head 마지막 layer만 변경).

**Deep Momentum Networks도 Sharpe 학습 전 ordinal pretraining 단계 사용** — 같은 철학.

---

## 2. Multi-horizon aux weight **learnable uncertainty weighting**

R3 스펙 `0.1·Σ CE_aux_horizons` — 고정 weight. c2c_1과 c2c_120은 signal-to-noise가 자리수 차이:
- c2c_1 β-residual: SR~0.05 대역 (noise 지배)
- c2c_120 β-residual: SR~0.3 대역

**Kendall, Gal & Cipolla (CVPR 2018, arXiv:1705.07115)** — 각 task에 learnable log-variance `σ_k`, loss `Σ (1/(2σ_k²))·L_k + log σ_k`. Noise 많은 horizon은 자동으로 weight 낮춤.

λ_turn/λ_β warmup과 독립이라 학습 간섭 없음. 고정 0.1이면 c2c_1 noise에 끌려가 main target gradient 오염 위험 있습니다.

---

## 3. SOFT Sinkhorn **log-domain iteration 필수** + ε_min floor 0.05

스펙에 "ε warmup 1.0 → 0.1"만 적혀 있는데, 구현 단에서 **수치 안정성 명시** 안 하면 재현성 사고:

- **Log-domain Sinkhorn** (Cuturi 2013 원래 formulation의 stabilized 변형) — standard-domain은 ε<0.2에서 underflow 빈번
- **ε_min floor = 0.05** (0.1 아님) — bull/bear regime boundary에서 z-score 분포 왜곡 시 0.1에서도 Sinkhorn 수렴 실패 가능. 최소 50 iteration 상한 + 비수렴 시 ε×1.5 자동 증가 fallback
- Red/Green TDD 테스트 항목 명시:
  - `test_soft_topk_marginal_converges_at_eps_min`
  - `test_soft_topk_gradient_nonzero_on_all_symbols_at_warmup_phase`
  - `test_soft_topk_falls_back_on_nonconvergence`

R3 실험 지시사항 9번 `src/training/heads/soft_topk.py`에 위 3개를 Red 단계 test로 고정 요청.

## R3 질문 답변 — **amihud도 예외 없이 per-symbol z + CS rank 적용**

질문: "amihud는 이미 log 변환 포함이므로 예외 둘까?"

**반대**. log 변환은 **분포 왜곡 보정**일 뿐, **cross-sectional 비교 가능성**을 보장하지 않습니다.

근거 3가지:

1. **Amihud = |r|/volume_usd** — volume_usd가 심볼별 자리수 차이. log 후에도 BTC amihud는 -15 대역, 소형 알트 amihud는 -8 대역처럼 **offset bias** 잔존.
2. **Regime 변화**: bear regime에서 전체 volume 30% 급감 시 amihud 전 심볼 동시 상승 → CS rank 없으면 regime-dependent 피처로 변질.
3. **KOSPI 교훈**: `base_14 = trade_value_per_avg_360min`도 log1p 포함. **log 변환이 sentinel 방지 못 함**(2026-04-15 autoresearch). log는 tail 압축용이지 scale-normalization 아님.

**결론**: 일괄 적용 원칙 **예외 없음**. "log 이미 있으니 괜찮다" 식의 피처 개별 tuning이 KOSPI `base_14` sentinel의 원인이었음. Phase 0-R entry gate 재실행 시 log-포함 피처도 per-symbol z + CS rank 후 IC/ICIR 재측정.

### 1. CORAL ordinal head — **Expert1 조건 + 한 가지 더**

Expert1이 "regime IC 부호 일치 피처에 한해"라고 했는데, **CORAL의 전제는 피처가 아니라 target 분포**입니다. CS percentile bin [0.2,0.4,0.6,0.8] 자체가 **regime마다 절대 수익률 폭이 완전히 다름**:

- Bull 구간: percentile 0~20 = -3% 대역, percentile 80~100 = +5% 대역
- Bear 구간: percentile 0~20 = -8% 대역, percentile 80~100 = +1% 대역

CORAL이 "bin 1→2 오분류 cost < bin 1→5 오분류 cost"를 가정하는데, **PnL 관점에서 이 가정이 깨짐**: bear 구간에서 percentile 4→5 오분류는 수익 절대값 차이가 크고, bull 구간에서는 작음. **Regime-aware CORAL** (bin boundary 대신 regime별 수익 gap으로 weight 재계산) 아니면 표준 CE가 차라리 안전. Phase 2-R에서 A/B 테스트 필수 — 표준 CE vs CORAL vs regime-weighted CORAL.

### 2. Learnable uncertainty weighting — **방향 찬성, formulation 수정 요구**

Kendall-Gal-Cipolla는 **task independence 가정**입니다. 그런데 c2c_1, c2c_5, c2c_30, c2c_60, c2c_120은 **nested cumulative return** — 강한 상관. c2c_120 = c2c_60(+0) + c2c_60(+60)처럼 정보 중첩.

Independent `σ_k`는 이 상관을 무시 → **정보량 과대 추정** → main task gradient weight가 부당하게 낮아질 수 있음. Multi-horizon이 "독립 task"가 아니라 **hierarchical signal**이라는 구조 반영:

**대안**: c2c_1~240을 개별 CE로 쓰지 말고, **forward return curve**를 하나의 타겟으로 두고 **curve reconstruction loss** (예: 각 horizon의 β-residual return을 5-dim vector로 묶어 MSE 또는 Gaussian NLL). Uncertainty는 curve 전체에 하나만. 구현 간단하고 multicollinearity 자동 처리.

R3 PM, 이 수정은 Phase 2-R 구현 스펙에 반영 요청. 고정 0.1도, independent σ_k도 아닌 **curve-level uncertainty** 안.

## R2 보강 3건 판정

### 1. CORAL — 방향 옳으나, **ListNet/LambdaRank A/B로 확장** 요구

Expert2의 "regime 간 bin 절대 수익 폭 차이" 지적이 맞음. 여기서 한 발 더 나감:

Portfolio 최종 decision은 **top-10 선택** — ordinal 전 구간 정확도 아님. CORAL이 bin 2→3 오분류 정확도에 투자하는 gradient가 portfolio objective로 환류되는 신호가 **구조적으로 약함**.

**대안: ListNet (Cao et al. ICML 2007) 또는 LambdaRank**. 5-class 경계 자체를 버리고 cross-sectional rank를 직접 학습 목표화. Portfolio top-k와 target이 **같은 ordering 공간**. Expert2의 regime-weighted CORAL 구현보다 단순 (Occam).

Phase 2-R A/B: **표준 CE vs CORAL vs ListNet (3-way)**. R3 PM 스펙에 반영 요청.

### 2. Multi-horizon uncertainty — Expert2 curve-level 동의, 단 **Gaussian NLL은 안 됨**

Expert2의 "c2c_1~240은 nested cumulative, independent task 위반" 정확. Curve reconstruction 방향 동의.

그러나 curve-level Gaussian NLL은 **heavy-tail 가정 위반**. 크립토 4h return은 kurt > 10, skew 큼(Liu-Tsyvinski-Wu 2022 표 3). Gaussian NLL은 tail event에서 loss 급증 → 학습 불안정.

**권장**: **Student-t NLL (df=5 고정)** 또는 **Huber curve loss**. 구현 비용 동일, tail 강건성 확보, gradient bounded. R3 PM 스펙에 "heavy-tail robust curve loss" 명시 요청.

### 3. SOFT 수치안정 + Expert1의 scale-shift invariance test — **전적 찬성**

추가할 것 없음. 특히 scale-shift invariance test가 BTC/ETH sentinel 재발 방지의 **직접 가드**. 필수.

## R1의 ListNet 지적에 승복 — **아키텍처 관점에서 이게 더 맞다**

R1이 짚은 "portfolio top-k와 target이 **같은 ordering 공간**" 논거가 결정적입니다. 제가 CORAL을 제안한 건 "percentile bin의 ordinal 구조"에 갇혔기 때문인데, **bin 자체가 중간 단계**입니다. 

- CORAL: "percentile bin 분류"라는 **프록시 task** 학습
- ListNet: "cross-sectional rank"라는 **portfolio objective 직접 정렬 학습**

Donti-Amos-Kolter (NeurIPS 2017)의 "task loss dominates" 정리 관점에서도 ListNet이 더 적합합니다 — portfolio allocation의 ordering이 바로 task. CORAL은 중간 misspecification 남김. **Phase 2-R A/B: 표준 CE / CORAL / ListNet 3-way에 동의**, 단 Expert2의 regime-weighted CORAL 대신 **regime-stratified ListNet** (bull/bear/neutral 각 regime에서 ListNet loss 평균) 포함 요청.

## Expert2의 curve-level 제안에 대한 R1의 Student-t 수정 — **완전 동의**

제가 간과한 heavy-tail. Liu-Tsyvinski-Wu (JF 2022)의 crypto kurt>10 데이터에 Gaussian NLL 쓰면 tail event 1개가 batch gradient를 **독점**. Student-t (df=5) NLL이 gradient boundedness + tail robustness 둘 다 확보. 구현 원가 JAX에서 `tfp.distributions.StudentT` 1줄. **R3 PM 스펙에 "heavy-tail robust curve loss (Student-t NLL df=5 default, Huber fallback)" 명시** 요청 동의.

## R1의 factor concentration 게이트 — **아키텍처 관점 보강 1건**

R1의 hierarchical clustering 게이트 (dominant family >40% 경고, >60% 차단)는 거의 완전한데, **representation 단계에도 projection** 추가 제안:

Phase 1-R backbone에 **factor-aware projection layer** (optional):
```
embedding → [momentum-head, mean-rev-head, microstructure-head, ...] 
         → concat → main task
```
각 head는 사전 정의 factor family별 subset 피처만 입력. 집중 factor에서 gradient가 다른 family head로 **regularization 효과** 발생. Phase 0-R 결과 dominant family 30~40% 경계 회색지대일 때 Phase 1-R 진입 가능 옵션.

**단 필수 아님** — Phase 0-R에서 집중 <30%면 불필요. R3 PM 스펙에 **옵션으로만 기재** 요청.

## SOFT scale-shift invariance test — Expert1 제안 채택, **구현 노트 1개**

`test_soft_topk_invariance_under_feature_scale_shift` 구현 시 주의: Sinkhorn log-domain에서 **log-sum-exp 수치 안정성**이 shift에 민감. PyTorch/JAX 둘 다 `logsumexp` max-subtraction이 기본이지만, 커스텀 Sinkhorn 코드에서 이걸 누락하면 shift +5 같은 작은 상수에서도 깨질 수 있음. **테스트 통과 + `scipy.special.logsumexp` 대조 검증** 병행 권장. `src/training/heads/soft_topk.py` 구현 시 Red 단계에 포함.

## 피처 관점 마지막 추가 2건 — Day 0 체크 확장 요청

### 1. **β_i 추정 품질 자체를 Day 0 체크에 포함**

β-residual target의 전제는 β_i 추정이 **시간에 걸쳐 안정적**이라는 가정입니다. 현재 스펙은 24h rolling OLS인데:

- Bull regime에서 BTC 변동성이 낮으면 **분모(Var(r_BTC))가 작아져 β 추정 분산 폭발**. 특히 2024H1 BTC 횡보 구간에서 β_i가 실제 알트 노출 대비 과대 추정될 수 있음
- Bear regime에서 BTC 급락 시 **단일 tail event가 24h window β를 지배**

**Day 0 체크 항목 추가 요청**: 후보 bull hold-out 구간에서 β_i trajectory의 **1d 변화율 분포 + bootstrap 신뢰구간**. 24h window β_i의 표준오차가 평균 β_i 크기의 30% 초과 심볼 비율이 높으면 **β window를 24h → 72h로 확장** 또는 **Kalman filter β** 대안 고려.

근거: β heterogeneity를 target에 반영하는 이상, β 추정 자체의 regime-dependence가 **2차 leakage 원인**이 됨. KOSPI `base_14`에서 배운 "정규화 전제 자체를 검증" 원칙의 연장.

### 2. **Scale-shift invariance test를 SOFT 단독이 아니라 feature pipeline 전체에 확장**

R2가 `test_soft_topk_invariance_under_feature_scale_shift`를 head 단위 test로 정의했는데, **feature pipeline 전체**(per-symbol z → CS rank → backbone → score → SOFT)에 end-to-end invariance test 1개 추가 필수:

```
test_pipeline_invariance_under_per_symbol_constant_shift
```

동일 심볼에 **상수 shift**(예: 모든 피처 값에 +0.01) 가해도 final portfolio weight 불변. per-symbol z-score가 상수 shift를 제거해야 하는데, **amihud처럼 log 변환이 앞에 있으면 shift-invariance가 깨질 수 있음**. 이 test가 통과해야 피처 개별 tuning 함정(amihud log가 다른 전처리와 interaction)을 막음.

## 1. Expert1의 β_i 추정 품질 체크 — **"피처 품질" 아니라 "Target 품질" 이슈로 재분류 요구**

Expert1이 "피처 관점 추가"로 올렸지만, **이건 본질적으로 problem formulation 문제**입니다. 내 관점에서 경고 수위를 한 단계 올립니다:

현재 target이 `r_i' = r_i - β_i·r_BTC`인데, β_i가 regime-dependent noise를 포함하면 **target 자체가 label noise를 실어나르는 통로**가 됩니다. 즉:

- β_i estimation error = **target construction noise**
- 이 noise는 피처 pipeline이 제거 불가 (label에 있으므로)
- 모델 capacity가 아무리 좋아도 **irreducible label noise 하한** 확정

이건 R1이 "label noise 대비 모델 capacity"라고 제가 초기에 강조한 그 지점의 **target 측 발현**입니다. β heterogeneity를 해결하려 도입한 β-residual이 **β 추정 불안정성을 target으로 smuggling**하는 역설.

**요구사항 (Expert1 체크 확장)**:

```
Day 0 β quality gate (pass/fail):
1. 후보 bull 구간 β_i trajectory:
   - 24h rolling OLS β_i의 1d 변화율 |Δβ|/|β| 분포
   - bootstrap 1000회 β_i 95% CI width / |β_i 평균|
2. "β 불안정 심볼" 정의: CI width ratio > 0.3
3. Universe에서 β 불안정 심볼 비율:
   - < 20%: 24h OLS 유지
   - 20~40%: 72h OLS로 확장 (longer window)
   - > 40%: Kalman filter β 또는 β-residual target 자체 재고 ★
4. Regime별 β 추정 bias 측정:
   - bull/bear/neutral 3 regime에서 β_i 평균값 분포 비교
   - regime 간 평균 β shift > 0.5면 "β가 regime marker" 오염 경고
```

**4번이 결정적**입니다. Regime 간 β가 크게 shift하면 β-residual target이 "regime 방향"을 residual로 implicit encoding — **regime-robust라는 설계 목표와 정면 충돌**. 이 경우 target을 β-residual에서 **rank-based cross-sectional residual** (각 timestamp에서 demean + standardize)로 대체 검토 필요.

## Expert2의 β 품질 재분류 — **전적 승인, 한 단계 더 강화**

Expert2가 Expert1의 "피처 품질" 프레임을 **"target 품질"**로 재분류한 것, 결정적으로 옳습니다. β-residual target은 β 추정 error를 **irreducible label noise**로 smuggling하는 구조 — 이건 피처 전처리로 제거 불가.

여기에 한 가지 추가합니다:

### β 추정 자체의 **horizon mismatch** 문제

현 스펙 β_i = 24h rolling OLS, target horizon = 4h. 이게 조용히 깔려 있는 mismatch:

- **Rolling window horizon**: β_i가 24h 동안의 co-movement를 평균 → 4h intraday β와 lag
- **Market microstructure β ≠ daily β**: 크립토는 intraday에서 BTC 주도 "drag effect" 시점별 강도 변화 (Hou-Xue-Zhang 2020 crypto factor model)
- **4h β로 직접 추정 시도**: 샘플 수 6배 증가하나 noise 폭발 → 역시 불안정

**요구사항**: Expert2의 4개 β 품질 gate에 **5번 추가**:

```
5. β estimation horizon sensitivity:
   - 4h / 24h / 72h rolling OLS β_i 3종 산출
   - Pairwise Spearman correlation > 0.7 (β ordering 안정성)
   - < 0.5 시: "β가 horizon-dependent" 경고 → β-residual target 재고
```

경고 발동 시 Expert2의 대안(rank-based CS residual)으로 전환하는데, 저는 **demean만이 아니라 demean + median absolute deviation scaling**을 추가 제안합니다. 단순 demean은 regime별 dispersion 차이를 그대로 둬서 loss scale이 regime간 불일치. MAD scaling하면 regime-invariant target scale 확보.
