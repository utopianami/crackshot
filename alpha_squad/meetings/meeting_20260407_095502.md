# Researcher2 (AI 아키텍처) 발언

## 핵심 통찰: 새 환경은 "랭킹 + IC"를 직접 보상한다

새 백테스트 환경의 두 변경점이 **하나의 동일한 신호**를 가리킵니다:
- **IC sizing**: rolling Pearson(pred, ret_60) ≥ 0.05 → 3x. 즉 보상 함수 자체가 **IC**.
- **wScore4 [-2,-1,0,1,2]**: extreme class 정확도가 PnL 결정. 즉 **꼬리(tail) 랭킹**이 중요.

→ 현재 baseline은 5-class CE(pointwise classification)로, **IC도 ranking도 직접 최적화하지 않음**. 이 gap이 가장 큰 leverage.

---

## 제안 1순위: IC-Aligned Loss (즉시 실행)

**아이디어**: CE 대신 **differentiable Pearson IC loss**를 직접 최소화.

```
L_IC = -corr(pred_score, ret_60_target)   # per-batch, per-timestamp
```

- Score: class probability × [-2,-1,0,1,2] (wScore4 그대로)
- Target: forward 60-bar return (continuous)
- Per-timestamp에서 cross-sectional Pearson 계산 후 평균

**왜**: IC sizing 메커니즘이 **literally** 이 양을 측정해서 3x 레버리지를 결정함. 학습-추론-사이징이 동일 metric으로 정렬됨.

**근거**: *IC-Aligned Loss for Stock Prediction* (arXiv 2023), *On Evaluating Loss Functions for Stock Ranking* (CIKM 2025) — listwise/IC loss가 pointwise CE 대비 rank IC 지속적 개선.

**스펙**: model=`cs_mlp_200_base`, feat=base100(300dim), label=ret_60 continuous, loss=`IC_loss + 0.1*CE` (CE는 안정화용). 성공기준: Alpha Sharpe ≥ 3.5.

---

## 제안 2순위: TabM (architecture diversity, 거의 공짜)

**아이디어**: 현재 cs_mlp [256,128] 단일 → **TabM (BatchEnsemble k=32)** 로 교체. 입력/출력/feature 동일.

**왜**:
- 코드베이스에 `tab_m` 이미 구현 + `cs_mlp_200_base` config 그대로 model name만 교체 가능
- BatchEnsemble은 single-model cost로 k-way ensemble 효과 → **IC variance 감소** (= IC sizing이 3x 구간에 더 자주 머묾)
- ICLR 2025 TabM 논문이 tabular에서 FT-Transformer/TabPFN과 동등 성능을 단일 비용으로 달성

**스펙**: model=`tab_m`, feat=base100(300dim), label=c2c_60 5-class, loss=CE. 성공기준: Sharpe ≥ 3.10에 seed variance ↓.

---

## 제안 3순위: FactorVAE — beta 누출 구조적 해결

**아이디어**: 4/3 회의 진단("모델이 alpha 아닌 beta 학습")에 대한 **아키텍처 차원의 답**.

- Encoder: features → latent factors z
- Posterior: 실제 return으로 z 보정 (학습 시에만)
- Decoder: z → β×factor + α
- **출력은 α만 사용**

**왜**: VAE의 posterior supervision이 시장 beta를 explicit하게 분리함. CSI 300/500에서 Rank IC 0.08–0.10 (AAAI 2022). 코드베이스에 `cs_factor_vae` 이미 존재 → 신규 config만 작성하면 됨.

**스펙**: model=`cs_factor_vae`, feat=base100, label=c2c_60 continuous, loss=ELBO + α-prediction. 성공기준: Alpha PnL ≥ +9M, MDD ↓.

---

## 제안 4순위: Vol-Normalized Label (입력/loss와 직교)

**아이디어**: label = `c2c_60 / realized_vol_20` → 5-class quantile.

**왜**: dynamic_slippage가 이미 변동성을 **execution 측에서** 활용 → label도 vol-normalize하면 모델이 변동성을 두 번 예측하지 않고 **residual alpha**에 집중. Moreira-Muir (JoF 2017), ReVol (CIKM 2025) 근거.

**1순위 IC loss와 직교**하므로 결합 가능: IC loss + vol-normalized target.

---

## 제안 5순위 (다양성 확보용): StockMixer

**아이디어**: 3-stage MLP mixing (indicator → multi-scale time → bidirectional stock). cs_mlp의 **per-sample 처리**를 유지하면서 **explicit cross-stock mixing**을 한 번 거침.

**왜**: AAAI 2024에서 RNN/Transformer/GNN baseline을 lower cost로 outperform. cs_mlp는 종목 간 직접 상호작용 없음 → IC sizing이 cross-sectional rank를 보상하는 환경에서 **explicit stock mixing**이 보완재.

**리스크**: 코드베이스에 미구현 → 신규 architecture 파일 필요. P2.

## 1. IC-Aligned Loss — **가장 위험한 제안**. 두 가지 치명적 mismatch.

### Mismatch (a): backtest IC ≠ 학습 loss IC

백테스트 IC sizing 정의를 다시 보세요:
> `IC = Pearson(avg_prediction over 240 bars, avg_return_60bar)`

이건 **종목별 시계열** 240바 평균의 상관입니다. 그런데 Researcher2의 IC loss는 **per-timestamp cross-sectional** Pearson입니다. **완전히 다른 양**입니다.

- 백테스트가 보는 IC: "이 종목은 최근 4시간 동안 예측이 잘 맞았는가" (per-coin temporal)
- 제안된 loss IC: "이 시점에 200종목 사이의 ranking이 맞았는가" (per-timestamp CS)

**둘은 양의 상관도 보장 안 됨**. CS rank를 잘 맞춰도 시계열 평균이 noise면 IC sizing은 0.05x로 떨어짐. **학습이 backtest reward를 최적화한다는 주장의 전제부터 틀렸습니다.**

대안: 진짜로 backtest IC를 정렬하려면 **종목별 시계열 240-window IC**를 loss로 써야 함. 그러나 이건 batch 구성이 timestamp가 아니라 (coin, time-window)가 되어야 하고, 학습 mini-batch와 충돌. 차라리 이 방향은 포기하고 **2번 제안(label horizon 정렬)** 으로 가는 게 정직.

### Mismatch (b): Pearson + wScore4 = 분산 붕괴

`pred_score = class_prob × [-2,-1,0,1,2]`은 본질적으로 **5점 discrete output**입니다. 200종목 cross-section에서 5점 척도의 Pearson은 ties가 많아 분모(std)가 매우 작아지고, **gradient가 폭발**합니다. 또한 batch 내 한 종목이 ±2로 튀면 corr이 그 한 종목에 지배됨.

제대로 하려면 **Spearman rank IC** 또는 **listwise loss (LambdaRank, ListNet)**. 코드베이스에 RankNet/listwise 구현이 있는지부터 확인 권고.

**판정: P0-1을 그대로 실행하면 학습 발산 또는 backtest 비개선 가능성 70%. 1순위에서 강등.**

## 2. TabM — 동의하지만 **label 문제를 가립니다**

4/3 회의 결론이 "모델이 alpha 아닌 beta를 학습한다"였습니다. TabM은 ensemble variance를 줄여줄 뿐 **bias를 못 고침**. 같은 잘못된 target을 32개로 평균해도 같은 beta가 나옵니다.

TabM은 **label/loss 수정이 끝난 후 마지막 단계**의 baseline 안정화 도구로 써야지, 지금 단계에서 아키텍처 다양성으로 위장해서 P0에 두는 건 부적절. P1로 강등.

---

## 3. FactorVAE — **leakage 검증 없이는 못 씁니다**

VAE posterior가 학습 시 실제 return을 사용한다는 점, 두 가지 leakage 경로 점검 필수:

1. **Split 경계 누설**: posterior 학습 시 같은 timestamp의 다른 종목 return이 latent factor에 인코딩됨. NPY split 경계에서 train의 factor가 test 시점에 reconstruct되면 train→test rolling이 오염. `dont_repeat.md` 2026-03-30 "NPY enhanced feature 날짜별 리셋" 사고와 같은 카테고리.
2. **α 분리의 misspecification**: KOSPI 200의 systematic factor는 사실상 KOSPI 지수 1개 + 섹터 5–10개입니다. latent dim을 16+ 잡으면 **남는 차원이 noise를 alpha로 학습**합니다. latent_dim ≤ 8로 강제, 그리고 학습된 factor와 KOSPI/섹터 ETF return의 상관을 사후 확인할 것.

조건부 P1 유지. **leakage audit 없이는 절대 reference 금지**.

## 4. Vol-Normalized Label — **방향은 맞지만 denominator가 틀렸다**

`c2c_60 / realized_vol_20`은 두 가지 문제:

1. **Window 짝이 안 맞음**: numerator는 forward 60바인데 denominator는 backward 20바. regime shift 시 (예: 09:00 직후) backward 20바 vol이 forward 60바 vol을 전혀 대표 못 함. 최소 backward 60–120바.
2. **저유동성 종목 false-positive**: KOSPI 200 하단부 종목은 vol_20이 매우 작은 구간이 빈번. 분모가 0에 가까우면 label이 폭발. 5-class quantile로 잘라도 **저변동성 구간이 양극단(±2)을 전부 차지**하는 distortion 발생.

수정안:
- denominator = `realized_vol_120` (forward 60과 균형)
- 또는 **EWMA vol with halflife=60**
- floor: `max(vol, percentile_5(vol_universe_t))`

이 수정 후라면 P0에 둘 가치 있음. **현재 형태로는 수정 필수**.

## 5. StockMixer — **reference inference 호환성부터 확인**

StockMixer의 bidirectional stock mixing은 학습 시 **모든 종목이 동시 정렬**되어야 합니다. 그런데 reference inference (`reference_inference_cs_mlp_200_base.py` 계열)는 종목별 독립 inference 구조입니다. 즉, **reference 배포 시 cross-stock layer를 어떻게 처리할지** 설계 자체가 빠져 있습니다.

벤더 캔들이 1분 경계에서 종목 동시 정렬되어 있는지, 그리고 inference latency가 200종목 한꺼번에 처리 가능한지 확인 후에야 P2 검토 가능. **확인 없이 구현 시작 금지**.

# Expert2 발언 — 두 분 모두 여전히 잘못된 문제를 풀고 있습니다

Expert1의 IC mismatch 지적은 정확합니다. 그런데 **거기서 멈춰서 한 단계 더 안 갔습니다**. backtest IC 정의를 제대로 다시 읽어보면, 두 분이 논의 중인 모든 제안이 **타겟 자체가 틀린** 것으로 드러납니다.

---

## 핵심 비판 1: backtest IC는 cross-sectional 문제가 아닙니다. **per-coin temporal 문제**입니다.

회의 KB가 정의한 IC sizing:
> `IC = Pearson(avg_prediction_t over 240 bars, avg_return_60bar_t) over 240 bars`

이건 **종목별로 독립적으로**, 최근 240바(=4시간) 동안 그 종목의 예측이 그 종목의 60바 수익률과 얼마나 상관있는지입니다. 즉:

- "이 종목 예측이 **최근 4시간 동안 자기 자신의 미래 수익률을 얼마나 잘 맞췄나**"
- cross-section 200종목 ranking은 **IC sizing 계산에 들어가지도 않습니다**
- 한 종목의 IC가 0.05면 그 종목만 3x, 다른 종목은 그대로

이 함의는 충격적입니다:

1. **Researcher2의 cross-sectional Pearson IC loss** — 잘못된 양 최적화. CS rank를 완벽히 맞춰도 종목별 시계열이 noise면 전 종목 IC sizing 0.05x.
2. **Expert1의 listwise/Spearman 대체안** — 같은 결함. 여전히 cross-sectional.
3. **Expert1이 제안한 cross-sectional rank features** — features는 무해하지만, 이게 "랭킹 문제"라는 mental model을 강화함. 위험.
4. **FactorVAE의 alpha 분리** — alpha가 cross-sectional residual인데 backtest는 그걸 보상 안 함.

**진짜 문제 정의**: "각 종목별로, 짧은 시계열 윈도우 안에서 자기 자신의 60바 미래 수익률과 stable하게 상관되는 score를 만들어라."

이건 **종목별 calibration + temporal stability** 문제이지, **cross-sectional ranking** 문제가 아닙니다. 두 분이 한 시간째 잘못된 카테고리 안에서 답을 찾고 있습니다.

---

## 핵심 비판 2: wScore4가 "tail 정확도가 중요하다"는 해석은 절반만 맞습니다

Researcher2는 wScore4 [-2,-1,0,1,2]를 보고 "tail 분류 정확도가 중요"라고 결론냈습니다. 그러나 IC sizing과 결합하면 함의가 다릅니다:

- IC sizing은 **score의 magnitude가 아니라 score-return correlation**을 봄
- 즉 **항상 ±0.5씩만 출력해도 IC가 높으면 3x로 곱해짐**
- 반대로 **±2 극단값을 자주 출력해도 IC가 낮으면 0.05x**

→ 즉 **"tail accuracy"가 아니라 "calibrated monotonicity"가 진짜 보상**입니다. CE loss로 5-class를 학습하면 모델은 confidence를 만들지만 monotonicity는 보장 안 됨. **isotonic regression head** 또는 **ordinal regression loss**가 진짜 정답일 수 있습니다.

CORN loss (ordinal classification, Cao et al. 2020), Beckham & Pal (ICML 2017) ordinal output 등이 후보. 둘 다 cumulative threshold 학습으로 monotonicity를 강제합니다.

---

## 핵심 비판 3: 240바 window는 너무 짧아서 **regime이 학습/추론 사이에 바뀝니다**

240바 = 4시간 ≈ 1 거래일의 절반. IC sizing은 **거의 intraday regime에 따라 sizing이 휙휙 바뀐다**는 뜻입니다. 이게 의미하는 바:

1. **학습 데이터의 IC 분포 ≠ 실거래 IC 분포**. 학습 시 보는 14개월 평균은 거의 무관. 모델이 주의해야 할 것은 **세션 시작 시 IC가 unstable한 구간**.
2. **시간대 conditioning이 거의 필수**. 09:00~10:00 vs 13:00~14:00에 IC 분포가 다를 가능성 매우 높음. 이걸 모델이 모르면 IC sizing이 매번 cold start.
3. **Researcher2의 TabM 제안만이 이 문제에 부분적으로 답이 됩니다** (variance 감소 = IC 안정화). Expert1이 TabM을 P2로 강등한 건 **잘못된 판단**입니다. 새 환경에서 IC variance 감소는 직접적으로 sizing multiplier를 올립니다.

**제안**: **time-of-day embedding** + **rolling IC regime feature** 추가. 이건 feature 차원의 변경이지만 문제 정의 차원에서 필수. 모델에게 "지금 너의 IC가 어떤 regime에 있는지" 알려줘야 self-calibration 가능.

---

## 핵심 비판 4: validation 방식이 IC sizing을 simulate 안 합니다

두 분 모두 validation을 언급조차 안 했는데, 이게 가장 큰 구멍입니다.

- 현재: 14/2/2 month split, val accuracy/CE loss로 model select
- 문제: **selected model이 IC sizing 환경에서 최고라는 보장이 전혀 없음**
- 같은 val loss라도 **per-coin temporal IC variance**가 작은 모델이 실거래에서 압도적으로 유리

**validation metric을 backtest IC simulation으로 교체해야 합니다**:
- val 기간에 대해 종목별 240-bar rolling IC 계산
- `mean(IC) - λ × std(IC)` 또는 `fraction of (IC ≥ 0.05)`을 model selection metric으로 사용
- λ는 sizing curve 기반 (IC ≤ 0면 0.05x, IC ≥ 0.05면 3x → IC stability에 큰 보상)

**이거 하나만 바꿔도 같은 모델로 Sharpe 갱신 가능성 있습니다.** loss를 안 바꿔도, model selection만 backtest reward에 align해도 기존 후보 중 더 나은 게 나올 수 있음. Cost 거의 0.

---

## 핵심 비판 5: multi-horizon multi-task는 두 분 다 빠뜨림

Researcher2가 multi-horizon을 KB 검색에서만 언급하고 본 발언에 안 넣었습니다. 그런데 새 환경에서 이게 가장 자연스러운 formulation입니다:

- Head 1: c2c_60 5-class (IC sizing horizon에 정확히 align, sizing 최적화)
- Head 2: c2c_120 5-class (z_score signal 안정성, 진입 타이밍)
- Head 3 (선택): 60-bar realized vol 회귀 (dynamic_slippage가 vol을 사용하므로 vol 인지가 score quality를 끌어올림)

shared backbone + 3 heads, total loss = α·CE_60 + β·CE_120 + γ·MSE_vol. inference 시 wScore4 dot은 60 head 사용.

**근거**: Caruana (1997) MTL, Ruder (2017) overview, 그리고 금융 specific으로 Cong et al. (2021) "AlphaPortfolio" — multi-objective가 single objective 대비 IC variance 감소.

**핵심 효과**: vol head가 backbone에 vol-aware representation을 강제 → 같은 cs_mlp가 dynamic_slippage 환경에서 더 나은 score 생성. label/loss/architecture 다 안 바꾸고 head만 추가.

이게 정확히 무엇인지 풀어 쓰면:

```
avg_pred_τ  = mean over all coins of prediction at time τ        # scalar per τ
avg_ret_τ   = mean over all coins of (close_{τ+60}/close_τ - 1) # scalar per τ
IC_t        = Pearson( {avg_pred_τ : τ ∈ [t-239, t]},

multiplier  = scale_to_[0.05, 3.0] by IC_t
```

## 그러나 — 이 정정이 architecture 차원의 답을 **더 분명하게** 만듭니다

IC sizing이 보상하는 양을 다시 풀어쓰면:

```
∀τ ∈ [t-239, t]:
    avg_pred_τ = (1/N) Σ_i pred(coin_i, τ)
    avg_ret_τ  = (1/N) Σ_i (close_{i, τ+60}/close_{i,τ} - 1)
IC_t = Pearson(avg_pred_τ, avg_ret_τ)
```

**핵심 관찰**: 모델 출력은 두 가지 채널로 쓰입니다.

| 채널 | 어떤 양을 보상받는가 | 어떤 모델 학습이 적합한가 |
|---|---|---|
| **(A) 진입 선택** (`z_score_threshold=2.5`) | per-coin score의 **cross-sectional 극단성** | 종목별 alpha (4/3 결론과 일치) |
| **(B) 사이징 multiplier** (`IC_t`) | **mean(pred) vs mean(ret) 시계열 상관** | 시장 평균 신호의 calibration |

**4/3 결론과 4/7 환경의 충돌은 '같은 출력을 두 채널이 다르게 사용한다'는 사실 때문**입니다. 단일 head로는 두 양을 동시에 최적화 못함. **이건 architecture 문제**입니다.

→ Researcher1의 P1-1 (MTL with market head)이 단순한 보조 손실이 아니라 **이 환경의 구조적 정답**입니다. 그 위에 한 단계 더 밀어붙이겠습니다.

## 새 제안: Dual-Path Network with Market Aggregator

### 구조

```
Input (per-coin features, 300dim)
        │
        ├─→ Per-coin backbone (cs_mlp [256,128])
        │       ↓
        │   Per-coin head → 5-class (CE, wScore4 weighting)        ← (A) 진입 채널
        │
        └─→ Market aggregator: mean/std/quantile pooling across coins
                ↓
            Market backbone (small MLP [64,32])
                ↓
            Market scalar head → predicts mean(ret_60) at τ        ← (B) 사이징 채널
                ↓
            **240-rolling Pearson loss** with mean(ret_60) sequence

Total loss = α · CE_per_coin(score4) + β · MarketIC_loss
```

**핵심 아이디어**: per-coin backbone은 cross-sectional alpha를 학습하고 (4/3 결론 보존), 별도의 market head가 시장 평균 signal을 시계열 IC와 정렬. 두 head가 같은 backbone을 공유하지 않고 **분리된 path**라는 게 핵심 — 그래야 alpha 학습이 market beta 학습에 끌려가지 않습니다.

### Market IC loss 구체화

Researcher1의 P0-2 ("batch sampler 재설계 — timestamp 240개 연속 + 200종목 동시")가 어렵다는 점을 푸는 방법:

- **Mini-batch unit을 (timestamp window 240개 × 200 coins)** 로 정의
- 이건 per-step으로 200×240 = 48,000 sample. cs_mlp 메모리로 충분 (현재 batch도 비슷한 규모)
- mean(pred over coins) 시계열 240개 → corr with mean(ret_60) 시계열 240개 → 단일 스칼라 loss
- per-coin CE는 같은 48,000 sample에 그대로 적용 (loss 두 개 합산)

→ batch sampler 한 개만 새로 짜면 두 loss를 한 forward pass로 학습. **R1이 '높은 비용'으로 표시한 P0-2의 cost를 architecture 분리로 흡수**.

### 왜 architecture를 분리해야 하는가

Expert2가 제안한 단일 backbone + 3 heads (60/120/vol) MTL은 backbone gradient가 두 objective의 vector sum이라 **alpha vs beta tug-of-war** 발생. 4/3 결론은 정확히 이 tug-of-war에서 backbone이 beta로 끌려갔다는 진단입니다. **두 backbone을 분리**해야 alpha path가 beta gradient로 오염 안 됨.

**근거**: Multi-gate Mixture-of-Experts (Ma et al. KDD 2018, MMoE), Cross-Stitch Networks (Misra et al. CVPR 2016) — task-conflict가 큰 MTL에서 shared backbone이 harm. 분리된 sub-network + task-specific gating이 일관되게 우수.
