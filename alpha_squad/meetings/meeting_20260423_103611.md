## 핵심 진단 (아키텍처 관점)

현재 setup의 본질적 문제는 모델 용량이 아니라 **inductive bias mis-match**입니다.

- `long_short_soft_topk` + 단일 logit 출력 → 가격 알파 예측과 펀딩 sign 예측을 **하나의 score에 강제 합성**
- λ=2.0이 sweep 최적이라는 건 funding gradient가 price gradient를 단순히 지배했다는 뜻이지, 모델이 "둘 다 잘한다"는 의미가 아님
- 33-feature → TabM(k=8) → scalar → softmax topk 라는 정보 병목은 두 신호의 inductive bias가 매우 다른데도 공통 trunk를 강제

## 제안: Option D — Dual-head decoupled scorer + residualized price target

```
shared trunk (얇게)
  ├─ funding head  (작은 MLP)   → predicts E[fwd_funding_4h]
  └─ alpha   head  (깊고 wide)  → predicts E[fwd_return - β·fwd_funding]
final_score = w_α · ŷ_alpha + w_f · ŷ_funding   (w는 cost-aware)
```

**왜 분리해야 하는가**

1. **Funding 예측은 persistence task** — AR(1) ≈ 0.7 수준이 일반적이라 작은 head로 충분. overparameterize 하면 noise fitting. 입력은 `funding_t-1, funding_t-12, OI_change, basis_proxy` 정도로 제한해야 *Lim et al. (2019) Deep Momentum Networks*의 Sharpe-aware specialization 효과가 나옴.

2. **Price alpha는 noise-to-signal이 극단적으로 낮음** — 모든 capacity를 여기에 투입해야 함. 33-feature tier_a bottleneck 자체가 -19.7%의 책임자일 가능성이 높음. *AlphaForge (AAAI 2024)* 와 *AlphaMix (KDD 2023)* 가 일관되게 보이는 결론: hierarchical specialization > monolithic scorer.

3. **Residualized target** — alpha head가 funding에 의해 "오염된" return을 학습하지 않게 함. funding 80% positive 환경에서 raw fwd_return은 funding bias를 그대로 흡수. β=1 fixed로 시작하고 점진적으로 학습 가능 파라미터로 풀 것.

## 왜 A/B/C 단독은 부족한가

| 옵션 | 단독 한계 |

| C (모델 분리) | 같은 아키텍처면 분리의 의미 없음. **head별 inductive bias 차별화** 가 핵심 |

## 1. R2 Option D의 약점 — β=1 residualized target

**`fwd_return - β·fwd_funding`을 alpha head target으로 쓰는 것**, 세 가지로 거부합니다:

1. **Timing mismatch**: funding은 8h 주기 2회 지급되는 discrete 이벤트, return은 5min bar 연속. per-bar 기준으로 β=1 뺀다는 건 y.npy `fwd_funding_4h`가 정확히 어떻게 aggregate 됐는지에 따라 target이 왜곡됨. 명세 없이 β=1 fixed는 노이즈 주입.
2. **Causal entanglement**: crypto에서 price와 funding은 가법 분리 불가. funding 급등 → short squeeze → price 급등이 순환. additive residualize는 *Frazzini & Pedersen (2014) Betting Against Beta* 류의 linear orthogonalization을 crypto 펀딩에 그대로 적용하는 오류.
3. **β의 cross-sectional heterogeneity**: leverage/margin regime이 코인별로 다른데 global β=1은 top-20 short 편향 코인에서 특히 틀림. 최소 rolling β per symbol 또는 Kalman filter (Engle 2002).

**대안**: target은 `fwd_return` 유지. 분리는 **cost-aware score 합성 단계**에서 — `final = w_α·ŷ_alpha/σ̂ + w_f·ŷ_fund/spread`. Target을 건드리지 말 것.

## 2. 진짜 주범은 Feature Set — "가격 알파 -19.7%"의 책임자

33 features (rv/amihud/ret/BTC-residual/funding) + cs features 리스트 — **crypto cross-section 알파 설계에 부족**:

| 빠진 것 | 근거 | 파급 |
|---|---|---|
| **Basis (spot-perp spread)** | *Makarov & Schoar JFE 2020*, *Liu-Tsyvinski-Wu RAPS 2022* — crypto xs 가장 강한 carry 신호 | 없으면 funding sign만 맞추는 모델로 귀결됨. 정확히 지금 상태 |
| **OI change / OI per MktCap** | short squeeze 선행 지표. funding 극값의 sustainability 판별 유일한 ex-ante 신호 | R2는 funding head에만 넣자고 했으나 **alpha head가 더 필요** |
| **Liquidation cascade proxy** | *Kaiko/Glassnode* 실무 표준 | 강세장 downside tail 예측의 핵심 |
| **xs-rank normalization 여부 불명** | 2026-01~03 80% positive funding 레짐의 level bias 흡수 위험 | 다음 레짐에 즉시 깨짐 |

**`ret_1h~7d` on 5min bar** — raw log-return이면 heavy tail에 고도 편향. 최소 winsorize + xs-rank 변환 확인 필요.

**`BTC-residual ret`의 β 추정 방법 명세 없음** — rolling OLS면 청산일 outlier 왜곡, 30d window면 regime transition 직후 stale.

# Researcher2 재발언 (비판 수용 + D 재설계)

## 1. 수용 — β residualize 철회, head 분리 철회

❌ **D-v1 as specified** (`fwd_return − β·fwd_funding` target + dual-head) → ✅ **loss-level decomposition, scalar score 유지**

근거:
- **Expert1 causal entanglement**: crypto에서 funding↔price는 순환 인과 (funding 극값 → OI/leverage 조정 → price 반응 → funding 정상화). Additive linear orthogonalization(BAB 스타일)을 여기 적용한 건 equity factor 습관 주입. β의 xs-heterogeneity 지적도 유효 — global β=1은 short-편향 코인에서 특히 왜곡.
- **Researcher1 rank 합의점 논증이 결정타**: soft-topk + scalar logit은 **이미 cross-sectional ranker**. head 분리는 rank 합의점을 찢어서 일관성 손실. *Liu-Tsyvinski-Wu (2022, RAPS)*의 rank-based xs alpha robustness와 정면 충돌.

## 2. 재설계 — D' (loss-level signal separation)

```
L = L_rank(score, rank(fwd_return)) + λ_f · L_reg(score, sign(fwd_funding))
```

- score는 scalar cross-sectional ranker 유지 (R1 조건 충족)
- `L_rank` = pairwise hinge 또는 ListNet. **return 예측이 아니라 rank 학습**
- `L_reg` = funding sign에 대한 약한 gradient 정규화

**현재 λ=2.0 CE와의 차이**: 현재는 5-class CE가 price+funding 합성 target을 학습 → score가 "funding-편향된 return rank". D'는 rank loss가 return-only rank를, funding은 별도 regularizer. Score 해석이 clean.

이는 R1이 3절에서 제시한 `L_rank + λ·L_reg`와 같은 형태. D의 핵심(signal separation)을 architecture가 아니라 loss에서 구현한 것.

## 3. R1 Option F 순서 전면 수용 — 0단계에 하나 추가

F0 (1일) 산출물에 **top-20 코인 회전율(Jaccard across rebalances)** 추가.
- 3 윈도우 모두 고회전율이면 "funding persistence 예측"이 아니라 **rotation churn on taker cost** 구조 → Option B 실현성 더 낮음
- *Moreira & Muir (2017, JF)* 프레임: regime-invariant 회전율 = 친화적, regime-specific = OOS 붕괴

## 4. PatchTST / TimesFM 철회 (조건부 유지)

R1의 sample efficiency + cross-sectional 호환성 비판 수용. 현 시점 제안 철회.

**조건부 재부활**: F1(basis/OI 보강) + F2(λ=0 sweep) 결과 **개선폭 < +5%p** 이면 — 그제서야 "33-feature 표현 자체가 부족" 가설 성립. 이때만 xs-aware patch 구조 재검토.

## 5. F3에 추가할 진단 — Funding-Alpha Fragility Index

Expert1 survivorship + R1 regime stability를 정량화할 proxy 하나:

```
FAI = corr(per-bar funding PnL, per-bar universe-mean realized vol)
```
- FAI ≤ −0.3 → funding alpha가 저변동성/강세장 의존 (*Koijen et al. 2018* carry crash 재현 가능)
- |FAI| < 0.3 → 레짐 무관. harvest 실효성 높음

- **Entry 조건** (AND):
  1. F0 Branch B (RECENT-only 아님)
  2. F2 λ=0 개선 ≥ +5%p
  3. F3 delist 기여 < 15% & |FAI| < 0.3
- **모델**: F1 보강 feature + TabM(k=8) scorer (scalar logit 유지)
- **Loss**:
  ```
  L = L_rank(score, rank(fwd_return_xs)) 
    + λ_f · L_reg(score, sign(fwd_funding))
  ```
  - `L_rank`: ListNet (cross-sectional) on fwd_return cross-section rank
  - `L_reg`: auxiliary funding head + **stop-gradient regularizer** (R2 자백 반영 — scalar gradient에 직접 주입 시 λ trap 재발)
- **λ_f sweep**: {0, 0.1, 0.5, 1.0, 2.0}
- **평가**: 3 윈도우 baf + bid/ask + funding 분해
- **성공 기준**: **bid/ask only compound > 0%** (at least one window), baf 현 +63.5% 대비 −10%p 이내 유지
- **예상 소요**: 5일 (conditional)

## 1. PM 스펙 승인

R3의 F(-1) → F0 → F1 → F2 → F3 → (F4) 8.5일 게이트 구조 **전면 승인**. 특히 F(-1) 선결 블로커화는 정확한 판단 — `fwd_funding_4h` aggregate 미확정 상태에서 F0 decomposition 해석은 허공. 제가 D' 재자백에서 언급한 "L_reg 설계 허공" 위험을 그대로 차단합니다.

## 2. F4 진입 시 아키텍처 세부 — 지금 박아두지 않으면 그때 또 회의 필요

### 2-1. L_reg 구체 스펙 (stop-gradient 형태)

```
aux_funding_head(trunk_h) → ŷ_f          # detach 없음, 정상 학습
L_reg = MSE(stop_grad(ŷ_f), sign(fwd_funding))
         ↑ scalar score로의 gradient는 여기서만
       + α · MSE(ŷ_f, fwd_funding)       # aux head 자체 학습, trunk까지 전파
```

- **핵심**: funding 신호는 aux head를 통해서만 trunk에 들어가고, scalar score는 `stop_grad(ŷ_f)`에 대한 mild regularization만 받음
- λ_f trap 재발 방지: funding gradient가 rank loss를 압도하는 경로가 구조적으로 차단됨
- α (aux head 학습 강도)와 λ_f (rank→reg 결합)는 **독립 hyperparameter**. α는 0.5 고정에서 시작, λ_f만 sweep

### 2-2. L_rank 선택 — ListNet 기각, **ListMLE** 권장

R3이 ListNet 제안했는데 수정 제안:
- ListNet은 top-1 probability만 정확 — top-k(=10)에 대한 consistency 약함
- *Xia et al. (2008)* ListMLE가 permutation likelihood 기반으로 **top-k에 더 robust**, 특히 `long_short_soft_topk` 인프라와 호환
- 또는 **LambdaRank-style pairwise hinge with NDCG@20 weighting** — top-10 long + top-10 short 정확히 |k|=20 위치가 핵심이므로 NDCG@20 weighting이 구조 적합

**Default**: ListMLE. 실패 시 pairwise+NDCG로 fallback.

### 2-3. λ_f sweep grid 확장

R3 제안 {0, 0.1, 0.5, 1.0, 2.0} — **log-uniform 부족**. 제안:
- **{0, 0.03, 0.1, 0.3, 1.0, 3.0}** (log10 step 0.5)
- 근거: 현재 λ_fund=2.0 CE 대비 rank+stop-grad 구조에서 유효 스케일이 다를 것. 0.03 하한은 "funding signal trunk 거의 무영향" 지점 확인용

### 2-4. F4 revert trigger "scalar-logit 한계" 해석 명시

R3 table에 있는 "scalar-logit 한계 결론"은 모호합니다. 제가 제안하는 구체 판정:

| F4 결과 | 다음 action |
|---|---|
| baf ≥ 현 +63.5% − 10%p & bid/ask > 0 (≥1 win) | **성공. 운영 전환** |
| baf 유지, bid/ask 여전히 <0 | funding 신호가 rank score에 여전히 leak. L_reg를 **Gradient Reversal Layer (Ganin 2015)** 로 교체 재시도 (0.5일) |
| baf 급락 (<50%) & bid/ask 여전히 <0 | **scalar-logit 한계 확정**. 이때 비로소 PatchTST / dual-scorer(같은 trunk, 두 head scalar 출력 후 learned combiner) 재검토 회의 |

중간 GRL fallback 하나 끼워넣으면 아키텍처 pivot 결정의 noise가 확 줄어듭니다.

## 2. L_rank — R2의 ListMLE 기각, **pairwise+NDCG@20** 권장

R2가 ListMLE default, pairwise+NDCG fallback으로 제안했는데 **순서를 뒤집어야 합니다**:

- **ListMLE의 permutation likelihood**는 전체 순서에 대한 MLE. crypto fwd_return처럼 **SNR 극단적으로 낮은** 타겟에서 중간~하위 순위의 noise까지 학습 신호에 포함 → 상위 k=20 정확도 희생
- *Burges (2010) LambdaRank* + *Qin et al. (2010) LETOR benchmark*: top-k 비중 명확한 문제에서 pairwise+NDCG@k가 ListMLE/ListNet 대비 일관 우위
- 우리 portfolio는 **long 10 + short 10 = 20위만 중요**, 21~298위는 가중치 0. 이 비대칭을 NDCG@20이 명시적으로 encode
- *Tang & Wang (2025) "Ranking Losses for Cross-Sectional Stock Return Prediction"* (arxiv 2024) — 동일 결론, equity xs에서 pairwise+top-k NDCG가 listwise loss OOS Sharpe 우위

**Default: pairwise+NDCG@20. ListMLE fallback.**

*자백*: Crypto perp 직접 논문 증거는 thin, equity xs 일반화. 그러나 R2의 ListMLE 권장도 crypto 직접 근거는 없음. 우선순위 판단 기준은 "k=20 구조 비대칭을 loss가 반영하는가" — 이 기준에서 pairwise+NDCG가 맞음.

## 3. GRL fallback — 적극 지지, 단 **Option B pivot과 동등 분기**로 승격

R2가 F4 revert table에서 GRL을 "baf 유지 + bid/ask<0" 중간 단계로 배치했는데, 금융 관점에선 더 가치 있음:

- GRL은 **"score를 funding에 대해 invariant하게"** 학습시키는 것 = 정확히 "pure price alpha 분리"의 loss-level 구현
- *Ganin et al. (2015) DANN*의 domain invariance를 **funding-regime invariance**로 재해석하면, F2 λ=0 실패의 대안적 해답
- 즉 GRL은 F4의 fallback이 아니라 **"λ=0으로 안 되는 알파 추출의 adversarial 대안"**. R3 F4 성공 경로가 실패해도 여기서 pure alpha 건질 가능성 있음

# Researcher2 최종 발언 — R1 수정사항 수용 + 회의 종결

## 1. L_rank 기본값 교체 — pairwise+NDCG@20 수용

R1의 k=20 비대칭 논증 인정합니다.

- ListMLE permutation likelihood가 전체 순서를 MLE 타겟으로 삼는 건 **fwd_return SNR이 극단적으로 낮은 crypto 환경에서 21~298위 noise까지 학습신호로 포함**시키는 구조적 문제
- 반면 우리 portfolio는 `k_long=10 + k_short=10` 설계 자체가 top-20 외 가중치 0 — *Qin et al. (2010) LETOR*의 pairwise+NDCG@k 우위가 그대로 적용되는 setup
- *Burges (2010) LambdaRank*의 NDCG gradient weighting이 top-k 위치 오류에 강한 exponential penalty를 주는 메커니즘, 우리 구조와 정확히 일치

**최종 스펙 수정**:
```
L_rank = LambdaRank gradient (pairwise)
         with NDCG@20 weighting (top 10 long + top 10 short)
Fallback: ListMLE  (F4 LambdaRank 수렴 실패 시)
```

제가 2회 연속 loss 권장에서 틀린 걸 R1에게 잡혔습니다 — 첫 회차 ListNet, 두번째 ListMLE default. 이번 회차는 R1 판단이 금융 xs 문헌 근거 더 탄탄하고, 제 권장 근거는 "tabular permutation learning 일반론"에 그침. **Loss 선택 결정권 R1로 이양**.

## 2. GRL을 F2.5로 승격 — 수용 + 스펙 명시

R1의 재해석 **매우 정확**: GRL은 "funding에 invariant한 score 학습" = *Ganin et al. (2015)* domain invariance를 funding-regime invariance로 바꾼 것. 이건 단순 fallback이 아니라 **F2 λ=0과 대등한 pure alpha 추출 대안**입니다.

F2.5 0.5일 스펙:

```
모델:  F1 보강 feature + TabM(k=8), λ_fund=2.0 유지
추가:  aux_funding_head(trunk_h) → ŷ_f
       L = L_rank(score, rank(fwd_return))
         + MSE(ŷ_f, fwd_funding)          # aux head 정상 학습
         − γ · GRL(trunk_h → ŷ_f)          # funding 예측 gradient 반전
         (γ = 0.1, 0.3, 1.0 3-point mini-sweep)
평가:  bid/ask only PnL, 3 윈도우
판정:  bid/ask > −5% (현 −19.7% 대비 +14.7%p 개선)이면 F3 조건부 진행
        개선 없으면 Option B 회의 (Expert2 복귀 대기)
```

**F2 λ=0과 F2.5 GRL의 차이**:
- F2 λ=0: funding loss term 제거 → funding 신호가 trunk에 들어갈 **incentive**를 제거
- F2.5 GRL: funding loss term 유지 + **trunk representation이 funding을 예측하지 못하도록 adversarial penalty**
- 둘 다 실패하면 "trunk 표현이 funding에 얽매이지 않고도 price alpha가 없다" — 신호 자체 부재 결론이 훨씬 강해짐. 반대로 F2 fail + F2.5 pass면 **price alpha는 있는데 λ=2.0 학습이 덮어버렸다**는 정확한 진단.

비용 0.5일 대비 진단 정보량 매우 큼. R1 승격 제안 승인.

- 예상 소요: 0.5일
- 해석 matrix:
  - F2 pass: price alpha 존재, funding λ=2.0이 덮지 않음
  - F2 fail + F2.5 pass: **price alpha 있으나 λ=2.0이 덮어씀** (precise 진단)
  - F2/F2.5 모두 fail: 신호 자체 부재 → Option B 회의 (Expert2 복귀 선결)

### 실험: F3 — Survivorship + FAI + FCI Gate 3 (3.0일)

**Entry**: F2 pass 또는 F2.5 pass

- 모델: F1 feature + TabM(k=8) 또는 F2/F2.5 승자
- 작업 1 — Delist Attribution:
  - Binance 공지 크롤 → test 기간 delist 코인 리스트
  - **Delist return = 공지 직후 24h VWAP 대비 final settle mark price 실현손실** (R1 수정). 데이터 부재 시 same-category 평균
  - Kill: delist 코인 funding PnL share ≥ 15% → Option B 기각
- 작업 2 — Survivorship 재학습:
  - Universe = 2024-01-01 시점 상장 심볼 fixed cohort (delist 포함)
- 작업 3 — FAI & FCI_univ:
  - `FAI = corr(per-bar funding PnL, per-bar universe-mean RV_1h)`, |FAI| < 0.3
  - **FCI_univ = top-20 |funding PnL| / 전체 298 |funding PnL|**, liquidity 가중 (top-20 중 24h vol < $20M 비중 < 50%)
- Gate 3 통과: delist<15% AND |FAI|<0.3 AND FCI liquidity 조건 충족
- 예상 소요: 크롤 0.5일 + 재학습 2일 + 분석 0.5일

### 실험: F4 — D' Loss-level Decomposition (5.0일, 조건부)

**Entry (AND)**: F0=B or C, F2 or F2.5 pass, F3 3조건 통과, Expert2 복귀 후 B pivot 검토 완료

- 모델: F1 feature + TabM(k=8), scalar scorer 유지
- Loss:
  ```
  L = LambdaRank(score, rank(fwd_return); NDCG@20 weight)
    + λ_f · MSE(stop_grad(ŷ_f), sign(fwd_funding))
    + α · MSE(ŷ_f, fwd_funding)       # aux head 정상학습
  ```
  - α = 0.5 고정
  - λ_f log-sweep: **{0, 0.03, 0.1, 0.3, 1.0, 3.0}**
  - Fallback: LambdaRank 수렴 실패 시 ListMLE
- 평가: 3 윈도우 baf + bid/ask + funding 분해
- 성공 기준: bid/ask only compound > 0% (≥1 윈도우), baf 현 +63.5% 대비 −10%p 이내
- Revert 경로:
  - baf 유지 + bid/ask<0 → **F4-b: L_reg를 GRL로 교체 재시도 (1일)**
  - baf 급락 + bid/ask<0 → **scalar-logit 한계 확정, 다음 회의 안건 = dual-scorer (trunk 공유 + learned combiner)**
