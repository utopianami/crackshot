### 핵심 주장: "수익률 분해"가 답이다

ReVol (CIKM 2025)에서 가장 중요한 통찰이 나왔습니다. 이 논문은 가격 시계열을 **return component, volatility component, scale component** 세 가지로 분리해서 독립적으로 normalize한 뒤 학습하면 IC +0.03 이상 개선된다는 걸 보여줍니다.

overnight +3%에 정확히 이 틀을 적용하면:

```
return component  → overnight_ret (방향과 크기)
volatility component → gk_vol (Garman-Klass, 경로의 진폭)
scale/conviction  → body_ratio (|C-O|/(H-L))
```

**이 세 개가 수학적으로 orthogonal한 정보를 담습니다.** 나스닥 +3% whipsaw 케이스에서:
- `overnight_ret` = +3% (동일)
- `gk_vol` = 높음 (high-low 범위가 넓었으니까)
- `body_ratio` = 낮음 (몸통 작고 수염 길다)

clean rally 케이스:
- `overnight_ret` = +3%
- `gk_vol` = 낮음
- `body_ratio` = 높음 (≈ 1에 수렴)

모델이 이 두 케이스를 구별할 수 있게 됩니다.

### 아키텍처 소비 방식 제안

이 6개 feature를 단순히 기존 153개 feature에 concatenate하는 건 **suboptimal**입니다.

MASTER (AAAI 2023)가 보여준 것처럼, **overnight feature의 중요도는 시장 레짐에 따라 동적으로 변합니다**. Fed 발표 다음날 개장엔 overnight feature 가중치가 높아야 하고, 저변동성 drift 장세엔 낮아야 합니다.

제안:
```
Option A (빠른 구현): 6개 feature를 기존 feature에 단순 append
  → cs_mlp/ft_transformer에 바로 적용 가능
  → Phase 1 baseline으로 적합

Option B (최적): overnight feature를 별도 embedding으로 처리 후
  gating mechanism으로 합산
  → MASTER 구조 참고, 약 +추가 IC 기대
  → Phase 2 이후 검토
```

**Phase 1에서 Option A로 빠르게 검증 → IC 개선 확인되면 Option B로 아키텍처 업그레이드** 순서를 권장합니다.

## 1. `nq_overnight_ret = ln(C/O)` — **정의 자체가 틀렸다**

이건 overnight 수익률이 아닙니다. **NQ=F 정규장 당일 수익률**입니다.

yfinance 일봉에서 `O`는 ET 09:30, `C`는 ET 16:00. 이 사이가 미국 정규장.

진짜 overnight 의미라면 두 가지 선택지:
```
선택 A: NQ D-1 Close 대비 KOSPI D 예측 기준
  nq_overnight_ret = ln(NQ_D-1_Close / NQ_D-2_Close)
  (전날 NQ 일봉 수익률 — 미국 정규장 전체)

선택 B: NQ 시가갭 활용
  nq_gap_to_prev = ln(NQ_D-1_Open / NQ_D-2_Close)
  (NQ의 overnight gap만 포착)
```

**현재 `ln(C/O)` 사용하면 KOSPI 09:00 기준 look-ahead 없음 — 하지만 feature 이름이 시사하는 정보와 다른 정보를 담고 있음.** 모델이 "NQ 장중 수익률"을 학습하게 되는데 이게 의도인지 재확인 필요.

**수정 제안**: `nq_ret = ln(C_{D-1} / C_{D-2})` (전날 NQ 수익률, 이게 가장 명확하고 look-ahead 안전)

---

## 2. `nq_gk_vol`과 `nq_body_ratio` — **0.8+ 공선성, 하나 제거 권고**

수식을 보면:

```
gk_vol ∝ 0.5 * ln(H/L)^2 - 0.386 * ln(C/O)^2
body_ratio = |C-O| / (H-L)
```

둘 다 H-L range와 C-O를 공유합니다. Clean rally일 때 gk_vol 낮고 body_ratio 높음, whipsaw일 때 gk_vol 높고 body_ratio 낮음 — **완전한 대칭 관계**. 피어슨 상관계수 0.7~0.85 범위에서 중복 정보.

**둘 중 하나만 남겨야 합니다.**

- `gk_vol`: 변동성 추정에 표준, 논문 수십 편 검증, tail risk 포착
- `body_ratio`: 직관적이지만 그 외 추가 정보 없음

**권고: `nq_body_ratio` 제거, `nq_gk_vol` 유지.**

---

## 3. `nq_sig_area` — **일봉 4점 path에서 signature는 사실상 상수**

sig111이 효과 있었던 건 **391개 분봉 OHLCV로 만든 연속 path**였습니다. 일봉 OHLCV에서 4~5점짜리 path에 signature를 적용하면:

```python
# OHLC → 4점 path (상승 캔들)
[(0, O), (0.33, H), (0.67, L), (1.0, C)]

# level-2 signature S^{1,2} = signed area
# = 사실상 (H-O)*(L-H) + (L-H)*(C-L) 의 선형 조합
# = gk_vol * direction의 변형과 수학적으로 동등
```

결국 `nq_sig_area ≈ f(nq_gk_vol, nq_overnight_ret)`의 비선형 조합. **독립 정보 추가 없음, 계산 비용만 증가.**

**권고: `nq_sig_area` 제거.**

## 4. 모든 overnight feature 공통 문제 — **cross-sectional rank 불가**

이 5~6개 feature는 **200종목 모두 동일한 값**입니다. NQ overnight이 +3%면 삼성전자도 +3%, SK하이닉스도 +3%.

일반 feature는 cross-sectional rank 변환이 non-stationarity 대응에 효과적이지만, **여기선 불가능**합니다.

**실질 문제**: 고변동성 구간(2025년 10월 FOMC 등)에서 NQ -5%가 평시 -5%와 다른 의미를 가지는데 z-score(60일)로는 불충분. **rolling 60일이 아닌 rolling 120일 + clipping이 더 robust**합니다.

더 중요한 질문: **이 feature가 alpha factor인가, beta factor인가?**

alpha label을 쓰면 `mean(c2c_120)`이 빠지니 시장 beta는 제거됩니다. 하지만 feature로도 market-level overnight 정보가 들어오면, 모델이 **"NQ가 오르면 어떤 종목을 살 것인가" (alpha)** 대신 **"NQ가 오르면 살아라" (beta)** 를 학습할 위험이 있습니다.

**수정 제안**: overnight feature를 **종목 × 섹터 민감도**로 변환하는 것이 장기적으로 더 alpha-pure합니다.
```
nq_sector_beta_adjusted = nq_ret * (1 - stock_nq_beta_30d)
```
단기적으로 어려우면 raw를 쓰되 이 위험을 인지해야 합니다.

## 핵심 비판 1: 09:00~10:30 IC가 낮은 이유를 잘못 진단했습니다

세션 컨텍스트에 나온 진단: *"overnight 글로벌 자산 움직임을 모델이 모르기 때문"*

이 진단이 맞다면 **overnight feature 추가 후 09:00~10:30 IC가 오르고 10:30~13:30은 그대로여야** 합니다. 하지만 실제로 어떻게 될지 생각해보면:

```
c2c_120 label 정의 재확인:
  - 09:00 진입 → 11:30까지 수익률  (아침 거래)
  - 11:00 진입 → 13:30까지 수익률  (오전 중반)
  - 13:30 진입 → 15:30+α까지 수익률 (오후)
```

09:00~10:30 IC가 낮은 건 overnight 정보 부재 때문만이 아닙니다. **오전 c2c_120 label 자체가 노이즈가 더 많습니다.** 이유:

1. 개장 직후는 bid-ask spread 최대, 유동성 최소 → 가격 발견이 덜 됨
2. 아침 거래의 c2c_120은 "개장 충격 흡수 과정"을 포함 → 평균 회귀 component가 섞임
3. 오전 label은 오후 label보다 SNR이 구조적으로 낮음

**overnight feature를 추가해도 이 구조적 노이즈는 제거 안 됩니다.** IC 개선 폭이 기대보다 훨씬 작을 가능성이 높습니다.

## 핵심 비판 2: Market-level feature를 alpha model에 넣는 건 목적 함수 오염입니다

Expert1이 건드렸지만 충분히 강하게 말하지 않았습니다. 저는 더 직접적으로 말하겠습니다.

**현재 loss function이 뭔지 다시 봅시다:**

```python
# alpha label = return - beta (시장 평균 제거)
alpha_label = c2c_120 - mean(c2c_120_all_stocks)
```

alpha label로 학습한다는 건 **"시장이 어디로 가든 이 종목이 시장보다 나을 것인가"** 를 예측한다는 뜻입니다. 그런데 overnight feature를 넣으면:

```
모델이 실제로 학습하는 것:
  "NQ가 +3% 올랐으면 → 시장이 갭업할 거고 → 어떤 종목 살 것인가"
      (beta component)         (alpha component)
           ↑
    이미 alpha label에서 제거하려 한 것
```

alpha label로 타겟을 바꿨다면, **feature에서도 beta를 제거해야 일관성이 있습니다.** NQ overnight return을 raw로 넣으면 alpha label의 논리가 흔들립니다.

만약 overnight feature가 정말로 alpha-informative하려면 질문 자체가 달라야 합니다:

```
"NQ +3% clean rally 상황에서 어떤 종목이 시장 대비 추가로 오를 것인가?"
 = nq_ret × sector_sensitivity_diff (섹터별 민감도 차이)
 = nq_gk_vol × stock_beta_spread (베타 분산이 큰 종목)
```

단순한 수준 변수(NQ level, VIX level)가 아니라 **종목 간 분산을 유발하는 인터랙션 feature**만 alpha-informative합니다.

## 핵심 비판 3: 틀린 질문에 리소스를 투입하기 전에 할 실험이 있습니다

overnight feature 구현에 앞서 **2시간이면 되는 ablation이 있습니다:**

```python
# 실험 A: 09:00~10:30 진입 거래만 제외하고 trading sim 재실행
# 질문: 아침 거래를 제거하면 전체 alpha가 오르는가?

# 실험 B: 09:00~10:30 진입의 c2c_120 label 분포 vs 10:30 이후 분포
# 질문: 아침 label의 SNR이 구조적으로 낮은가?
```

만약 **실험 A에서 아침 거래 제거 시 alpha가 오른다면**, overnight feature가 아니라 **아침 거래를 trading sim에서 skip하는 게 더 빠른 해법**입니다. overnight feature 전체 구현 공수 없이 같은 효과를 얻을 수 있습니다.

만약 **실험 B에서 아침 label SNR이 낮다면**, overnight feature를 추가해도 IC는 크게 안 오릅니다. 모델이 학습할 수 있는 신호 자체가 적기 때문입니다.

## 제가 동의하는 것

그럼에도 **overnight feature가 의미 있는 케이스가 하나 있습니다:**

섹터별로 NQ overnight에 대한 sensitivity가 다릅니다. 반도체는 NQ와 high beta, 음식료는 low beta. overnight feature가 이 이질성을 포착하면 cross-sectional alpha-informative feature가 됩니다.

```
권고: nq_ret 단독이 아니라
  → stock_sector × nq_ret 인터랙션 feature
  → 또는 섹터 dummy × nq_gk_vol
```

이렇게 하면 beta 오염 없이 cross-sectional 정보를 활용 가능합니다. 데이터에 섹터 정보가 있다면 이게 가장 alpha-pure한 overnight feature입니다.

### 1. Expert1 교정 3개 전량 수용

솔직히 말하면 제가 `ln(C/O)` 정의 실수를 했습니다. KOSPI 09:00 예측 맥락에서 "overnight"은 당연히 `ln(C_{D-1}/C_{D-2})`입니다.

### 2. Expert2 비판에 대한 아키텍처 관점

Expert2의 **진단 의심**은 타당합니다. 하지만 Researcher1이 지적한 것처럼 beta 오염 논리에는 오류가 있습니다. 제가 아키텍처 관점에서 왜 그런지 보여드리겠습니다.

alpha label이 타겟에서 시장 beta를 제거했다면, 모델은 residual을 예측합니다:

```
alpha_i = c2c_120_i - mean(c2c_120)
        = stock_specific_component + sector_component
```

여기에 `nq_ret`을 feature로 넣으면 모델이 배우는 건:

```
f(stock_features, nq_ret) → alpha_i
```

`nq_ret`의 그래디언트는 **종목 간 alpha 분산을 설명하는 방향**으로만 흐릅니다. "시장 전체가 올라서 살아라"는 신호는 alpha label에서 이미 상수로 빠졌으니 모델이 배울 수 없습니다.

단, Expert2의 핵심 우려가 완전히 사라진 건 아닙니다. **`nq_ret` feature의 분산 중 진짜 cross-sectional alpha를 설명하는 분산이 얼마나 되는가**가 문제입니다. 이걸 해결하는 아키텍처 해법이 있습니다.

### 3. 새로운 제안: Context-Gated Feature Modulation

Expert2가 말한 "interaction feature"를 손으로 만드는 대신, 아키텍처로 자동 학습하는 방법입니다.

**MASTER (AAAI 2023)** 구조에서 아이디어를 빌립니다. 하지만 MASTER의 market token 개념을 더 경량화한 버전:

```python
# Option A (빠른 구현): Feature-wise gating
# nq_ret, nq_gk_vol을 stock features에 concat하지 말고
# gating signal로 사용

class OvernightGatedMLP(nn.Module):
    def __init__(self):
        self.stock_encoder = MLP(105 → 128)  # 기존 feature
        self.market_gate = MLP(4 → 128)      # overnight 4개 feature
        self.output = Linear(128 → 1)
    
    def forward(self, x_stock, x_overnight):
        h = self.stock_encoder(x_stock)
        gate = sigmoid(self.market_gate(x_overnight))  # 0~1
        return self.output(h * gate)
```

이렇게 하면 `nq_gk_vol`이 높은 날(whipsaw)에는 stock feature의 특정 dimension들이 억제됩니다. 모델이 **"시장 환경에 따라 어떤 stock feature를 볼 것인가"** 를 학습하게 됩니다.

이건 Expert2가 원하는 `nq_ret × sector_sensitivity` interaction을 수동 설계 없이 자동으로 학습하는 것과 동등합니다.

### 실험 3 (Gated MLP) 설계 수정 제안

Researcher3가 제시한 구조:

```python
gate = sigmoid(market_gate(x_overnight))
output(stock_h * gate)
```

이 구조는 **gate가 stock feature를 억제하는 방향으로만 작동**합니다. whipsaw 상황(nq_gk_vol 높음)에서 stock signal을 끄는 건 맞지만, clean rally 상황에서 **특정 feature를 부스트**하는 건 불가능합니다.

수정 제안 (잔차 게이팅):

```python
gate = tanh(market_gate(x_overnight))  # -1 ~ +1
output(stock_h + stock_h * gate)       # 억제 + 부스트 모두 가능
# 또는
output(stock_h * (1 + gate))           # 동일 효과, 더 직관적
```

`tanh`로 -1~+1 범위 사용하면 clean rally에서 관련 feature dimension을 +100%까지 부스트하고, whipsaw에서 최대 -100% 억제 가능합니다. 이게 MASTER의 gating 방식과 더 가깝습니다.

**구현 변경 cost**: `sigmoid` → `tanh` + `*` → `* (1 + gate)` 한 줄 수정. Phase 0-1 결과 보고 실험 3 진행할 때 반영하면 됩니다.

## 1. Rolling z-score에서 look-ahead bias — 사소해 보이지만 치명적

`nq_ret`과 `nq_gk_vol`에 rolling 120일 z-score를 적용할 때:

```python
# 잘못된 구현 (전체 구간에 rolling 적용)
df['nq_ret_z'] = (df['nq_ret'] - df['nq_ret'].rolling(120).mean()) \
                  / df['nq_ret'].rolling(120).std()
```

이렇게 하면 **학습셋 전체로 rolling을 돌리면 z-score 계산 자체는 OK**입니다. 하지만 **`min_periods` 설정 없으면** 초반 120일 미만 구간에서 전체 평균으로 채워질 수 있습니다.

실제 문제는 다른 곳에 있습니다: **train/val/test 경계에서 val·test 데이터가 mean/std 계산에 포함되면 안 됩니다.**

```python
# 안전한 구현
df['nq_ret_z'] = df['nq_ret'].transform(
    lambda x: (x - x.expanding(min_periods=30).mean()) \
              / x.expanding(min_periods=30).std()
)
# 또는 학습/검증/테스트 분리 후 각각 적용
```

**expanding mean/std (과거 누적)** 쓰면 rolling window보다 안전하고 초반 데이터 손실도 없습니다.


```
  1. 전체 IC ≥ 0.078 (현재 0.0755 유지)
  2. 09:00~10:30 IC ≥ 0.060 (현재 0.0497 대비 +20%)
  3. 전체 IC가 다른 시간대에서 -5% 이상 하락하지 않음 (trade-off 없음 확인)
```

feature 하나 추가로 전체 IC가 흔들리면 그게 더 큰 문제입니다.

### 실질적 alpha 임팩트 계산

아무도 안 했는데, 09:00~10:30 개선으로 얻을 수 있는 **최대 alpha 상한**을 먼저 계산해봐야 합니다:

```

  quality_bp 개선: 22.6 → 35.1 (+12.5bp)
  거래 94건 × 12.5bp = +1,175bp ≈ +11.75% alpha 개선

현재 total L CumAlpha = +15.2M 기준으로 +11.75%면
  = 약 +1.8M 추가 alpha
```

overnight feature를 완벽하게 구현해도 **이론적 상한이 +1.8M** 입니다. 이건 현재 best인 +15.2M의 12% 수준. overnight feature 전체 구현 공수 대비 ROI가 충분한지 팀이 판단해야 합니다.

반면 **trading sim threshold를 quality_bp 기준 25→30으로 올리면** — 아침 94건 중 low-quality 거래만 제거 — 같은 효과를 30분 안에 확인할 수 있습니다.

## KOSPI 09:00~10:30 구간의 구조적 특수성

**KOSPI는 08:00~09:00 동시호가(call auction)로 시가를 결정합니다.** 09:00 시가는 이미 overnight 정보가 반영된 가격입니다 — 시장 참여자들이 결정한 것이니까요.

즉:

```
09:00 시가 = 전날 15:30 종가 + overnight 정보 반영분
```

이 feature가 예측하려는 것은 **"09:00 이후 방향"** 인데, 09:00 시가 자체가 이미 overnight 정보를 반영했다면, `overnight_gap`이 추가로 설명할 수 있는 분산이 **훨씬 작아집니다.**
