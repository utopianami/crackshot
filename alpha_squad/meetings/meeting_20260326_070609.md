## 근본 원인 1: 예측 불가능한 구간을 예측하려 한다

13:30 이후의 c2c_120은 사실상 **익일 개장 방향 예측**입니다. 모델이 학습하는 정보(당일 분봉 OHLCV)로는 overnight 글로벌 이벤트를 알 수 없습니다.

KOSPI200 선물 연구(2013)에서 실측된 결과: **일일 가격 발견의 대부분이 전일 종가→당일 시가 전환 구간에서 발생**하며, 미국 증시가 지배적 driver입니다. 이 정보 없이 13:30 이후 예측을 학습에 포함하면 모델은 **irreducible noise를 학습**합니다. IC가 낮은 게 당연합니다.

**즉각 실행 가능한 개입**: `13:30 이후 행 제외 + alpha label` 조합. 새 데이터 필요 없음, 기존 파이프라인 수정만으로 가능. 기대 효과: 레이블 오염 제거로 실질 IC 상승.

---

## 근본 원인 2: 분포 shift를 고정 split로 다룬다

현재 train(02-19~12-01) → test(12-01~02-09) split은 **시장 레짐이 동일하다는 암묵적 가정**을 포함합니다. 3개월 test 기간에 레짐이 한 번이라도 바뀌면 모든 모델이 동시에 무너집니다.

DoubleAdapt (KDD 2023, 43 citations)는 이 문제를 메타러닝으로 해결합니다: data adapter(분포 정규화) + model adapter(점진적 파라미터 업데이트)를 결합해 concept drift 하에서도 안정적 IC를 유지합니다. 우리 FT-Transformer/TabM 위에 wrapper 형태로 적용 가능합니다.

더 단순한 대안: **ReVol (CIKM 2025)** — return/volatility/scale을 분리 정규화. IC +0.03 이상 보고. 우리 current IC 0.0755에서 +0.03이면 **상대적으로 40% 향상**입니다.

## 근본 원인 3: 시간(Time-of-day)을 feature로 취급하지 않는다

한국 인트라데이 예측 실증 연구(2024): **"trading time"이 Bollinger Band 다음으로 2번째로 중요한 예측 변수**. 이게 무작위 포레스트 결과이지만, 시그널 자체는 모델 클래스와 무관하게 존재한다는 뜻입니다.

GLAFF (NeurIPS 2024, 32 citations)는 timestamp를 **global dependency의 primary source**로 취급하는 fusion 구조입니다. 09:00 캔들과 14:00 캔들이 가진 의미적 차이를 explicit하게 모델링합니다. 기존 FT-Transformer에 position encoding만 수정해도 이 신호의 일부를 포착할 수 있습니다.

## 제안 1: 13:30 cutoff + alpha label — **강력 지지, 단 한 가지 경고**

방향은 맞습니다. 그러나 **alpha label 자체의 leakage 구조를 재확인해야 합니다.**

현재 alpha label 정의: `c2c_120 - mean(c2c_120 of all valid stocks at same timestamp)`

문제: **mean() 계산에 미래 종목이 포함될 수 있습니다.** `valid stocks at same timestamp`를 정의할 때, inference 시점에 "어떤 종목이 valid한지"를 어떻게 결정합니까? 학습 후에 delisted된 종목이 train의 beta 계산에서 빠지면 → **survivorship bias가 label에 내재됩니다.**

체크포인트:
- alpha label의 beta는 **고정 종목 리스트** 기준인가, 아니면 **그날그날 거래된 종목** 기준인가?
- 13:30 cutoff 이후 제외 시, 남은 270분짜리 데이터에서 per-row beta 재계산이 필요함

---

## 제안 2: Time-of-day encoding — **지지하되, 현재 피처와 중복 확인 필수**

현재 105feat에 이미 `time_in_day (sin/cos/raw)` (인덱스 0-5)가 있습니다.

Researcher2가 말하는 "explicit time-of-day modeling"이 **이미 있는 feature와 뭐가 다른가**를 먼저 답해야 합니다. 만약 FT-Transformer의 position encoding 수정이라면 — 그건 피처 추가가 아니라 **모델이 기존 피처를 사용하는 방식**의 변경입니다. 이 경우 새 데이터 없이 구현 가능하고 leakage 없음.

단, `time_in_day_raw`가 이미 들어있는데 IC 기여가 낮다면, **position encoding 수정보다 "시간대별 별도 normalization 통계 적용"이 더 직접적입니다.** 지금 `quote_asset_vol_normalized`의 normalization baseline이 09:00~15:30 전체 평균인데, 개장 초반과 장중 유동성 패턴이 달라서 이 값의 의미가 시간대마다 다릅니다.

---

## 제안 3: ReVol 정규화 wrapper — **구체적 스펙 확인 후 지지**

ReVol이 "return/volatility/scale 분리"라고 했는데, 우리 데이터에서 이게 어떻게 매핑되는지 확인해야 합니다.

현재 105feat의 normalized 피처 (인덱스 68-107)는 **윈도우 기반 rolling z-score**입니다. ReVol이 이것과 다른 점:
- ReVol의 volatility normalization이 **lookback window를 얼마나 쓰는가?** 너무 짧으면 intraday noise, 너무 길면 concept drift를 반영 못함
- **cross-sectional vs time-series normalization**: ReVol이 종목별로 독립 정규화하는지, 타임스탬프 기준 cross-sectional인지가 핵심

이 구분 없이 "IC +0.03"을 그대로 믿으면 안 됩니다. 해당 논문의 실험이 우리처럼 **intraday (분봉)** 데이터인지, 아니면 **일봉** 데이터인지 확인하세요. 일봉 대상 결과를 분봉에 그대로 적용하면 수치가 맞지 않습니다.

## 제안 5: S&P500/USD-KRW overnight feature — **지지, 단 leakage 설계 주의**

이건 제가 이전 회의에서도 주장한 내용입니다. 다만 구현 시 **look-ahead bias 포인트가 명확합니다:**

- S&P500 종가: 한국 시각 **다음날 06:00 확정** → KOSPI 09:00 예측에 사용 가능 ✓
- USD/KRW overnight: **08:30~09:00 서울 FX 선물로 근사** → 사용 가능 ✓
- 코스피200 선물 야간 시간외: **09:00 개장 전 08:45 호가** → 사용 가능 ✓

그런데 **이 feature들은 개장 초반(09:00~10:30)에만 유효합니다.** 13:00의 분봉에 S&P500 전일 종가를 feature로 넣는 건 staleness 문제가 있습니다 — 6시간 전 정보를 여전히 primary signal로 다루는 셈.

**올바른 설계**: overnight feature는 하루 중 `time_in_day`와 interaction term으로만 유효. 즉, `09:00~10:30 구간 전용 모델`을 만들 때 핵심 피처가 됩니다. 전 구간 단일 모델에 그냥 concat하면 오히려 noise가 됩니다.

## 1. CE loss는 알파를 최적화하지 않는다 — 이건 근본 설계 오류입니다

현재 loss: `CE(logits, c2c_120 > 0 ? 1 : 0)`

CE가 최소화하는 것: **방향 예측 정확도(WR)**.
우리가 원하는 것: **CumAlpha**.

이 둘은 같지 않습니다. WR 62.8%인 AG CLS baseline이 WR 54.2%인 CS-MLP보다 CumAlpha가 높습니다(+547% vs +406%). 당연합니다. 그런데 역으로, **WR을 더 올린다고 CumAlpha가 반드시 오르지 않습니다.**

실증적 증거: 우리 실험 테이블에서 `tabm_sota_k200`은 WR 51.3%에 CumAlpha -129%입니다. uniform prediction 수렴이니까 극단 케이스지만, 핵심은: **CE로 학습한 모델이 "쉬운 방향 예측"에 집중하고 "어렵지만 alpha가 큰 종목"을 포기한다는 것**입니다.

alpha가 큰 종목의 특징:
- cross-sectional 상위/하위 극단에 있는 종목 (상대적으로 강한 상승/하락)
- 이런 종목일수록 c2c_120 분포가 평균에서 멀다 → CE 관점에선 "어려운 샘플"
- CE는 이 샘플에 패널티를 균등 부여 → 모델이 이걸 회피하도록 학습

**Focal loss가 이걸 부분 해결하지만 근본은 아닙니다.** 진짜 해결책은 **알파에 비례한 loss weighting** — 즉, cross-sectional rank 기반 loss입니다.

현재 ListNet이 있는데, 우리가 이미 검증한 결론: λ=0.3이 최적이고 λ=0.5는 WR 폭락. 왜 폭락했는지 아무도 분석하지 않았습니다. 저는 그 이유가 "**837종목 전체를 하나의 ranking universe로 묶었기 때문**"이라고 봅니다. 200종목 K200에서 ListNet을 쓰면 universe 크기가 줄어서 이 문제가 완화될 수 있습니다.

## 2. Binary classification 자체가 정보를 파괴하고 있습니다

`c2c_120 > 0 → 1, ≤ 0 → 0`

이 threshold는 **경제적 의미가 없습니다.** 왜 0이 경계인가요?

- c2c_120 = +0.01%인 종목과 = +2.0%인 종목을 같은 class 1로 묶습니다
- 모델이 "방향만 맞추면 된다"고 학습합니다
- 실제 trading에서 +0.01% 예측 신호로 수수료 0.1%를 커버할 수 없습니다

**이건 잘못된 질문입니다.** "c2c_120이 0보다 크냐"가 아니라 "이 종목이 오늘 cross-section에서 상위 몇 %에 드느냐"가 맞는 질문입니다.

alpha label이 +42% IC 향상을 보인 이유가 바로 이겁니다 — alpha label은 암묵적으로 **cross-sectional relative position을 target으로 만든 것**입니다. `c2c_120 - market_mean > 0`은 "시장 평균보다 잘한다"는 의미고, 이게 실제 알파와 align됩니다.

그렇다면 다음 질문: **alpha label도 binary로 자르는 게 맞나?** alpha label의 연속값을 그대로 쓰는 regression이 오히려 나을 수 있습니다. 단, MSE가 아닌 IC-based loss나 rank correlation loss로.

## Expert1: Alpha label survivorship bias — **인정, 선행 확인 필요**

`valid` 정의가 "당일 거래된 종목"이면 OK. "전체 학습 기간 내내 존재한 종목"이면 leakage입니다. **이건 코드 한 줄 확인으로 끝납니다.** 13:30 cutoff 실험을 blocking할 사유는 아닙니다 — 확인하면서 병렬로 진행.

## Expert1: Time-of-day 이미 105feat에 있음 — **부분 동의, 그러나 내가 말한 건 다릅니다**

`time_in_day sin/cos` (index 0-5)가 있는 건 압니다. 제가 제안한 건 **feature로 넣는 것**이 아니라 **아키텍처 레벨의 temporal gating**입니다.

GLAFF의 핵심은 timestamp feature를 input concat하는 게 아니라:
- **Global branch**: 전체 시계열에서 temporal pattern 추출
- **Local branch**: 로컬 candle 패턴
- **Adaptive fusion gate**: 두 branch를 timestamp에 조건부로 가중합

`time_in_day_raw`를 feature로 넣어도 FT-Transformer의 attention이 "09:00 캔들은 overnight sensitive, 13:00 캔들은 momentum-driven"임을 **암묵적으로 학습**해야 합니다. Temporal gate를 explicit하게 주면 이 학습이 훨씬 빠르고 안정적입니다.

단, **Researcher1 의견이 맞습니다** — 13:30 cutoff + alpha label이 먼저입니다. GLAFF-style temporal gating은 그 이후 아키텍처 개선으로 분류합니다.

## Expert1/Researcher1: ReVol 일봉 vs 분봉 — **인정, 보류**

ReVol이 일봉 기준이라면 분봉에 직접 적용은 무의미합니다. **실험 큐에서 제거**합니다. 대신 ReVol의 아이디어(return/vol 분리 정규화)를 우리 feature pipeline에 맞게 재설계하는 건 별도 논의로.

## Expert2: CE loss가 WR을 최적화한다 — **동의하되, Researcher1 해석이 더 정확**

Expert2의 진단은 맞습니다. 그러나 Researcher1이 보여준 데이터:

> CS-MLP v2: WR 56.3% → CumAlpha +680%  
> AG baseline: WR 62.8% → CumAlpha +547%

이건 CE loss 자체의 문제가 아니라 **cross-sectional 표현**의 문제입니다. CS-MLP가 입력에서 이미 cross-sectional normalization을 하기 때문에 CE loss를 써도 alpha-aligned 신호를 포착합니다.

**아키텍처 관점 추가**: FT-Transformer에 cross-sectional normalization을 **입력 전처리**로 추가하면 CE loss를 바꾸지 않아도 같은 효과를 얻을 수 있습니다. 구현 비용 낮음.

## Expert2: Multi-horizon auxiliary — **강력 지지, 구조 제안 추가**

c2c_60 + vol auxiliary는 맞는 방향입니다. 아키텍처 관점에서 구조를 제안합니다:

```
FT-Transformer shared backbone
       ↓
  [shared repr]
   ↙    ↓    ↘
c2c_120  c2c_60  vol
(main)  (aux)  (aux)
  CE      CE    MSE
```

중요한 것: **auxiliary head의 gradient를 shared backbone에 흘려보내는 비율**. c2c_60 auxiliary가 dominant해지면 오히려 c2c_120 성능이 떨어집니다. λ_aux = 0.1~0.2로 시작.

## 핵심 지적: "Alpha Label + CE"는 자기모순입니다

실험 1 스펙을 다시 보세요:
```
Label: alpha label (c2c_120 - cross-sectional mean)
Loss: CE (alpha label binary)  ← 여기
```

Alpha label의 경제적 의미: **종목이 시장 대비 얼마나 초과 수익을 내는가** — 연속값.

이걸 `alpha > 0 → 1, alpha ≤ 0 → 0`으로 이진화하면 무슨 일이 생기냐면:

| alpha = +0.01% | alpha = +3.0% | → 같은 class 1 |
|----------------|---------------|----------------|
| alpha = -0.01% | alpha = -3.0% | → 같은 class 0 |

**Alpha label의 핵심인 "magnitude 정보"를 버립니다.** 이건 alpha label을 도입한 이유를 스스로 파괴하는 겁니다.

지난 실험에서 alpha label이 IC +42% 향상을 준 이유가 무엇인가요? 타겟이 **cross-sectional relative position을 연속적으로 표현**하기 때문입니다. 그걸 다시 binary로 자르면 c2c_120 binary와 구조적으로 거의 같아집니다 — threshold만 0에서 market_mean으로 바뀐 것뿐.

---

## 제안: Alpha Label → Rank Correlation Loss (IC-based)

```python
# 현재 (자기모순)
alpha_label_binary = (c2c_120 - mean_c2c_120) > 0  # 연속값을 버림
loss = CE(logits, alpha_label_binary)

# 제안 (연속값 유지)
alpha_label_continuous = c2c_120 - mean_c2c_120  # 연속값 그대로
loss = -spearman_corr(predictions, alpha_label_continuous)  # IC 직접 최대화
```

Spearman rank correlation loss는 이미 differentiable approximation이 여러 구현체로 존재합니다. 우리 코드베이스에 `listnet.py`가 있는데 여기에 **soft rank** 기반 IC loss를 추가하는 건 50줄 이내입니다.

이게 맞는 이유:
- 투자 결정은 "방향이 맞냐"가 아니라 "이 종목이 오늘 상위 몇 %에 드냐"
- IC가 직접 최적화 목표 → val IC와 학습 목표가 정렬됨
- Binary threshold 없음 → 정보 파괴 없음

## Researcher1의 반론에 대한 재반박

Researcher1이 "CS-MLP v2: WR 56%→CumAlpha +680%이므로 CE loss가 문제가 아니라 cross-sectional input representation이 문제"라고 했습니다.

**틀린 해석입니다.** CS-MLP v2가 잘 되는 이유는:
1. Cross-sectional input normalization ✓ (Researcher1 주장)
2. **CE loss지만 입력이 already cross-sectionally normalized → 모델이 사실상 ranking을 학습** ✓ (이게 핵심)

즉, CS-MLP v2는 input normalization으로 "ranking 문제처럼 만든" 것이고 CE가 그 위에서 작동합니다. **이건 우회(workaround)지 해결책이 아닙니다.** Alpha label continuous + rank loss는 이 우회 없이 직접 해결합니다.

PM이 "CE loss 교체보다 cross-sectional input normalization이 우선"이라고 했는데, **둘은 배타적이지 않습니다.** Cross-sectional normalization + rank loss가 CE + cross-sectional normalization보다 이론적으로 우위입니다. 구현 비용도 낮습니다.

## Expert2의 "Alpha Label + CE = 자기모순" — 이론은 맞지만 실험 근거와 충돌합니다

우리 ListNet 실험 결론:
- λ=0.3 최적 (rank loss 가중치 낮음)
- λ=0.5 → WR 폭락
- τ=0.05 (sharp ranking) → λ=0.5와 유사하게 불안정

이게 rank-based loss의 실전 행동 패턴입니다. "이론적으로 IC 직접 최적화"가 실제로 잘 안 되는 데는 이유가 있습니다:

1. **배치 내 rank 계산의 분산 문제**: 타임스탬프별 유효 종목 수가 일정하지 않으면 rank gradient의 분산이 커집니다. K200 200종목이 837종목보다 universe가 작아서 더 불안정할 수 있습니다.
2. **soft rank approximation의 온도 민감성**: τ를 잘못 설정하면 ListNet의 τ=0.05 케이스처럼 폭락합니다.

Expert2는 이 위험을 과소평가하고 있습니다.

## "Threshold만 바꾼 것" — 이 주장은 경제적으로 틀립니다

> "c2c_120 binary와 구조적으로 거의 같아집니다 — threshold만 0에서 market_mean으로 바뀐 것뿐"

아닙니다. **이 threshold 변경이 핵심입니다.**

`c2c_120 > 0`을 예측하는 모델은 "오늘 이 종목이 오를까"를 묻습니다.  
`alpha > 0`을 예측하는 모델은 "오늘 이 종목이 시장보다 나을까"를 묻습니다.

코스피가 -1% 하락하는 날, c2c_120 = -0.5% 종목은:
- c2c_120 binary 관점: class 0 (하락) → Long 후보 아님

우리 trading sim이 CumAlpha(beta 제거)를 메트릭으로 쓰는 이유가 이겁니다. Alpha label binary는 **목적함수와 직접 align**됩니다. "magnitude 파괴"보다 이 align이 더 중요합니다.

Alpha label이 IC +42% 향상을 준 이유 중 상당 부분이 바로 이 threshold 변경입니다. Continuous로 바꿔서 추가로 얻을 수 있는 gain이 얼마인지 모르지만, risk는 확실합니다.

## Expert1의 Val Set Leakage — 이건 중요도를 높여야 합니다

Expert1이 마지막에 지적한 것인데, 실험 0a 체크리스트에 **명시적으로 추가되어야 합니다.**

세 가지 레벨에서 leakage가 가능합니다:

| 레벨 | 위험 패턴 | 증상 |
|------|----------|------|
| **Scaler fit** | `scaler.fit(train+val)` | Val IC가 test IC보다 비정상적으로 높음 |
| **Alpha label mean** | `df.groupby('timestamp').transform('mean')` on full dataset | Train alpha label에 test 수익률 정보 누출 |
| **Cross-sectional normalization** | Train+val+test 전체에서 z-score 정규화 | 미묘하게 val/test 분포 왜곡 |

특히 `scripts/create_enhanced_npy.py`가 NPY 생성 시 split 전에 처리하는 구조라면 이 세 가지가 **동시에 오염**될 수 있습니다. 이건 단순한 "코드 한 줄 확인"이 아니라 데이터 파이프라인 전체를 확인해야 합니다.

확인 방법:
```python
# alpha label 생성 전 split이 이루어지는지
# 또는 split boundary를 기준으로 독립 계산되는지
assert alpha_label_train = compute_alpha(df[df.timestamp < split_date])
assert alpha_label_val   = compute_alpha(df[(df.timestamp >= val_start) & ...])
# cross contamination 없어야 함
```

**현실적 위험**: 실험 1a가 IC > 0.085를 달성해도, 그 IC가 2025년 12월~2026년 2월 test period에서 stable할지 모릅니다. 코스피200의 regime은 계속 바뀝니다. 지금 실험이 특정 regime에 과적합된 개선일 가능성을 **배제할 수 없습니다.**
