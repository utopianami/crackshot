## Researcher2의 아키텍처 제안을 듣기 전에, 현재 피처/모델 현황의 근본 문제부터 짚겠습니다.

---

### 1. Ens4로 +33.3M 달성했지만, 이건 "수의 폭력"이지 "질의 승리"가 아닙니다

4개 데이터셋(105+enh+d7+a101)을 앙상블해서 **겨우 +0.1M 차이**로 AG baseline을 넘었습니다. 이건 피처 품질이 좋아서가 아니라, **서로 다른 noise를 평균내서 분산을 줄인 것**에 불과합니다. 단일 모델로는 TabM 105feat이 +20.2M — baseline 대비 60% 수준입니다.

**결론: 새 아키텍처를 논의하기 전에, 피처 자체의 정보량이 충분한지 먼저 의심해야 합니다.**

---

### 2. 현재 피처의 구조적 결함

**105feat의 50개 가격 차이 feature는 공선성이 심각합니다.** `close-open` 윈도우 1분과 5분은 상관계수 0.8 이상일 겁니다. 153feat 분석에서 "153→~50 effective features"라는 결과가 이미 나왔고, 105feat도 동일한 문제를 가집니다.

더 심각한 것은 **normalization 방식**입니다:
- 현재 가격 차이 feature는 **종목 내 rolling normalization**을 사용하는데, 이는 **종목 간 스케일 차이를 제거하지 못합니다**
- cross-sectional z-score를 쓰면? CS-MLP 실험에서 이미 확인했듯이 **대형/소형 구분을 인코딩해서 beta만 학습**하는 문제가 생깁니다
- 즉, **어떤 normalization을 써도 현재 피처 구조에서는 alpha signal이 아니라 size factor를 학습할 위험**이 있습니다

---

### 3. 아키텍처 논의에서 반드시 짚어야 할 피처 관점

Researcher2가 어떤 모델을 제안하든, 다음 질문에 답해야 합니다:

1. **입력이 현재 105feat인가, raw candle인가?**
   - 105feat을 쓴다면 → 아무리 좋은 아키텍처를 써도 **입력의 정보량 상한**에 걸립니다. TabM이 이미 per-sample에서 꽤 효율적으로 학습하고 있으므로, 아키텍처 변경의 marginal gain은 작을 겁니다
   - raw candle을 쓴다면 → **정보량 상한이 올라갑니다**. 하지만 1분봉 391개 시퀀스를 처리하는 컴퓨팅 비용과 32GB GPU 제약을 해결해야 합니다

2. **feature interaction을 모델이 학습할 것인가, hand-craft할 것인가?**
   - Transformer/Attention 계열은 feature interaction을 자동 학습하지만, 금융 데이터에서 이게 실제로 작동한 evidence는 제한적입니다
   - 오히려 **domain knowledge 기반 feature engineering**(예: bid-ask spread, order flow imbalance)이 더 직접적인 signal일 수 있습니다

3. **target은 c2c_120을 그대로 쓸 것인가?**
   - 이전 회의에서 제안한 **alpha label (return - beta)**를 직접 학습하는 것이 아키텍처 변경보다 더 큰 impact를 줄 수 있습니다
   - 현재 모델은 c2c_120을 예측한 후 beta를 빼는데, **beta 예측에 capacity를 낭비**하고 있을 가능성이 높습니다

### Expert2_문제정의전문가
# Expert2 (Problem Formulation 비판) 발언

---

## Expert1이 "수의 폭력"이라고 했는데, 난 한 단계 더 파겠습니다. **왜 수의 폭력이 필요했는가** — 그건 문제 정의가 잘못됐기 때문입니다.

---

### 1. c2c_120 binary classification은 **잘못된 질문**입니다

지금 뭘 하고 있나요? "120분 후 수익률이 양수인가 음수인가"를 분류하고 있습니다. 그런데 **평가는 CumAlpha**로 합니다. 이 두 가지가 align되지 않습니다.

**구체적으로:**
- 모델이 "이 종목 올라간다"고 예측 → 맞음 → 근데 시장 전체가 올라서 beta=+0.3%인데 이 종목은 +0.2% → **alpha는 음수**
- 모델이 "이 종목 내려간다"고 예측 → 맞음 → 시장이 -0.5%인데 이 종목은 -0.1% → **alpha는 양수**

즉, **방향 분류 정확도와 alpha는 상관관계가 낮을 수 있습니다.** 이건 이론이 아니라 실험에서 이미 증명됐습니다:
- TabM 105feat: 방향 정확도 괜찮은데 alpha +20.2M (baseline의 60%)
- CS-MLP: WR 54%로 나쁘지 않은데 beta를 학습해서 alpha가 오히려 낮음

**결론: "수익률 방향을 맞추는 모델"을 만들고 있는데, 필요한 건 "alpha를 생성하는 모델"입니다. 질문 자체가 틀렸습니다.**

---

### 2. Loss function이 투자 목적과 완전히 괴리됩니다

현재 loss 구조를 보면:
- **CE loss**: "이 종목이 올라갈 확률"을 학습 → **절대 수익률 방향**
- **ListNet**: "종목 간 상대 순위"를 학습 → 이건 alpha 방향에 가깝지만, **ranking target이 c2c_120 raw return**

ListNet의 ranking target이 raw return이면 **beta가 큰 날에 beta를 잘 예측하는 모델이 높은 ranking loss를 달성**합니다. 이건 alpha가 아닙니다.

**해야 할 것:**
```
현재: CE(predict direction of c2c_120) + ListNet(rank by c2c_120)
필요: CE(predict direction of alpha_120) + ListNet(rank by alpha_120)
  또는: IC-based loss(maximize rank IC of alpha_120)
  또는: Sharpe loss(maximize portfolio Sharpe ratio)
```

---

### 3. Expert1의 우선순위 표에서 빠진 것: **Label 구성 방식 변경**

Expert1이 alpha label을 1순위로 올렸는데, 난 더 구체적으로 쪼개겠습니다.

| 접근 | 구현 난이도 | 기대 impact | 리스크 |
|------|-----------|------------|--------|
| **(A) Alpha label 직접 학습** | **낮음** — label만 바꾸면 됨 | **높음** — beta capacity 낭비 제거 | alpha 자체의 SNR이 raw return보다 낮을 수 있음 |
| **(B) ListNet target을 alpha로 변경** | **낮음** — `listnet.py`에서 ranking target만 변경 | **중간** — ranking이 alpha 기준으로 정렬 | CE와 ListNet의 target이 달라지면 conflict |
| **(C) IC-based loss** | **중간** — 새 loss 구현 필요 | **높음** — 평가 지표와 직접 align | differentiable IC 구현이 까다로움 |
| **(D) Sharpe loss** | **높음** — portfolio 구성을 loss에 포함 | **매우 높음** — 평가와 완벽 align | 계산 비용, 미분 불안정 |

**내 추천 순서: A → B → C.** D는 연구 프로젝트 수준이라 현 단계에서 무리.

---

### 4. 한 가지 더 — Validation 방식은 괜찮지만 **regime을 무시하고 있습니다**

시간순 split은 올바릅니다. 그런데:
- Train: 2025-02-19 ~ 10-01 (상승장? 횡보?)
- Val: 10-01 ~ 12-01
- Test: 12-01 ~ 02-09

**만약 train 기간과 test 기간의 market regime이 다르면**, validation loss가 낮아도 test에서 실패합니다. 현재 실험 결과에서 "val_loss 최저인데 trading sim 최악"인 케이스(tau=0.5)가 이미 이걸 보여줍니다.

이건 아키텍처나 피처로 해결할 문제가 아닙니다. **Regime-conditional normalization**이나 **adversarial training**(regime에 invariant한 representation 학습)이 필요한 영역입니다. 단, 이건 장기 과제이고 지금 당장은 label 변경이 더 급합니다.

### 5. 최종 발언: Researcher2에게

아키텍처 제안 전에 이걸 먼저 대답해 주세요:

1. **c2c_120 대신 alpha_120을 타겟으로 쓸 의향이 있는가?** 이게 아키텍처 변경보다 impact가 큽니다.
2. **새 아키텍처가 "alpha signal 추출"에 구조적으로 유리한 이유가 있는가?** 단순 capacity 증가는 noise도 같이 학습합니다.
3. **Multi-task로 여러 horizon(c2c_30, c2c_60, c2c_120)을 동시 학습하는 것도 고려했는가?** 짧은 horizon은 SNR이 더 높을 수 있고, auxiliary signal이 representation을 개선할 수 있습니다.

**결론: 모델을 바꾸기 전에 "무엇을 예측할 것인가"를 바꿔야 합니다. 잘못된 타겟에 좋은 모델을 붙여봐야 잘못된 답을 더 정확하게 낼 뿐입니다.**

## 1. Expert2의 "c2c_120 분류는 잘못된 질문" — **부분 동의, 하지만 과장됨**

Expert2 논리가 깔끔한데, 실험 데이터가 이걸 완전히 지지하지는 않습니다.

**반론 근거:**
- TabM 105feat은 c2c_120 방향 분류로 학습했는데도 **Non-Top200에서 +20.2M alpha**를 생성합니다. 만약 방향 분류와 alpha가 상관없다면 이 숫자가 나올 수 없습니다.

**동의하는 부분:**
- beta 예측에 capacity를 낭비한다는 건 맞습니다. 특히 시장 전체가 강하게 움직이는 날, 모든 종목을 "상승"으로 분류하면 CE loss는 낮지만 alpha는 0입니다.
- ListNet target이 raw return인 것도 문제입니다. **beta가 큰 날에 beta를 잘 맞추는 모델이 ListNet loss에서 보상받는 구조**가 맞습니다.

**결론: 타겟을 바꾸는 건 시도할 가치가 있지만, "질문 자체가 틀렸다"는 건 과장입니다. c2c_120에서도 alpha가 나오고 있으니까요.**

## 2. Alpha label의 실질적 문제점 — Expert2가 간과한 것

Alpha label `α = return - beta`를 직접 학습하면 좋겠지만, **금융 데이터 특성상 세 가지 문제**가 있습니다:

| 문제 | 설명 | 심각도 |
|------|------|--------|
| **SNR 하락** | raw return에서 beta(가장 큰 component)를 빼면 남는 건 noise가 지배적인 잔차. 분류 경계가 더 모호해짐 | 높음 |
| **Beta 추정 불안정** | `beta = mean(c2c_120, valid stocks at t)` — 종목 수와 구성이 시간마다 다름. Non-Top200은 유동성 낮은 종목 포함이라 beta 자체가 noisy | 중간 |
| **Look-ahead 위험** | beta를 계산하려면 같은 timestamp의 다른 종목 미래 수익률이 필요. 학습 시점에서 이걸 알 수 있는가? label 생성 시점에서만 가능하고, **inference 시점에서는 alpha label의 ground truth 자체가 존재하지 않음** | 치명적이진 않음 (label이니까) |

**세 번째 포인트가 중요합니다.** Alpha label은 학습용 label로는 사용 가능하지만 (과거 데이터니까), inference 시점에서 "alpha가 양수인가"를 분류하는 건 결국 "이 종목이 시장 평균보다 더 오르는가"를 맞추는 것이고 — 이건 c2c_120 ranking과 본질적으로 같은 문제입니다.

**그래서 내 판단:**
- Alpha label 직접 학습: **시도할 가치 있지만 은탄환은 아님**. SNR이 낮아서 TabM PLE binning이 더 힘들어질 수 있음
- **ListNet target을 alpha로 바꾸는 게 더 안전한 첫 단계**. CE는 c2c_120 유지, ListNet만 alpha ranking으로 변경하면 conflict도 적고 alpha 방향 학습 유도 가능

## 3. Expert1의 "아키텍처 변경은 marginal" — **대체로 동의**

실험 데이터가 이걸 강력히 지지합니다:

- K200에서 CS-Attn, PatchTST, TSMixer, ALSTM, MASTER — **전부 TabM보다 못합니다**
- Transformer 계열(PatchTST, TSMixer)은 Long 방향이 역전되는 치명적 패턴을 보였고
- CS-Attn은 epoch 0이 best → 학습할수록 나빠짐 → **attention이 noise를 학습**

**이 패턴이 뜻하는 바:**
1. 금융 1분봉 데이터에서 **sequence modeling은 기대만큼 작동하지 않습니다**. SNR이 너무 낮아서 temporal pattern보다 noise를 먼저 학습합니다.
2. TabM의 PLE binning + BatchEnsemble은 **low-SNR 환경에 surprisingly robust**합니다. Quantile boundary가 non-stationarity를 흡수하고, 앙상블이 noise를 평균냄.
3. 따라서 **동일 피처에서 아키텍처만 바꿔서 TabM을 이기기는 매우 어렵습니다.**

**단, 예외가 하나 있습니다:** TabM이 못하는 걸 하는 아키텍처라면 가치가 있습니다. 구체적으로:
- **Feature interaction을 명시적으로 모델링** — TabM은 feature를 독립적으로 PLE 인코딩한 뒤 MLP로 interaction을 학습. 근데 MLP의 interaction 학습은 implicit하고 얕음
- **FT-Transformer의 attention이 feature interaction을 explicit하게 학습**할 수 있지만, K200 실험에서 attention이 noise를 학습한 전례가 있어서 **regularization이 관건**

### 제안 1: Gated Feature Selection + TabM (GFS-TabM)

**TabM이 못하는 것:** 153개 feature를 전부 동등하게 PLE 인코딩합니다. 공선성 높은 feature(close-open 1분 vs 5분)와 실제 alpha signal을 가진 feature를 **구분하지 못합니다.** MLP가 implicit하게 학습한다고 하지만, Expert1이 지적했듯이 "153→~50 effective features" 수준의 redundancy를 MLP가 효율적으로 처리한다는 근거가 없습니다.

**구조:**
```
Input(142 feat) → GRN(Gated Residual Network) → Feature weights(142) → Weighted PLE → TabM backbone
```

- Temporal Fusion Transformer(Lim et al., 2021)의 **Variable Selection Network**를 분리 추출
- 핵심: `softmax(W₂ · ELU(W₁ · x + b₁) + b₂)` → feature-wise gate → **redundant feature 자동 억제**
- TabM backbone은 그대로 유지 — PLE + BatchEnsemble 건드리지 않음
- **파라미터 추가량**: ~20K (142×128 + 128×142) — TabM 대비 <5% 증가

**왜 이게 TabM보다 나을 수 있는가:**
- 공선성 feature를 gate로 억제하면, PLE binning이 **informative feature에 capacity를 집중**
- 특히 Alpha label과 결합하면 — alpha signal이 약한 feature(beta-correlated)를 gate가 자동으로 내림
- K200에서 attention이 실패한 건 **sample 간 attention**이었음. 이건 **feature 간 gating**이라 차원이 다름. Noise 학습 위험이 구조적으로 낮음

**리스크:** Gate 자체가 noise를 학습할 가능성. → **Dropout 0.3 + L1 sparsity on gate weights**로 대응

**구현 비용:** architecture 파일 1개 + config 1개 + trainer는 TabM trainer 복사. **반나절.**

---

### 제안 2: Contrastive Pre-training → TabM Fine-tune (Phase 2 후반)

이건 Expert1이 언급한 **"정보량 상한 돌파"** 문제에 대한 유일한 구조적 해법입니다.

**현재 한계:** 어떤 모델을 써도 입력이 142개 hand-crafted feature인 이상, **feature engineering이 놓친 정보는 절대 복원 불가**입니다. AG baseline이 +33.2M인 이유도 결국 같은 feature에서 더 잘 짜낸 거지, 정보량 자체가 다른 게 아닙니다.

**제안 구조:**
```
Phase A (Pre-train): Raw 1분봉 OHLCV(120 bars) → 1D-CNN encoder → [CLS] token
  - Contrastive loss: 같은 종목의 인접 시간대 = positive, 다른 종목 = negative
  - 또는 Masked Candle Prediction: 랜덤 bar를 masking → 복원
  - Label 불필요 — self-supervised

Phase B (Fine-tune): [CLS] embedding(256d) + 142 engineered features → TabM → alpha prediction
```

**왜 이게 다른 sequence 모델과 다른가:**

K200에서 sequence 모델이 전멸한 이유는 **end-to-end로 sequence → alpha를 직접 학습**했기 때문입니다. Low-SNR target에 대해 sequence encoder가 noise를 먼저 학습한 거죠.

Contrastive pre-training은 **label을 안 씁니다.** "이 가격 패턴이 저 가격 패턴과 비슷한가"만 학습합니다. 이건 noise가 아니라 **시장 microstructure의 구조적 패턴**을 인코딩합니다. NLP에서 BERT가 downstream task 없이 language structure를 학습하는 것과 같은 원리입니다.

그 후 fine-tune에서 frozen encoder의 embedding을 **추가 feature로** TabM에 넣습니다. TabM의 검증된 구조는 그대로 유지하면서, 정보량 상한만 올리는 겁니다.

**리스크:**
- 1분봉 120개 × OHLCV 5채널 = 600차원 input → 1D-CNN으로 처리 가능하지만, pre-train에 91M 샘플 × 수 에포크 = **GPU 시간 상당**
- Pre-trained representation이 alpha-relevant한 정보를 실제로 담고 있을지 불확실
- **이건 Phase 1 결과를 본 후, label/loss 변경으로 +33.2M을 못 넘었을 때만 시도할 가치가 있습니다**

**구현 비용:** 1D-CNN encoder + contrastive loss + 2-stage training pipeline. **1-2일.**

## 1. GFS-TabM (Gated Feature Selection) — **조건부 동의, 하지만 함정이 있습니다**

Researcher2의 논리는 깔끔합니다: "142개 feature를 동등 처리하는 TabM에 gate를 달아서 redundant feature를 억제한다." 피처 관점에서 이건 **올바른 문제 인식**입니다.

**하지만 gate가 alpha-relevant feature를 실제로 찾을 수 있는가?**

핵심 문제를 짚겠습니다:

- **Gate의 학습 signal은 결국 loss에서 옵니다.** CE loss가 c2c_120 방향 분류라면, gate는 **c2c_120 방향 예측에 유용한 feature**에 높은 weight를 줍니다. 이게 alpha-relevant feature와 같다는 보장이 없습니다. Beta-correlated feature(시장 전체 움직임과 상관 높은 feature)가 c2c_120 방향 예측에는 더 유용할 수 있습니다.

**내 판정:**

## 2. Contrastive Pre-training — **피처 관점에서 가장 흥미롭지만, 치명적 결함 하나**

Researcher2가 "정보량 상한 돌파"라고 했고, Expert1인 제가 이전에 "raw candle self-supervised pretrain"을 제안한 바 있습니다. 방향은 동의합니다.

**하지만 contrastive loss 설계에 피처 leakage 위험이 있습니다:**

> "같은 종목의 인접 시간대 = positive, 다른 종목 = negative"

이 정의가 금융 도메인에서 **심각하게 잘못될 수 있습니다:**

1. **같은 종목 인접 시간대가 positive?** 1분봉 데이터에서 인접 bar는 **autocorrelation이 매우 높습니다.** 모델이 "가격 수준이 비슷하면 positive"를 학습하면, 이건 representation이 아니라 **가격 레벨 인코딩**입니다. 대형주는 대형주끼리, 소형주는 소형주끼리 묶이는 — CS-MLP의 beta 학습 문제와 동일한 메커니즘.

2. **다른 종목이 negative?** 같은 시점에 시장이 급락하면 **모든 종목의 캔들 패턴이 유사**합니다. 이걸 negative로 처리하면 모델이 **시장 regime 정보를 버립니다.** 우리가 원하는 건 그 반대 — regime-aware representation입니다.

**대안:**
- **Positive pair**: 같은 종목의 **다른 날, 유사한 alpha 구간**의 캔들
- **Negative pair**: 같은 종목의 **alpha 부호가 반대인** 캔들
- 이렇게 하면 representation이 **alpha-predictive pattern**을 인코딩하게 됩니다

단, 이 대안도 문제가 있습니다 — **alpha label이 필요합니다.** 순수 self-supervised가 아니게 되죠. 그래서 **Masked Candle Prediction 쪽이 더 안전합니다.** Label 없이 시장 microstructure를 학습하니까요.

### 실험 2 (Alpha Label) — alpha 분포 분석을 반드시 선행하세요

이건 이전 회의에서도 제가 요구했고 PM이 수용한 사항입니다. Alpha label을 만들 때:

```python

```

이 alpha의 분포를 **학습 전에** 반드시 확인해야 합니다:

| 분석 항목 | 왜 필요한가 |
|-----------|------------|
| **Kurtosis** | alpha가 heavy-tail이면 PLE binning이 극단값에 bin을 낭비 |
| **Time-varying std** | alpha의 변동성이 시간에 따라 달라지면 rolling normalization 필요 |
| **Cross-stock 상관** | alpha 간 상관이 높으면 종목 독립 가정이 깨짐 |
| **Zero-crossing 비율** | 50%에서 크게 벗어나면 class imbalance 문제 |
| **Beta estimation noise** | valid 종목 수가 적은 timestamp에서 beta가 불안정 → alpha도 noisy |

**특히 5번째가 중요합니다.** Non-Top200 종목은 유동성이 낮아서 특정 timestamp에 valid 종목이 100개 미만일 수 있습니다. 그 시점의 `mean(c2c_120)`은 **소수 종목에 의해 좌우**되고, alpha label 자체가 noise가 됩니다.

## 1. PM 실험 스펙에 빠진 치명적 검증 하나: IC Sanity Check

PM이 실험 3개를 확정했는데, **실험 결과를 해석할 기준선**이 없습니다.

현재 평가 흐름: 학습 → trading sim → L CumAlpha → 성공/실패 판정

**문제:** CumAlpha는 **trading sim의 parameter(threshold, cooldown, window)**에 민감합니다. 같은 모델이 threshold=0.1%에서 +30M이고 threshold=0.05%에서 -10M일 수 있습니다. 이건 모델 성능이 아니라 **sim parameter 적합도**입니다.

**Phase 1 실험 전에 반드시 추가해야 할 것:**

```
각 실험 모델의 예측 확률에 대해:
1. Rank IC (Spearman correlation between predicted rank and actual alpha rank) — per timestamp, then average
2. IC의 시간별 안정성 (IC의 std / mean = ICIR)
```

이 두 숫자가 있으면:
- IC > 0.03이고 ICIR > 0.5면 → **모델이 alpha signal을 잡고 있다**, trading sim 결과는 parameter tuning으로 개선 가능
- IC ≈ 0이면 → **모델이 alpha를 못 잡고 있다**, trading sim에서 양수가 나와도 우연

**이게 없으면 Phase 1 실험 3개 결과를 놓고 "이게 좋다 나쁘다" 논쟁만 반복합니다.**

## 3. Expert1의 alpha 분포 분석 요구 — **전면 지지, 하나 추가**

Expert1이 alpha 분포 5가지 분석을 요구했습니다. 전부 맞습니다. **하나 더 추가합니다:**

| 분석 항목 | 왜 필요한가 |
|-----------|------------|
| **Alpha-Beta 상관** | alpha = return - beta인데, beta가 큰 날 alpha도 분산이 커지면 heteroscedasticity 문제. PLE bin boundary가 시간에 따라 달라져야 함 |

이건 Expert1이 짚은 "time-varying std"와 관련되지만 더 구체적입니다. **Beta가 큰 날(시장 급등락) alpha의 noise도 커지는가?** 그렇다면 alpha label의 classification boundary를 **절대값이 아니라 그 날의 alpha std 기준 상대값**으로 잡아야 합니다.

**실질적 제안:**
```python
# 고정 boundary (현재)
alpha_class = (alpha > 0).astype(int)

# 상대 boundary (제안)
alpha_std_t = std(alpha, valid_stocks_at_t)
alpha_class = (alpha / alpha_std_t > threshold).astype(int)
```

이걸 쓸지 말지는 **분포 분석 결과에 따라 결정**합니다. 미리 구현할 필요 없고, 분석만 먼저.

- TabM hp8 (λ=0.1): trading sim **crash** — 근데 이게 모델이 나빠서인지 sim threshold와 안 맞아서인지 구분 불가

**IC/ICIR이 있으면 이 해석이 가능해집니다:**
- IC 높고 CumAlpha 낮으면 → 모델은 좋은데 sim parameter가 안 맞음 → threshold 조정
- IC 낮고 CumAlpha 높으면 → 우연. 기각.
- IC 높고 CumAlpha 높으면 → 진짜 좋은 모델

**단, Expert2의 "IC < 0.02면 trading sim 안 돌리고 즉시 기각"은 너무 공격적입니다.**

이유: Non-Top200 600종목은 유동성이 낮고 noise가 큽니다. K200에서 IC 0.03이면 Non-Top200에서는 0.015도 의미 있을 수 있습니다. **기각 threshold를 미리 정하지 말고, 모든 실험의 IC를 기록한 뒤 상대 비교하는 게 안전합니다.**

## Expert2의 "c2c_120 반론에 대한 재반론" — **논리적으로 맞지만 실무적으로 의미 없음**

Expert2가 "A로 결과가 나왔으니 A가 최적이다는 논리적 오류"라고 했는데, 맞습니다. 제가 말한 건 "c2c_120이 최적이다"가 아니라 **"c2c_120이 틀렸다는 주장이 과장이다"**입니다.

어차피 실험 2에서 검증하니까 이 논쟁은 여기서 종료합시다. **실험이 답해줄 문제를 이론으로 싸우는 건 시간 낭비입니다.**

## Expert1의 alpha 분포 분석 + Expert2의 heteroscedasticity 추가 — **전면 동의**

특히 Non-Top200에서 실질적으로 걱정되는 시나리오:

| 시나리오 | 발생 조건 | 영향 |
|----------|----------|------|
| **Beta 추정 폭발** | 특정 timestamp에 valid 종목 50개 미만 | alpha label이 소수 종목의 outlier에 좌우 |
| **Alpha 분산 regime 변동** | 시장 급락일 alpha std가 평상시 3배 | PLE bin boundary가 평상시 기준이면 급락일 alpha를 제대로 binning 못함 |
| **Class imbalance** | alpha > 0 비율이 45%면 | CE loss가 "전부 음수" 쪽으로 bias |

**이 3가지가 실험 2를 죽일 수 있는 구체적 경로입니다.** 분포 분석 없이 돌리면 "alpha label이 안 먹히네"로 결론 내고, 실제로는 binning이나 class balance 문제일 수 있습니다.


이게 GFS-TabM과 같은 효과인데 **새 아키텍처 구현이 필요 없습니다.** 실험적으로도 "feature pruning이 효과 있는가"를 먼저 검증하고, 있다면 그때 gate를 넣는 순서가 맞습니다.

## 다만, 이 회의에서 묻힌 구조적 리스크 하나만 못 박겠습니다.

**실험 2 (Alpha label)가 "성공"으로 판정되는 시나리오에서의 함정:**

PM이 성공 기준을 `실제 alpha > +33.2M (AG baseline)`으로 잡았습니다. 근데 이걸 넘었다고 해서 **alpha label이 c2c_120보다 낫다**는 결론을 바로 내리면 안 됩니다.

**왜?** Alpha label 실험은 **feature set도 다릅니다.** 142feat enhanced vs AG baseline의 feature set은 다릅니다. 따라서:

- 실험 2가 +35M → "alpha label 덕분인가, 142feat 덕분인가?" 분리 불가
- 이걸 분리하려면 **실험 1 (CE-only, c2c_120 target, 142feat)**과 **실험 2 (alpha target, 142feat)**의 IC를 직접 비교해야 합니다

**즉, 실험 1과 실험 2의 IC 차이가 alpha label의 순수 효과입니다.** CumAlpha 차이가 아니라요.

```
alpha label 효과 = IC(실험2) - IC(실험1)
  > 0: alpha label이 model quality를 개선 → 채택
  ≈ 0: alpha label 효과 없음 → c2c_120 유지 (더 단순하니까)
  < 0: alpha label이 SNR 하락으로 오히려 악화 → 기각
```

**이 비교 프레임을 PM 스펙에 명시해주세요.** 안 그러면 실험 2 결과가 나왔을 때 "CumAlpha가 높으니까 좋다"로 결론 내고, 실제로는 142feat의 효과를 alpha label의 효과로 오귀인(misattribution)할 수 있습니다.

nice-to-have라고 했는데, **Phase 1 결과 해석에 IC decomposition이 없으면 "왜 좋았는지"를 못 압니다.**

```python
# 간이 IC decomposition
ic_total = spearman(pred_rank, actual_return_rank)  # 전체 IC
```
