## Researcher2의 두 가지 제안에 대한 피처 관점 비판

### 제안 1: Alpha label 직접 타겟팅 (return - beta)

**피처 관점에서 강력 지지하되, 핵심 경고가 있습니다.**

현재 `c2c_120`을 타겟으로 쓰면 모델이 학습하는 건:
```
f(features) → total_return = alpha + beta
```

Beta가 전체 시장 방향인데, **우리 105feat에는 시장 전체 방향을 알려주는 피처가 없습니다.** 종목별 OHLCV만 있으니까요. 그래서 모델은 beta를 학습할 수 없으면서 beta를 포함한 타겟을 맞추려고 하고, 이게 noise로 작용합니다.

Alpha label로 전환하면 **피처와 타겟의 alignment가 개선**됩니다. 종목별 피처 → 종목별 alpha. 이건 맞습니다.

**하지만 경고:**
- Beta 계산 시점이 중요합니다. `beta_t = mean(c2c_120) at timestamp t`를 label 생성 시 계산하면, 이건 **해당 시점의 모든 종목 수익률을 알아야** 합니다. 학습 데이터에서는 문제없지만, **추론 시에는 동일 timestamp의 다른 종목 수익률을 모릅니다.** 
- 따라서 alpha label은 학습에만 사용 가능하고, 추론 시에는 여전히 raw prediction을 쓰고 사후에 beta를 빼야 합니다. **이건 leakage는 아니지만, 학습-추론 불일치(train-inference mismatch)입니다.**
- 실무적으로 CE loss에서 alpha label의 class boundary를 어떻게 정할지도 문제입니다. c2c_120의 quantile boundary와 alpha의 quantile boundary는 분포가 다릅니다.

**구체적 제안:** Alpha label 실험 시 반드시 **alpha의 분포를 먼저 확인**하세요. c2c_120은 대략 정규분포에 가깝지만, alpha는 beta 제거 후 분산이 줄어들면서 class boundary가 좁아집니다. 기존 5-class boundary를 그대로 쓰면 안 됩니다.

---

### 제안 2: Raw candle self-supervised pretrain

**피처 관점에서 회의적입니다. 이유를 구체적으로 말하겠습니다.**

1. **우리 데이터의 핵심 문제는 피처 품질이지 representation이 아닙니다.**
   - 105feat가 이미 OHLCV에서 파생된 hand-crafted features입니다
   - Self-supervised pretrain도 결국 같은 OHLCV에서 representation을 뽑습니다
   - **입력이 동일한데 representation만 바꿔서 얼마나 나아질 수 있는가?**

2. **시계열 모델이 이 프로젝트에서 전멸한 역사가 있습니다.**
   - CS-MLP, SeqGRU 등 시퀀스 기반이 tabular보다 못했습니다
   - 이건 1분봉 데이터의 SNR(signal-to-noise ratio)이 극도로 낮기 때문입니다
   - Self-supervised pretrain이 이 SNR 문제를 해결해 줄 근거가 없습니다

3. **Pretrain-finetune 파이프라인의 복잡성 대비 기대 효과가 불확실합니다.**
   - 구현 시간, 하이퍼파라미터 튜닝, pretrain 에폭 수 등 변수가 너무 많습니다
   - 같은 시간에 **피처 엔지니어링을 더 하는 게 ROI가 높습니다**

## 내가 보는 진짜 bottleneck: 피처 다양성 부족

현재 모든 피처가 **가격과 거래량**에서만 나옵니다. 금융에서 alpha를 만드는 signal은 크게 4가지인데:

| Signal 종류 | 현재 커버리지 | 상태 |
|------------|-------------|------|
| Price momentum/mean-reversion | 105feat으로 과포화 | 공선성 심각 |
| Volume/liquidity | vol_per_avg 5종 | 부족하지만 있음 |
| Market microstructure | 호가 스프레드, 체결강도 등 | **전무** |
| Cross-sectional relative | 종목 간 상대 위치 | **전무** |

**Alpha101이 앙상블에서 complementary한 이유가 정확히 이겁니다** — 105feat과 다른 종류의 signal을 포착하니까요. 하지만 alpha101 단독 성능이 낮은 건, 20개로는 충분한 정보가 없기 때문입니다.

## 구체적 우선순위 제안

1. **Alpha label 실험 (동의) — 단, alpha 분포 분석 선행 필수**
2. **Self-supervised pretrain (보류) — ROI 불확실, 시계열 모델 전멸 전례**
3. **대신 추가할 것: Cross-sectional relative features**
   - 각 timestamp에서 종목의 수익률/거래량 rank (percentile)
   - 이건 look-ahead bias 아닙니다 — 해당 시점까지의 실현 데이터만 사용
   - **하지만 주의:** 추론 시에도 동일 timestamp의 전 종목 데이터가 필요합니다. 이게 가능한지 파이프라인을 먼저 확인해야 합니다.
4. **105feat 압축: PCA나 feature selection으로 50개 이하로 줄이기**
   - 공선성 있는 피처를 그대로 두면 모델이 같은 정보에 capacity를 낭비합니다
   - 줄이고 남은 capacity로 새 signal을 넣는 게 효율적입니다

## 1. Alpha Label — 지지하되, Expert1이 놓친 더 근본적인 문제를 지적합니다

Expert1이 train-inference mismatch를 경고했는데, 이건 사실 **문제가 아닙니다.** 이유:

- 학습 시: `y = return - beta_t`로 alpha를 직접 예측하게 함
- 추론 시: 모델은 `f(features) → alpha_hat`을 출력하고, 이걸 그대로 종목 선택에 사용
- Beta를 빼는 건 **label 구성 단계**에서 끝난 일이지, 추론 시 다시 빼야 하는 게 아님

**진짜 문제는 다른 데 있습니다:**

### Alpha의 non-stationarity가 classification을 깨뜨린다

c2c_120에서 beta를 빼면 alpha가 나오는데, 이 alpha의 **분산이 regime마다 극심하게 변합니다.**

- 시장 횡보기: beta ≈ 0이므로 alpha ≈ total return, 분산 작음
- 시장 급등/급락기: beta가 크므로 alpha = return - (큰 수), 분산이 뒤틀림

이걸 **고정된 quantile boundary로 5-class classification** 하면, 학습 기간의 boundary가 테스트 기간에서 의미가 없어집니다. Expert1이 "alpha 분포 분석 선행"이라고 했는데, 분석만으로는 부족합니다. **Rolling quantile boundary가 필요합니다** — 매 시점마다 최근 N일의 alpha 분포에서 quantile을 재계산.

**구체적 제안:** Alpha label 실험 시 **두 가지를 동시에 비교**하세요:
- (A) 전체 학습 기간의 고정 quantile boundary
- (B) Rolling 20일 quantile boundary (label이 시간에 따라 재정의됨)

(B)가 (A)보다 나으면 regime non-stationarity가 핵심 병목이라는 증거입니다.

---

## 2. Self-Supervised Pretrain — Expert1의 "보류" 판단에 **부분 동의, 부분 반대**

Expert1이 "시계열 모델 전멸"을 근거로 보류를 주장했는데, 이건 **논리적 오류**입니다.

시계열 모델이 전멸한 건 **end-to-end로 raw sequence에서 바로 prediction까지 갔기 때문**입니다. Self-supervised pretrain은 다른 게임입니다:

- End-to-end: `raw OHLCV sequence → prediction` (SNR이 낮은 signal을 직접 학습)
- Pretrain-finetune: `raw OHLCV → representation (unsupervised)` → `representation → prediction (supervised)`

Pretrain 단계에서는 **label을 안 씁니다.** Next-bar prediction이나 masked reconstruction 같은 pretext task는 SNR 문제와 무관합니다. 시장 데이터의 **구조적 패턴**(volatility clustering, mean-reversion 주기 등)을 인코딩할 수 있습니다.

**그러나 ROI 관점에서 Expert1이 맞습니다.** Pretrain 파이프라인 구현 + 튜닝에 2-3일이 들고, 성공 확률은 불확실합니다.

**내 판단:** 우선순위 3번으로 내리되 완전 폐기하지는 마세요. Alpha label + CE only 실험 결과를 먼저 보고, **그래도 안 되면** pretrain이 다음 카드입니다.

---

## 3. 여기서 아무도 안 꺼낸 진짜 이슈: **Loss Function이 alpha 최적화에 align되지 않았다**

이게 이 회의에서 아직 안 다뤄진 핵심입니다.

현재 CE loss가 하는 일:
```
maximize P(correct class | features)
```

우리가 실제로 원하는 것:
```
maximize rank_correlation(prediction, future_alpha)
```

**이 두 가지는 같은 게 아닙니다.** CE loss로 학습하면:
- Class 1 (상위 20%)과 class 2 (20-40%)를 정확히 구분하는 데 capacity를 쓰지만
- 우리 trading sim은 **top/bottom만 선별**합니다
- Class 1과 class 2를 완벽히 구분하는 것보다 **class 1과 class 5를 확실히 구분하는 게** alpha에 더 중요합니다

ListNet이 이걸 보완하려고 했는데, Expert1이 말한 대로 837종목 전체를 하나의 ranking universe로 묶으면 beta를 학습합니다.

**대안: IC-aware loss 또는 Simplified Ranking Loss**

```
L = -IC(prediction_score, alpha_label)
```

여기서 IC = Spearman rank correlation. 이건 직접적으로 "예측 순위와 실제 alpha 순위의 상관"을 최적화합니다.

구현이 까다로우면 **더 간단한 방법**: CE를 유지하되 **class weight를 극단 class에 집중**시키세요.
```python
class_weights = [3.0, 1.0, 0.5, 1.0, 3.0]  # class 0,4에 3배 가중
```

이렇게 하면 CE가 top/bottom 구분에 더 많은 capacity를 쓰게 됩니다. 구현 비용 거의 제로이고, **label_smoothing_ce에 이미 class_weights 파라미터가 있습니다.** 코드 한 줄 바꾸면 됩니다.

## Expert2의 class_weights 제안 — 동의하지만 기대치를 낮춰야 합니다

Expert2가 "loss가 목적에 align 안 된다"고 했는데, 맞는 진단입니다. 그런데 `class_weights = [3,1,0.5,1,3]`이 이걸 해결한다는 건 **과대평가**입니다. 이유:

1. **CE with class_weights는 여전히 pointwise loss입니다.** 각 sample을 독립적으로 분류하는 구조에서 가중치만 바꿔봤자, "이 종목이 다른 종목보다 좋은가"라는 ranking signal은 안 나옵니다.

2. **실험적 근거**: K200에서 ListNet λ=0.3이 CE only보다 좋았던 이유가, ranking 정보를 추가했기 때문입니다. 837종목에서 ListNet이 beta를 학습하는 게 문제였지, ranking loss 자체가 나쁜 게 아닙니다.

3. **class_weights의 실제 효과**: extreme class에 weight를 주면 **precision은 오르지만 recall이 내려갑니다.** Trading sim에서 trade 수가 줄어들고, notional이 줄어듭니다. alpha101 단독이 bp=64.9인데 notional=3.7M이라 쓸모없었던 것과 같은 패턴이 될 수 있습니다.

**그래도 구현 비용이 0이니까 하세요.** 단, CE only 실험과 **동시에 돌리지 말고, CE only를 먼저 baseline으로 잡은 후** class_weights를 변형으로 테스트해야 인과관계가 깨끗합니다.

## Alpha label에 대해 — Expert1, Expert2 양쪽 정리

Expert1이 "train-inference mismatch"를 경고했고, Expert2가 "문제 아니다"라고 반박했는데, **Expert2가 맞습니다.** 

Label 구성 단계에서 beta를 빼는 건 학습 시 target을 정제하는 것이고, 추론 시 모델 출력은 "이 종목의 alpha가 높을 확률"이 됩니다. Trading sim이 cross-sectional rank로 종목을 선별하니까, alpha prediction의 rank만 보존되면 됩니다. beta를 추론 시 다시 빼야 하는 게 아닙니다.

**하지만 Expert2의 rolling quantile boundary는 구현 비용 대비 불확실합니다.** 이유:

- Rolling 20일 quantile로 label을 만들면, **같은 alpha 값이 시점에 따라 다른 class**가 됩니다
- 모델은 "이 feature 조합 → class 3"을 학습하는데, class 3의 의미가 시간에 따라 변하면 **학습 자체가 불안정**해집니다
- 이건 PLE binning이 feature 쪽에서 하는 normalization과 다릅니다 — PLE는 input을 정규화하는 거고, rolling boundary는 **target을 비정규화**하는 겁니다

**내 대안:** Alpha label을 쓰되, boundary는 **전체 학습 기간 고정 quantile로 시작**하세요. Alpha는 beta 제거 후 분산이 줄어드니까, 기존 c2c_120 boundary를 쓰면 안 되고, alpha 전용 quantile을 계산해야 합니다. 이건 `scripts/create_enhanced_npy.py`에서 label 생성 시 한 번만 하면 됩니다.

Rolling boundary는 고정 boundary 실험 결과가 나온 후에 **필요하다면** 시도하세요. 변수를 한 번에 2개 바꾸면 뭐가 효과인지 알 수 없습니다.

## Self-supervised pretrain — 내 최종 입장

Expert2가 "시계열 전멸 ≠ pretrain 실패" 논리를 펼쳤고, 학술적으로는 맞습니다. End-to-end와 pretrain-finetune은 다른 파이프라인입니다.

**하지만 실무적으로 이 프로젝트에서 안 되는 이유가 하나 더 있습니다:**

우리 데이터는 **1분봉 × 837종목 × 91.6M rows**입니다. Pretrain에 필요한 sequence를 구성하면:
- 120분 lookback × 837종목 = 한 시점에 837개 시퀀스
- Masked reconstruction이든 next-bar prediction이든, **GPU 메모리와 시간이 현재 인프라에서 감당 가능한지 불확실**
- SeqGRU v2가 seq_len=120으로 smoke test는 통과했지만, full training은 아직 미검증

Pretrain은 **최소 2-3 에폭은 돌려야** representation이 안정화되는데, 91.6M × 120 시퀀스를 2-3 에폭 돌리는 건 **현재 GPU 1장 환경에서 며칠이 걸릴 수 있습니다.**

**결론: 우선순위 최하위 유지.** Alpha label + CE only 실험에서 유의미한 개선이 보이면 그걸 밀어붙이는 게 ROI가 압도적으로 높습니다.

## 1. 실험 2 Alpha Label — 아키텍처 관점 주의사항

Alpha label로 전환하면 **output distribution이 바뀝니다.** c2c_120은 시장 beta를 포함해서 분산이 크고, alpha는 beta 제거 후 분산이 작습니다. 이게 왜 중요하냐면:

**TabM의 PLE binning이 input feature에만 적용되고 label에는 적용 안 됩니다.** Label 분포가 좁아지면 5-class 간 decision boundary가 더 촘촘해지고, 모델의 last layer가 **더 fine-grained한 구분**을 해야 합니다. 현재 `d_block=256`이 이 해상도에 충분한지는 실험으로만 알 수 있지만, **만약 alpha label 실험에서 val_acc가 c2c_120보다 오히려 낮아지면**, d_block을 384로 올리는 게 아니라 **class 수를 5→3으로 줄이는 걸 먼저 시도**하세요. 분산이 줄어든 alpha에서 5-class는 over-partition일 수 있습니다.

이건 변수를 하나만 바꾸는 원칙과 충돌하니까 **실험 2의 결과가 나쁠 때만** 후속 변형으로 검토하면 됩니다.

## 2. 실험 3 Class Weights — Researcher1의 경고에 추가


**반드시 확인할 4가지:**

| 항목 | 왜 중요한가 | 기준 |
|------|-----------|------|
| **std(alpha) / std(c2c_120)** | 분산 축소 비율 → class boundary 간격 결정 | 0.5 이하면 5→3 class 축소 검토 (Researcher2 제안과 일치) |

| **timestamp별 alpha std의 변동** | regime별 분산 차이 → 고정 boundary의 유효성 | cv(std_per_timestamp) > 1.0이면 고정 boundary가 위험하다는 조기 경보. 당장은 고정으로 가되, 이 수치를 기록해 두고 rolling boundary 재논의 근거로 삼을 것 |

**이 4가지를 alpha label 생성 스크립트에서 자동 출력하게 해 주세요.** 수동으로 확인하면 빠뜨립니다.

## 3. 모든 실험에 관통하는 근본 리스크: Evaluation과 Optimization의 괴리

이건 이 회의 내내 제가 말해온 건데, **마지막으로 한 번 더 명시합니다.**

우리가 최적화하는 것:
```
CE loss = -Σ log P(correct_class | features)
```

우리가 평가하는 것:
```
CumAlpha = Σ (alpha_long - alpha_short) over time
```

**이 둘 사이에 monotonic relationship이 보장되지 않습니다.** CE loss가 낮다고 CumAlpha가 높은 게 아닙니다. CE는 "맞는 class에 높은 확률을 부여"하는 걸 최적화하지만, CumAlpha는 "top/bottom 종목 선별 후 실현된 alpha의 합"입니다.

실험 1-4 전부가 CE 기반이고, **CE를 아무리 개선해도 CumAlpha와의 상관이 낮으면 의미가 없습니다.**

**이걸 검증하는 방법:** 각 실험에서 **validation CE loss vs validation CumAlpha의 상관**을 epoch별로 확인하세요. Best val_loss epoch과 best val_CumAlpha epoch이 일치하면 CE가 유효한 proxy입니다. **불일치하면 loss function 자체를 바꿔야 한다는 신호**이고, 그때 IC-based loss나 direct alpha optimization이 테이블에 올라옵니다.

현재 train.py에서 early stopping이 val_loss 기준이면, val_CumAlpha 기준으로 바꾸는 것만으로도 개선이 가능할 수 있습니다. 이건 loss function 변경보다 훨씬 싼 실험입니다.

Expert2가 "CE loss가 CumAlpha의 유효한 proxy인지 검증"을 요청했습니다. 방향은 맞는데, **현재 인프라에서 매 epoch CumAlpha를 계산하는 건 trading sim 전체를 돌려야 해서 비용이 큽니다.**

**현실적 대안:** Early stopping은 val_loss 기준으로 유지하되, **best epoch과 last epoch 두 개의 inference를 저장**해서 trading sim을 각각 돌리세요. 만약 last epoch이 best epoch보다 CumAlpha가 높으면, val_loss 기반 early stopping이 suboptimal이라는 증거입니다. 이건 추가 비용이 eval 1회분뿐입니다.

**그리고 솔직히 말하면**, 지금까지 프로젝트에서 val_loss best epoch이 trading sim에서도 best인 경우가 대부분이었습니다. 이게 깨지는 건 주로 overfitting이 심할 때(patience가 너무 클 때)인데, 현재 patience=15는 적절한 수준입니다.

---

## 3. Expert1의 prediction dispersion 비교 — 실용적으로 간단합니다

실험 1(CE only) 완료 후 기존 ListNet 모델과 비교할 때:

```python
# prediction dispersion = 종목 간 예측 확률의 표준편차
disp_ce = np.std(probs_ce[:, 0] - probs_ce[:, 4], axis=1).mean()  # class0-class4 차이의 std
disp_ln = np.std(probs_ln[:, 0] - probs_ln[:, 4], axis=1).mean()
```

**`disp_ce > disp_ln`이면 ListNet이 prediction을 compress(uniform화)시킨 것 → beta 학습 증거.** 이건 numpy 한 줄이니까 eval 시 자동으로 출력하면 됩니다.

## 4. Researcher2의 class 수 축소 (5→3) — 금융 관점에서 위험합니다

Researcher2가 "alpha 분산이 줄어들면 5-class가 over-partition"이라고 했는데, **trading sim 구조와 충돌합니다.**

Trading sim은 `probs[:, 0]` (class 0, 최하위)와 `probs[:, 4]` (class 4, 최상위)의 차이로 long/short 신호를 만듭니다. **3-class로 바꾸면:**
- Class 0이 하위 33%를 커버 → 극단 종목의 신호가 희석
- 현재 5-class에서 class 0(하위 20%)과 class 1(20-40%)을 구분하는 능력이 사라짐
- **Trading sim의 selectivity가 떨어져서 WR이 내려갈 가능성이 높음**

금융에서 extreme 예측의 정밀도가 생명입니다. 5-class를 유지하되, 만약 alpha 분산이 너무 좁으면 **class 수를 줄이는 게 아니라 boundary를 equi-frequency로 재설정**하는 게 맞습니다. 같은 5-class지만 각 class에 20%씩 균등 배분. 이건 Expert1이 제시한 분포 분석에서 자연스럽게 결정됩니다.
