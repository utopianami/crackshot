# Expert1 발언: 피처 품질 관점에서의 비판

## Researcher2의 H1~H3 가설에 대한 피처 레벨 코멘트

### H1: 종목별 독립 학습 — 동의하지만 피처 주의사항 있음

H1-1 (TabM + 105feat)은 이미 결과가 나왔고 **+33.2M AG CLS를 넘는 성과**를 보였다. 여기까진 좋다.

그런데 **H1-3 (alpha101)이 단독으로 약한 이유**를 짚어야 한다:

- **alpha101의 절반 이상이 cross-sectional rank 기반**이다. `rank(ts_corr(close, volume, 5))` 같은 식이 원본 정의에 있다. 이걸 종목별 독립 모델에 넣으면 **rank가 의미를 잃는다** — 전체 유니버스 대비 순위인데 단일 종목 시계열에선 항상 같은 값이 되니까.
- alpha101 중 **순수 time-series factor** (momentum, mean reversion, volume spike 등)만 추출해서 쓰면 단독 성능이 올라갈 가능성이 높다. 현재는 cross-sectional factor + time-series factor가 섞여서 noise를 만들고 있다.

**제안**: alpha101을 CS-dependent / TS-only로 분리하고, TS-only subset으로 H1-3를 재실험해볼 것.

### H1의 앙상블이 잘 되는 이유도 이걸로 설명된다

ens3 (105feat + alpha101 + d7)가 72.9% WR을 찍은 건, **alpha101의 cross-sectional signal이 105feat의 time-series signal과 orthogonal**하기 때문이다. 단독으론 약해도 앙상블에서 complementary한 건 **서로 다른 information source**를 보고 있다는 뜻. 이건 좋은 신호다.

### H2: Bucketed CS-MLP — 피처 관점에서 근본 문제가 남아있다

H2의 아이디어는 이해하지만, **bucketizing 자체가 look-ahead bias 위험**이 있다:

1. **유동성 버킷 기준이 뭔가?** 과거 N일 평균 거래대금이면 괜찮다. 하지만 시가총액 기준이면 **당일 종가에 의존**하므로 미세하게 forward-looking이 된다.
2. **버킷 경계에 있는 종목의 regime 변화**: 한 종목이 대형→중형으로 넘어가면 갑자기 z-score 분포가 바뀐다. 이 **discontinuity가 모델을 혼란**시킨다.
3. **각 버킷 내 종목 수가 너무 적다**: 600종목 ÷ 3 = ~200종목. cross-sectional z-score의 통계적 안정성이 떨어진다. 특히 소형주 버킷은 150종목 미만일 수 있고, 그중 상당수는 거래량이 불안정하다.

**verdict**: H2는 구현 복잡도 대비 기대 효과가 낮다. H1과 H3를 먼저 소진하는 게 맞다.

### H3: Temporal z-score — **이게 가장 중요한 실험**이다

내가 가장 주목하는 건 H3다. 이유:

1. **AG CLS가 성공한 핵심 메커니즘이 바로 이것**이다 — 종목 내 시계열 패턴 학습. rolling z-score는 이걸 명시적으로 인코딩한다.
2. **non-stationarity 대응이 자연스럽다**: rolling window 안에서 정규화하면 regime 변화에 adaptive하게 반응한다.
3. 하지만 **window size 선택이 critical**하다:
   - 너무 짧으면 (20일): noise에 민감, 특히 소형주는 거래 없는 날이 많아서 z-score가 불안정
   - 너무 길면 (120일): regime 변화 반영 못함
   - **제안: 60일 rolling을 기본으로, 20일/120일도 multi-scale로 넣어볼 것**

4. **주의**: rolling z-score를 만들 때 **window 끝이 현재 시점 t를 넘으면 안 된다**. `(x_t - mean(x_{t-W:t})) / std(x_{t-W:t})`에서 t+1 이후 데이터가 들어가면 look-ahead bias다. 당연한 얘기지만 구현 실수가 잦은 부분이다.

## 추가로 빠진 관점: **피처 redundancy 정리**

2. 또는 **beta-neutral한 prediction target**을 설계: 현재 c2c_120 raw를 예측하니까 beta에 끌려다니는 거다. `c2c_120 - sector_mean(c2c_120)` 같은 **residual return**을 타겟으로 쓰면 애초에 beta 노출이 줄어든다

## 예측 타겟 자체에 대한 비판: c2c_120 binary classification

### 1. Binary classification이 정말 맞는 formulation인가?

"120분 후 올라간다/내려간다"를 맞추는 건 직관적이지만, **투자 의사결정과의 alignment가 약하다.**

- +0.01% 오른 것과 +3% 오른 것이 같은 class다. 하지만 trading에서의 가치는 300배 차이다.
- 모델이 "확실히 +0.01% 오를 것"에 높은 confidence를 줄 수 있다. binary accuracy는 높아지지만 **alpha는 0에 수렴**한다.
- AG CLS가 잘 되는 이유 중 하나가 이거다 — 종목별로 학습하면 그 종목의 평균 변동폭이 암묵적으로 calibration이 되니까. Cross-sectional 모델은 이 calibration이 깨진다.

**제안**: binary 대신 **ordinal classification** (하락/약하락/약상승/상승) 또는 **quantile regression**을 고려해야 한다. 특히 non-Top200은 변동성이 크니까 magnitude 정보가 중요하다.

### 2. c2c_120이라는 horizon 자체

120분(2시간)은 한국 시장 기준 거의 장중 반나절이다. 이 horizon에서:
- **intraday regime shift가 빈번하다**: 오전 장 분위기와 오후 장 분위기가 다른 건 트레이더라면 누구나 안다
- **점심시간 효과**: 11:30~13:00 동안 유동성이 빠지면서 가격 dynamics가 달라진다
- 120분 후 예측인데 **entry 시점이 장 초반이냐 후반이냐에 따라 의미가 완전히 다르다**

이걸 다 뭉뚱그려서 하나의 binary target으로 만든 거 자체가 **label noise의 주요 원인**이다.

**하지만** — c2c_120 고정이 제약 조건이니 이건 인정한다. 다만 **auxiliary target으로 c2c_30, c2c_60을 multi-task로 넣는 건** 제약에 위배되지 않으면서 main target의 representation을 개선할 수 있다. Expert1이 multi-scale temporal z-score를 제안했는데, feature 쪽뿐 아니라 **target 쪽도 multi-scale**로 가야 한다.

## Loss function 비판: CE + ListNet(λ=0.3)

### CE의 문제

Cross-entropy는 **calibrated probability를 학습시키는 loss**다. 그런데 우리가 원하는 건 calibrated probability가 아니라 **ranking**이다. 상위 5% 종목을 골라서 사는 거니까.

CE를 쓰면:
- 모델이 55% vs 45%를 잘 구분하는 데 capacity를 쓴다 — 이건 trading에서 쓸모없다
- 우리에겐 **95% vs 90% (top-k 안에 드느냐)**가 중요하다

### ListNet이 이 문제를 부분적으로 해결하지만

λ=0.3이면 여전히 CE가 70%를 차지한다. **ranking이 목적이라면 λ를 더 키워야 하는데, λ=0.5가 과도하다는 실험 결과가 있다.** 이건 ListNet의 구현이나 temperature 세팅 문제일 수 있지, ranking loss 자체가 나쁜 게 아니다.

**더 근본적으로**: ListNet은 **전체 리스트의 top-1 probability**를 맞추는 loss다. 우리가 원하는 건 top-1이 아니라 **top-k%를 잘 골라내는 것**이다. **LambdaRank나 ApproxNDCG** 같은 top-k에 집중하는 learning-to-rank loss가 더 적합하다.

## Expert1의 H3 지지에 동의하되, 한 가지 추가

Expert1이 H3 (temporal z-score)를 1순위로 올린 데 동의한다. 하지만 **normalization만 바꿔서는 부족하다.**

AG CLS가 성공한 건 normalization 때문이 아니라 **종목별로 별도 모델을 학습**했기 때문이다. 각 종목의 고유한 volatility regime, mean-reversion 속도, 거래 패턴을 독립적으로 학습한 거다. Temporal z-score를 넣어도 **하나의 모델이 837종목의 서로 다른 dynamics를 동시에 배우는 건** 여전히 어렵다.

**제안**: H3를 한다면 **종목 embedding + temporal z-score**를 함께 써서, 모델이 "이 종목은 이 패턴에서 이렇게 반응한다"를 학습할 수 있게 해야 한다. 또는 아예 **meta-learning 관점**에서 접근하거나.

## Validation 방식: 지금은 괜찮지만 하나 확인 필요

Temporal split (train→val→test) 자체는 올바르다. Random split이 아닌 건 좋다.

하지만 **하나 확인해야 할 것**: val 기간(10-01~12-01)과 test 기간(12-01~02-09)의 **시장 regime이 유사한가?**

만약 val 기간이 상승장이고 test 기간이 하락장이면, val에서 최적화된 하이퍼파라미터가 test에서 무의미하다. 이건 **validation을 여러 regime에 걸쳐 rolling으로 해야** 하는 이유인데, 현재 single split으로는 regime robustness를 보장할 수 없다.

## H3 (Temporal z-score)에 대해 — Expert1, Expert2 둘 다 지지하지만 내 판단은 다르다

**나는 H3를 1순위로 보지 않는다.** 이유:

### AG CLS가 성공한 건 temporal z-score 때문이 아니다

AG CLS (AutoGluon)는 내부적으로 **gradient boosting 앙상블**이다. GBM 계열이 tabular에서 강한 이유는:
- **feature interaction을 자동으로 찾는다** — split 기반이니까 non-linear interaction이 공짜
- **overfitting에 robust하다** — bagging + early stopping이 기본
- **스케일 불변이다** — tree split은 feature의 절대값이 아니라 순서만 본다

AG CLS에 temporal z-score를 넣든 raw 값을 넣든 **결과가 거의 같을 것이다.** Tree는 스케일에 무관하니까. AG CLS가 성공한 핵심은 **종목별 독립 학습 + GBM의 implicit regularization**이지, normalization 방식이 아니다.

### TabM은 이미 PLE binning으로 normalization을 해결했다

TabM의 PLE가 하는 일이 뭐냐면:
- quantile boundary로 feature를 binning
- 각 bin에서 piecewise linear encoding
- **이게 사실상 adaptive normalization이다** — distribution이 바뀌어도 quantile rank는 안정적

Temporal z-score를 TabM에 넣으면 **PLE가 이미 하는 일을 redundant하게 한 번 더 하는 거다.** 효과가 0이라는 건 아니지만, 기대만큼 dramatic하지 않을 것이다.

### 대신 내가 보는 H3의 진짜 가치

Temporal z-score 자체보다, **rolling window 기반 feature engineering**이 가치가 있다:
- `feature_t / rolling_mean(feature, 60d)` — regime-relative feature
- `(feature_t - rolling_min) / (rolling_max - rolling_min)` — range-normalized
- 이런 걸 **새 feature로 추가**하는 건 의미 있다. 기존 feature를 대체하는 게 아니라.

## 내 우선순위: 실현 가능성 + 기대 효과 기준

금융 데이터에서 10년 넘게 삽질한 경험으로 말하면, **가장 확실한 alpha source는 "이미 작동하는 걸 더 잘 하는 것"**이다.

### 1순위: 앙상블 확장 (Ens3 → Ens5+)

**이게 압도적으로 ROI가 높다.** 근거:

- Ens3 (105+alpha101+d7)가 개별 모델 대비 **절대적으로 우월**하다. 72.9% WR.
- 이건 **다른 feature set을 더 추가하면 더 좋아진다**는 뜻이다. Diversification benefit은 feature 간 상관이 낮을수록 크고, 우리는 아직 **feature set을 3개밖에 안 써봤다.**
- 구체적으로:
  - **d30 (30일 rolling features)**: d7이 중간 성능 냈으니 longer horizon도 시도
  - **alpha101 TS-only subset** (Expert1 제안에 동의): cross-sectional rank factor 빼고 pure momentum/mean-reversion factor만
  - **volume profile features**: VWAP deviation, volume-at-price 등 — 이건 105feat에 부분적으로 있지만 더 세분화 가능
  - **volatility regime features**: realized vol / implied vol ratio, vol-of-vol 등

각 feature set으로 TabM을 학습하고 → probability averaging으로 앙상블. **구현 난이도 낮고, 실패 리스크 거의 없다.**

### 2순위: Multi-task auxiliary loss (Expert2 제안 수용)

Expert2가 c2c_30, c2c_60을 auxiliary로 넣자고 했는데, **이건 금융 데이터에서 실제로 작동한다.** 이유:

- 30분/60분 horizon은 120분보다 **signal-to-noise ratio가 높다** — 짧을수록 noise가 적다
- shared representation이 **multiple horizon에서 일관된 패턴**을 잡으면, 120분 prediction의 robustness가 올라간다
- 구현: 마지막 layer를 3개 head로 분리하고, loss = CE_120 + 0.3*CE_60 + 0.1*CE_30. 이거면 된다
- **단, auxiliary target 데이터가 이미 NPY에 있는지 확인 필요.** 없으면 데이터 파이프라인부터 만들어야 해서 우선순위가 내려간다

### 3순위: 105feat redundancy 분석 (Expert1 제안 수용)

이건 **30분이면 끝나는 일**이다:
- correlation matrix → 0.9 이상 pair 제거
- feature importance (TabM의 PLE weight 기반) → bottom 20% 제거
- 결과적으로 105 → 60~70개로 줄이면 **학습 속도 30% 향상 + overfitting 감소**

모든 후속 실험에 적용되니까 빨리 하는 게 이득.

### 4순위: Expert2의 ranking loss 교체

ApproxNDCG가 CE보다 나을 수 있다는 건 이론적으로 맞다. 하지만:
- **구현 난이도가 높다** — differentiable NDCG는 gradient가 불안정하고 hyperparameter 튜닝이 까다롭다
- **ListNet λ=0.3이 이미 잘 되고 있다** — 더 좋은 loss를 찾을 수 있겠지만, expected improvement가 작다
- 금융에서의 경험칙: **loss function 바꾸는 것보다 data/feature를 바꾸는 게 3배 이상 효과적**이다

소진 후 시도할 가치는 있지만 지금은 아니다.

### 5순위 이하: H2 (Bucketed CS-MLP), 종목 embedding

- H2는 Expert1이 이미 잘 죽였다. 구현 복잡도 대비 기대 효과 낮음.
- 종목 embedding은 **개념적으로는 매력적이지만 실전에서 안 먹힌다.** 837종목에 대해 meaningful한 embedding을 학습하려면 데이터가 수십 배 더 필요하다. 종목 수가 고정이 아니라 상폐/신규상장으로 계속 바뀌는 것도 문제. Meta-learning은 더 심하다 — 학술적으로 예쁘지만 KOSPI 5분봉에서 작동한 사례를 본 적이 없다.

# Researcher2 발언: 아키텍처 관점에서의 반론과 보완

## Researcher1의 "앙상블 확장이 최우선" — 동의하되 한계를 미리 짚는다

Researcher1이 fancy한 방법론보다 simple ensemble이 낫다고 한 건 **현 시점에서는 맞다.** Ens3 → Ens5로 가는 게 ROI 최고라는 건 이론적으로도 맞고 — diversity가 있는 한 ensemble은 monotonically improve한다.

**하지만 이건 log curve다.** 3→5는 크지만 5→7은 작고, 7→10은 거의 없다. 그리고 우리가 쓸 수 있는 **orthogonal한 feature set이 유한하다.** d7, d30, alpha101 TS-only... 몇 개 더 만들 수 있나? 현실적으로 5~6개가 한계다.

**이 한계를 인식한 상태에서** Phase 1을 진행하되, Phase 3를 "나중에"가 아니라 **Phase 1과 병렬로 준비**해야 한다는 게 내 주장이다.

---

## PM이 기각한 것들 중 재고해야 할 것: Model-level Diversity

PM이 "새 아키텍처 탐색은 앙상블 포화 후"라고 했는데, **아키텍처 다양성 자체가 앙상블 성능을 올리는 가장 강력한 수단**이라는 점을 간과하고 있다.

현재 Ens3는 **TabM × 3 (feature만 다름)**이다. 같은 아키텍처에 feature만 바꾸면:
- inductive bias가 동일 → 같은 패턴을 같은 방식으로 학습
- error correlation이 높음 → **diversity가 feature 차이에만 의존**
- feature를 아무리 늘려도 **모델이 놓치는 패턴 유형은 동일**

반면 **아키텍처가 다르면**:
- GBM은 feature interaction을 step function으로 잡고, MLP는 smooth function으로 잡는다
- CNN은 local temporal pattern에 강하고, attention은 long-range dependency에 강하다
- **error가 structurally decorrelated** → 같은 feature set이어도 앙상블 효과가 크다

이건 추상적인 이론이 아니라 **Kaggle top solution의 거의 100%가 model-level diversity를 쓰는 이유**다.

### 구체적 제안: Phase 1에 P1-5 추가

```
### 실험: P1-5 — GBM (LightGBM/XGBoost) + 105feat
- 모델: LightGBM 또는 XGBoost (sklearn API)
- Feature set: 105feat (동일)
- 목적: TabM과 structurally 다른 모델로 앙상블 diversity 확보
- 핵심: TabM이 PLE로 smooth boundary를 학습하는 반면,
        GBM은 hard split으로 다른 decision boundary를 만든다
- 예상 소요: 구현 30분 (trainer 추가) + 학습 5분 (GBM은 빠르다)
- 성공 기준: 단독 성능이 TabM 이하여도 OK.
             Ens3+GBM > Ens3이면 성공.
```

**왜 GBM인가:**
- AG CLS가 내부적으로 GBM 앙상블이고, 이게 +33.2M alpha를 냈다
- 즉 **GBM이 이 데이터에서 작동한다는 건 이미 검증됨**
- TabM과의 error correlation이 낮을 것이 거의 확실 — inductive bias가 근본적으로 다르니까
- 구현이 간단하고 학습이 빠르다 — JAX 필요 없이 sklearn으로 됨

Researcher1이 "이미 작동하는 걸 더 잘 하라"고 했는데, **AG CLS가 작동한다는 건 GBM이 작동한다는 뜻**이다. 이건 새 아키텍처 탐색이 아니라 **검증된 아키텍처의 편입**이다.

## 더 먼 시야: Phase 3에서 진짜로 시도해볼 아키텍처

PM이 보류한 항목들 중 **기술적 근거가 있는 것들**을 정리해둔다. Phase 1 결과를 보고 승격 여부를 판단하자.

### 1. Temporal Fusion Transformer (TFT) — 가장 현실적

Google이 2021년에 발표한 TFT는 **시계열 예측을 위해 설계된 attention 아키텍처**다:
- Variable Selection Network: 어떤 feature가 중요한지 time step마다 동적으로 선택
- Gated Residual Network: skip connection + gating으로 overfitting 방지
- Interpretable Multi-Head Attention: 어느 과거 시점이 중요한지 시각화 가능

**왜 금융에 맞나:**
- 5분봉 데이터의 feature importance가 시간대별로 다르다 (장 초반 vs 점심 vs 장 마감)
- Variable Selection이 이걸 자동으로 학습
- Expert2가 지적한 "entry 시점에 따라 의미가 다르다" 문제를 **아키텍처 레벨에서 해결**

**단, 현재 codebase에 이미 cs_transformer.py가 있다.** 이게 TFT인지 vanilla transformer인지 확인 필요. vanilla라면 TFT로 교체하는 게 의미 있다.

### 2. TabPFN / TabR — 최신 tabular 모델

2024~2025년 tabular benchmark에서 TabM을 능가한 모델들:
- **TabPFN**: pre-trained prior로 few-shot에서 강함. 하지만 우리 데이터는 충분히 크니까 이점이 적을 수 있다.
- **TabR**: retrieval-augmented tabular learning. 현재 sample과 유사한 과거 sample을 찾아서 prediction에 활용. **regime-adaptive prediction에 자연스럽게 연결**된다.

TabR이 특히 흥미로운 이유:
- Expert2가 말한 "val과 test의 regime이 다르면?" 문제에 대한 아키텍처적 해답
- 비슷한 시장 상황(과거 sample)을 참조해서 예측하니까 **regime shift에 robust**
- 하지만 retrieval index 구축 + inference 속도가 issue

### 3. Mamba (SSM) — 솔직히 여기선 아직

Mamba가 long-range dependency에서 Transformer보다 효율적인 건 맞지만, **우리 문제는 single time step feature → prediction이지 sequence modeling이 아니다.** 5분봉 시계열을 sequence로 넣으려면 데이터 파이프라인을 근본적으로 바꿔야 하고, 그건 Phase 3 이후의 이야기다.
