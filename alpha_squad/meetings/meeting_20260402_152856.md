## 현황 진단: MLP의 구조적 한계

오늘 실험 결과에서 가장 중요한 신호는 **"HP 튜닝 전부 실패 + epoch 0~15 early stop + val_acc 32.3%"** 입니다. 이건 모델이 데이터에서 유의미한 패턴을 거의 학습하지 못하고 있다는 뜻입니다. MLP의 inductive bias로는 이 문제를 풀기 어렵다는 증거입니다.

구체적으로:
1. **MLP는 feature 간 interaction을 암묵적으로만 학습** — 100개 feature 간의 어떤 조합이 유의미한지 스스로 찾아야 함
2. **Cross-stock 관계를 전혀 모델링하지 않음** — KOSPI200 종목 간 섹터 로테이션, 상관관계 무시
3. **시간축 구조 없음** — 5분봉 window를 flat vector로 보니 multi-scale 패턴 손실

## 제안 1: **StockMixer** (최우선, MLP 진화형)

> 출처: StockMixer (AAAI 2024) — MLP 기반이면서 Transformer를 능가

**왜 이게 맞는가:**
- 3단계 MLP pipeline: (1) indicator mixing → (2) multi-scale time patch mixing → (3) cross-stock mixing
- **현재 CS-MLP와 같은 MLP 계열**이라 구현 난이도 낮음
- 핵심 차이: time axis를 여러 scale의 patch로 나눠서 mixing — 현재 flat vector 대비 시간 구조 보존
- Cross-stock mixing이 섹터 로테이션 포착 가능

**구현 비용**: 새 trainer + architecture 파일. 기존 plugin 구조에 맞음. 1일 내 가능.

## 제안 2: **ReVol Normalization** (최소 비용, 최대 ROI)

> 출처: ReVol (CIKM 2025) — backbone-agnostic preprocessing wrapper

**왜 이게 맞는가:**
- **Backtest→Reference 갭(-3.8M)의 주요 원인이 distribution shift**일 가능성 높음
- ReVol은 return + volatility + scale로 정규화 → 모델은 residual만 학습 → 재통합
- 어떤 모델 위에든 씌울 수 있음 — **기존 CS-MLP에 바로 적용 가능**
- 논문 기준 IC +0.03, Sharpe +0.7 개선 (backbone 무관)

**구현 비용**: preprocessing/postprocessing wrapper. 모델 코드 변경 불필요. 반나절.

## 제안 3: **AlphaMix (MoE)** — HP 탐색을 앙상블로 전환

> 출처: AlphaMix (KDD 2023)

## Researcher2, 아키텍처 제안 전에 데이터가 보내는 신호를 먼저 읽으세요.

FT-Trans+base100 실험? 동의합니다. 10분이니까 하면 됩니다. 하지만 StockMixer, ReVol, AlphaMix — 이건 **"모델이 더 잘 학습하면 alpha가 나온다"는 전제**인데, 그 전제부터 의심해야 합니다.

## 1. val_acc 32.3%가 말해주는 것: **label이 쓰레기다**

5-class random baseline이 20%이고, 현재 32.3%입니다. 12.3%p 개선. 이 수준에서 아키텍처를 바꿔봤자 33→35% 가는 게 고작입니다.

**핵심 질문: 왜 5-class인가?**

현재 c2c_120 수익률을 5개 bin으로 잘라서 classification하고 있습니다. 이 bin 경계가 어떻게 설정되어 있는지, 각 class의 분포가 어떤지 — `y_train.npy not found`라서 확인도 안 됩니다. 하지만 구조적으로:

- 5분봉 120분 수익률의 **SNR은 극히 낮음** — noise 대비 signal이 거의 없는 label
- 5개 class 경계가 noise band 안에 있으면, **class 2-3-4 구분은 본질적으로 불가능** (동전 던지기)
- 모델이 학습하는 건 패턴이 아니라 **noise의 distribution**

**제안: 3-class로 축소하거나, 극단값만 binary로 예측하라.** Class 수를 줄이면 label noise가 줄고, 모델이 실제로 학습 가능한 signal-to-noise ratio가 올라갑니다.

---

## 2. sim ≠ trade fill 역전 — 이건 **모델 문제가 아닙니다**

Researcher2가 정확히 짚었습니다. dropout=0.2가 sim BEST인데 trade fill WORST라는 건:

- **sim에서 높은 확신(low dropout) → 극단적 포지션 → trade fill에서 슬리피지 폭발**
- dropout=0.4가 trade fill에서 나은 이유: 예측이 보수적 → 덜 극단적 포지션 → 실행 가능한 체결

이건 **loss function 문제**입니다. 현재 CE loss는 "맞추는 것"을 최적화하지, **"실행 가능한 예측"을 최적화하지 않습니다.**

구체적으로:
- CE는 prob을 극단(0 or 1)으로 밀어붙임 → 확신 높은 예측 → 큰 포지션 → 체결 비용 증가
- **IC-weighted loss나 Sharpe loss**는 "순위를 맞추되, 전체 포트폴리오 수익을 최적화" → 포지션 크기가 자연스럽게 조절됨

---

## 3. score4 > score2인 이유도 같은 맥락

score4 = (prob_3+prob_4) - (prob_0+prob_1)은 **양극단의 차이**를 보는 것이고,
score2 = prob_4 - prob_0은 **가장 극단적 class만** 봅니다.

score4가 나은 이유: class 3과 class 1의 정보를 활용함으로써 **noise에 덜 민감**해짐. 이건 본질적으로 **"5-class가 과분할"**이라는 증거입니다. 중간 class의 정보를 합쳐야 신호가 나온다는 뜻이니까요.

---

## 4. Candle → Trade fill 5배 괴리: **타겟 자체가 tradeable alpha와 misaligned**

Candle backtest alpha +2.9M → Trade fill +0.58M. 이 괴리는:

- 모델이 예측하는 것: c2c_120 수익률의 class
- 실제 필요한 것: **체결 비용 차감 후 수익**

모델은 "이 종목이 올라갈 것 같다"를 학습하지만, **얼마나 올라가야 체결 비용을 이기는지**는 모릅니다. 이건 아키텍처를 바꿔도 해결 안 됩니다.

**제안: label을 net-of-cost return으로 재정의하거나, loss에 transaction cost penalty를 넣어라.**

## Expert2의 진단에 대체로 동의합니다. 하지만 순서가 다릅니다.

Expert2가 "label이 쓰레기다"라고 했는데, 방향은 맞지만 **32.3%가 5-class에서 쓰레기라는 판단은 성급합니다.** 금융 시계열에서 이 수준의 accuracy가 나오면 실제로는 꽤 의미 있는 신호입니다. 문제는 accuracy 자체가 아니라 **그 신호가 tradeable alpha로 변환되는 경로**입니다.

---

## 1. 3-class vs 5-class — 동의하지만 이유가 다릅니다

Expert2는 "noise 감소"를 이유로 3-class를 제안했는데, 실제 효과는 다른 곳에 있습니다:

- **5-class에서 score4가 score2를 이기는 이유**: Expert2 말대로 중간 class 정보를 합쳐야 신호가 나옴
- 그런데 **이미 score4가 사실상 binary signal** (상위2 vs 하위2)로 쓰이고 있음
- 5-class 학습 → score4로 2-class 변환 → 이 과정에서 **학습 목표와 평가 목표가 misaligned**

**그래서 3-class가 아니라 binary (up/down)가 맞다고 봅니다.** 어차피 최종 결정은 long/short이니까. flat class는 "거래 안 함"인데, 이건 zscore threshold가 이미 처리하고 있습니다.

단, **주의점**: class 수를 줄이면 class boundary 근처의 noisy sample이 더 많은 비중을 차지함. 이걸 해결하려면 **boundary 근처 sample 제거 (margin-based filtering)**가 필요합니다. 예: 수익률 ±0.1% 이내는 학습에서 제외.

---

## 2. Loss 변경 — 여기서 Expert2와 강하게 동의합니다

CE loss의 문제를 금융 데이터 관점에서 더 구체적으로 말하면:

- CE는 **calibration을 최적화**함 — "이 종목이 올라갈 확률이 정확히 63%"
- 트레이딩에 필요한 건 **ranking** — "이 종목이 저 종목보다 더 올라갈 가능성이 높은가"
- 이 둘은 다른 목적함수임

**실제로 작동하는 대안들** (금융 시계열에서 검증된 것):

| Loss | 장점 | 구현 난이도 |
|------|------|------------|
| **ListMLE / ListNet** | 직접 ranking 최적화 | 중 |
| **Pairwise margin loss** | 종목 간 상대 순서 학습 | 하 |
| **IC loss** (= Pearson(pred, return)) | 직접 IC 최적화 | 하 |

특히 **IC loss는 regression으로의 전환**과 같습니다 — classification 자체를 버리고 continuous return을 예측한 뒤 ranking으로 쓰는 방식. 금융 ML 실무에서 classification보다 regression+ranking이 더 잘 작동하는 경우가 많습니다.

---

## 3. FT-Trans + base(100feat) — 이건 논의할 것도 없이 지금 당장

Researcher2 말대로 **이건 10분짜리인데 안 한 게 실수**입니다. 역사적으로 FT-Trans가 앙상블의 핵심이었고, feature ablation에서 base(100feat)이 압도적이었는데 이 조합을 테스트 안 했다는 건 실험 설계의 빈틈입니다.

## 4. Researcher2의 StockMixer/ReVol에 대한 feasibility check

### StockMixer
- **긍정적**: MLP 계열이라 기존 파이프라인과 호환, cross-stock mixing은 KOSPI200에서 의미 있음
- **우려**: 논문은 일봉 기준 실험. 5분봉에서 cross-stock correlation 구조가 다를 수 있음. 5분봉은 noise가 훨씬 많고 cross-stock signal이 약함
- **판단**: 시도할 가치 있지만, **label/loss 문제 해결 후에**. 지금 구현하면 같은 쓰레기 label에 더 복잡한 모델

### ReVol
- **긍정적**: 구현 비용 낮고, distribution shift 대응은 금융 데이터에서 항상 중요
- **우려**: KOSPI200은 유동성 높은 대형주라 distribution shift가 소형주 대비 덜 심각. 효과가 제한적일 수 있음
- **판단**: 시도할 가치 있지만 **게임 체인저는 아닐 것**. normalization으로 +0.58M → +5M은 불가능

### AlphaMix
- **가장 회의적**: 역사적 best가 앙상블이었던 건 맞지만, 그때는 개별 모델들이 **각각 양의 alpha**를 냈음. 지금은 **개별 모델 대부분이 음의 alpha** — 쓰레기를 섞으면 더 큰 쓰레기
- **판단**: 개별 모델 성능이 올라간 후에 논의

## 수용하는 것

**"label/loss를 먼저 고쳐라"** — 논리적으로 맞습니다. 인정합니다.

제가 처음에 "더 좋은 모델"에 집중한 건, 회의 안건 우선순위가 "1) 다양한 모델 2) 피처 3) 최적화"였기 때문입니다. 하지만 데이터가 말하는 건 명확합니다:

- val_acc 32.3%에서 아키텍처를 바꿔서 35%로 올려봤자, 그 +2.7%p가 trade fill alpha에서 의미 있는 차이를 만들 가능성은 낮음
- **score4가 score2를 이기는 현상 자체가 "5-class는 과분할"이라는 실증적 증거** — Expert2의 이 분석은 정확합니다
- sim/trade fill 역전이 CE의 극단 확신 문제라는 Expert2의 진단도 동의합니다

---

## 반박 1: Binary보다 **3-class가 낫다** (Researcher1에 대한 반박)

Researcher1이 "어차피 long/short이니 binary"라고 했는데, **이건 scoring function의 역할을 무시하는 겁니다.**

현재 시스템 구조:
```
모델 출력(class prob) → score 계산 → zscore threshold → long/short 결정
```

Binary classification이면 모델 출력이 이미 long/short 결정이 됩니다. 그러면 **zscore threshold로 "확신 없는 건 거래 안 함"을 구현할 수 없습니다.** prob(up)=0.52인 종목도 long을 치게 됨.

3-class (up/flat/down)라면:
- flat class의 probability가 높은 종목 = 확신 없음 → 자연스럽게 필터링
- score = prob(up) - prob(down) → zscore threshold과 호환
- **학습 목표와 평가 목표의 alignment가 5-class보다 훨씬 좋음**

Researcher1의 "margin filtering" (boundary 근처 sample 제거)도 유효하지만, 이건 **3-class에서도 적용 가능**합니다. 3-class + margin filtering이 binary + margin filtering보다 구조적으로 건전합니다.

---

## 반박 2: **ReVol과 아키텍처 변경은 label 수정과 병렬로 가능하다**

Expert2와 Researcher1 모두 "먼저 label, 그다음 아키텍처"라고 했는데, 이건 **직렬 사고**입니다. GPU 1장이라 학습은 하나씩이지만, **구현은 병렬로 할 수 있습니다.**

- label/loss 실험 돌리는 동안 → StockMixer architecture 코드 구현
- label 실험 결과 나오면 → 같은 label/loss 설정으로 StockMixer도 바로 실험

"label을 먼저 고친 뒤에 아키텍처를 논하자"는 건 시간 낭비입니다. **둘 다 준비해두고, 좋은 label이 확정되면 즉시 다양한 아키텍처로 실험하는 게 효율적입니다.**

Researcher1의 **"쓰레기를 섞으면 더 큰 쓰레기"**라는 지적이 정확합니다. 개별 모델이 대부분 음의 alpha인 상태에서 MoE는 의미 없습니다. 개별 모델이 양의 alpha를 내기 시작하면 그때 다시 논의합시다.

## 하나 더 — Researcher1의 "regression 전환" 아이디어에 대해

IC loss가 사실상 regression이라는 Researcher1의 지적은 기술적으로 맞습니다. 그런데 이걸 진지하게 고려한다면, **architecture 관점에서 regression에 최적화된 모델은 classification에 최적화된 모델과 다릅니다.**

- Classification: softmax → discrete decision boundary 학습
- Regression: continuous output → **TabM이나 FT-Transformer가 원래 regression 용으로 설계됨**

현재 코드베이스에 Tab-M이 이미 있지만 "학습 실패"로 기록되어 있습니다. **Regression 전환 시 Tab-M을 다시 시도할 가치가 있습니다** — 이 모델은 classification보다 regression에서 성능이 나오는 구조입니다.

# Researcher3 (PM) — 최종 종합 판정 및 실험 스펙 확정

## 합의/분쟁 정리

### 전원 합의 (즉시 채택)
- **FT-Trans + base(100feat) 즉시 실행** — 논의 불필요. 10분짜리 미테스트 조합.
- **label/loss 개선이 아키텍처보다 우선** — Researcher2도 최종적으로 수용.
- **AlphaMix(MoE) 철회** — 개별 모델이 음의 alpha인 상태에서 앙상블 무의미.

### 분쟁 1: 3-class vs Binary
| | 3-class (Researcher2) | Binary (Researcher1) |
|--|----------------------|---------------------|
| 근거 | flat class가 "확신 없음" 자연 필터링, zscore threshold 호환 | 최종 결정이 long/short, margin filtering으로 noise 제거 |
| 리스크 | flat class 경계 설정이 자의적 | prob 0.52도 long 되는 문제 |

**PM 판정: 3-class 채택.**

이유:
1. 현재 시스템이 `score → zscore threshold → long/short` 파이프라인. Binary로 바꾸면 **zscore 필터링 로직 전체를 재설계**해야 함 — 비용 대비 이득 불명확
2. 3-class의 flat은 "모르겠다"를 명시적으로 학습. 이건 금융에서 가치 있는 정보
3. Researcher1의 margin filtering은 3-class에서도 적용 가능 — 두 방법론은 배타적이지 않음
4. **단, margin filtering도 함께 적용한다.** up/down 경계 근처 ±0.05% 이내 sample 제외

### 분쟁 2: 아키텍처 준비 병렬 vs 직렬
**PM 판정: Researcher2의 "병렬 준비" 수용. 단, 구현 우선순위는 label/loss가 먼저.**

StockMixer 코드는 label/loss 실험 돌리는 "대기 시간"에 준비하되, **label/loss 결과가 확정되기 전에는 StockMixer 학습을 돌리지 않는다.** 쓰레기 label로 새 아키텍처를 평가하면 결론이 오염됨.

### 분쟁 3: Regression 전환
Researcher1이 "IC loss = 사실상 regression"이라 했고, Researcher2가 "Tab-M은 regression에서 성능이 나온다"고 보충. **유망하지만 보류.**

이유: regression 전환은 파이프라인(score 계산, 백테스트 연동) 변경 범위가 큼. 3-class + ranking loss로 먼저 개선 확인 후, 그래도 부족하면 다음 회의 agenda로.

## 2. **class_bins가 절대값이다 — 이게 가장 큰 문제**

`configs/data/260401_200_*.yaml`의 class_bins:

```yaml
class_bins:
  - -0.01      # <-1%
  - -0.003     # -1% to -0.3%
  - 0.003      # -0.3% to +0.3%
  - 0.01       # +0.3% to +1%
```

**이건 절대 수익률 기준입니다.** KOSPI200이 02-23~03-31 사이에 -11.46% 폭락한 환경에서:

- 하락장에서 class 0(-1% 이하)과 class 1(-0.3%~-1%)에 sample이 몰림
- 상승장에서는 class 3(+0.3%~+1%)과 class 4(+1% 이상)에 몰림
- **class 분포가 regime마다 완전히 달라짐** → 모델이 학습한 class boundary가 test에서 무의미

Expert2가 "label이 쓰레기"라고 했는데, **쓰레기인 이유가 여기 있습니다.** 5-class냐 3-class냐가 아니라 **절대 수익률 vs cross-sectional percentile** 문제입니다.

### 구체적 제안: **cross-sectional percentile 기반 class_bins**

```
# 매 시점 t에서 200종목의 c2c_120 수익률을 cross-sectional로 ranking
# 하위 20% → class 0, 20-40% → class 1, ..., 상위 20% → class 4
```

이렇게 하면:
- **class 분포가 항상 균일** (각 class 20%)
- **regime 변화에 invariant** — 시장이 폭락하든 폭등하든 상대 순위는 유지
- score4 = (prob_3+prob_4) - (prob_0+prob_1)이 **market-neutral alpha signal**로 작동

**현재 시스템은 absolute return을 예측하고 있습니다. 우리가 실제로 필요한 건 cross-sectional ranking 예측입니다.**

## 3. PM의 3-class 제안에 대한 수정 의견

PM이 "상위 33%/중간 34%/하위 33% (percentile 기반)"을 제안했는데, **percentile 기반이면 class 수보다 이게 핵심 변경입니다.** 

현재 절대값 5-class를 percentile 5-class로 바꾸는 것과, 절대값을 percentile 3-class로 바꾸는 것은 **두 가지 변수를 동시에 바꾸는 겁니다.** 실험 설계상:

| 실험 | class 수 | bin 기준 | 변경 변수 |
|------|---------|---------|----------|
| 현재 | 5 | 절대값 | - |
| PM 제안 | 3 | percentile | 2개 동시 변경 (위험) |
| **내 제안 A** | **5** | **percentile** | 1개만 변경 |
| 내 제안 B | 3 | percentile | 1개만 변경 (A 이후) |

**실험 1을 두 단계로 쪼개야 합니다:**
- **1a**: 5-class percentile (현재 아키텍처 그대로, bin 기준만 변경)
- **1b**: 3-class percentile (1a 결과 보고 결정)

5-class percentile만으로도 상당한 개선이 올 수 있습니다. 왜냐면 **현재 문제의 핵심이 class 수가 아니라 bin 기준의 non-stationarity**이기 때문입니다.

## Expert1, 당신이 이 회의에서 가장 중요한 발견을 했습니다.

## 1. Expert1의 percentile bins 제안 — 전면 동의하되, 한 단계 더

Expert1이 맞습니다. Cross-sectional percentile로 바꾸면:

- Class 분포가 **시장 regime에 invariant** — 폭락장이든 횡보장이든 각 class 20%
- 모델이 학습하는 것이 "이 종목이 0.3% 이상 오르나"가 아니라 **"이 종목이 다른 종목보다 상대적으로 잘하나"** — 이게 long/short alpha의 정의 그 자체

**그런데 이걸 인식하면, 실험 1a/1b 분리 제안에 대한 제 판정이 달라집니다.**

Expert1이 "변수 하나씩 바꿔라"고 했는데, 실험 설계론적으로는 맞습니다. 하지만 **현재 절대값 bins와 percentile bins는 질적으로 다른 문제 정의**입니다. 이건 하이퍼파라미터 튜닝이 아니라 **문제 자체를 재정의**하는 것입니다.

| | 절대값 bins | Percentile bins |
|--|-----------|----------------|
| 모델이 학습하는 것 | absolute return 예측 | **cross-sectional ranking** |
| Market exposure | 있음 (상승장 bias) | **없음 (market-neutral)** |
| Regime robustness | ❌ | ✅ |

**5-class percentile이면 사실상 ranking 문제로 전환된 겁니다.** 그리고 이 경우:

- score4 = (prob_3+prob_4) - (prob_0+prob_1)이 **cross-sectional alpha signal**로 정확히 작동
- ListNet loss와의 **alignment가 자연스러워짐** — label도 ranking, loss도 ranking
- 제가 앞서 주장한 "CE가 극단 확신 문제"도 **상당 부분 완화** — percentile class는 균일 분포라 CE가 한쪽으로 쏠리지 않음

## 2. 제 기존 주장 수정: 3-class는 보류

솔직히 말하겠습니다. 제가 "3-class로 줄여라"고 한 건 **절대값 bins 전제에서** 맞는 주장이었습니다. 절대값 bins에서는 class 경계가 noise band 안에 있으니 class 수를 줄이는 게 noise 감소에 효과적이었죠.

**그런데 percentile bins로 바꾸면 5-class도 clean합니다.** 각 class가 정확히 20%씩이고, class 경계가 market regime에 안정적이니까요. 3-class 실험(1b)은 1a 결과를 보고 결정하는 Expert1의 안에 동의합니다.

- **sim ≠ trade fill 역전 문제**: percentile bins로 바꿔도 CE의 극단 확신 경향은 남음. ListNet이 이걸 완화할 수 있지만, **percentile 5-class CE vs percentile 5-class ListNet 비교가 필수** (실험 1a vs 1b)
- **Regression 전환 보류**: PM 판정 동의. 하지만 **percentile bins + ListNet이면 사실상 ranking regression과 매우 유사한 formulation**. 명시적 regression 전환의 한계 이득이 줄어들 수 있음

## 5. 최종 경고: **피처도 cross-sectional rank로 바꿔야 완성된다**

Expert1이 "피처 82개가 절대값"이라고 짚었습니다. **label을 percentile로 바꿨는데 feature가 절대값이면 half-fix입니다.**

- Label: "200종목 중 상위 20%에 들 종목을 맞춰라"
- Feature: "이 종목의 price_diff가 0.003이다" (절대값)

모델은 **절대값 feature로 상대적 ranking을 예측**해야 합니다. 가능은 하지만, **feature도 cross-sectional rank면 모델의 job이 훨씬 쉬워집니다.** Input과 output이 같은 공간(rank)에 있으니까요.

단, 이건 NPY builder 수준의 변경이 필요하므로 **실험 3번 이후로** 배치하는 게 맞습니다. 지금은 label부터.

## 1. 제 기존 주장 수정: Binary → Percentile 5-class

제가 "binary + margin filtering"을 주장했는데, **Expert1의 percentile bins 발견 이후 전제가 바뀌었습니다.**

- 절대값 bins에서는 class 경계가 noise band에 걸려서 class 수를 줄이는 게 맞았음
- **Percentile bins에서는 5-class도 clean** — 각 class 정확히 20%, regime invariant

**Binary 주장을 철회하고 percentile 5-class를 지지합니다.** 3-class는 1a 결과 보고 판단하는 Expert1 안이 실험적으로 가장 건전합니다.

---

## 2. 왜 percentile이 "게임 체인저"인지 — 금융 데이터 관점

제가 금융 시계열을 다뤄온 경험에서 말하면, **cross-sectional percentile label은 사실상 market-neutral alpha를 직접 타겟팅하는 것**입니다.

현재 절대값 bins의 문제를 구체적으로:

- 02-23~03-31 KOSPI -11.46% 하락장 → c2c_120이 전반적으로 음수 → **class 0-1에 sample 쏠림**
- 모델은 "시장이 빠질 때 대부분 종목이 빠진다"를 학습 → **market beta를 학습하는 것**
- trade fill에서 long/short 양쪽을 치면 market beta는 상쇄 → **alpha가 0에 수렴**

이게 바로 **Alpha ≈ 0인 이유**입니다. 모델이 alpha가 아니라 beta를 학습하고 있었습니다.

Percentile로 바꾸면:
- 하락장에서도 "상대적으로 덜 빠지는 종목"이 상위 class
- 모델이 학습하는 건 **종목 간 상대 강도** = alpha의 정의 그 자체
- long/short에서 market exposure가 자연스럽게 제거됨

**이전 회의(03-21)에서 "alpha label (return - beta*market)" 아이디어가 나왔는데, percentile bins가 이걸 암묵적으로 달성합니다.** Beta 추정 없이.

---

## 3. ListNet + Percentile bins = 자연스러운 조합

Expert2가 정확히 짚었습니다. Percentile label + ListNet은 **label도 ranking, loss도 ranking**으로 완전히 aligned됩니다.

제가 앞서 "IC loss = 사실상 regression"이라고 했는데, **ListNet + percentile 5-class는 ranking regression의 이점을 classification 프레임워크 안에서 얻는 방법**입니다. 파이프라인(score → zscore → long/short) 변경 없이.

그래서 PM이 보류한 "regression 전환"의 필요성이 **상당히 줄어듭니다.** Percentile + ListNet으로 충분할 가능성 높음.

## 5. Cross-sectional feature rank — 동의하지만 타이밍에 주의

Expert1이 "피처 82개도 절대값"이라고 했는데, 맞습니다. 하지만:

- Percentile label만 바꿔도 **모델이 "절대값 feature에서 relative ranking을 추론"하는 건 가능**. 어렵지만 불가능하지 않음
- Feature rank 변환은 **NPY builder 수준 변경** — 실험 0/1a/1b와 분리해야 함
- **먼저 label만 바꿔서 효과를 확인하고, 부족하면 feature rank를 추가**하는 게 변수 통제상 맞음

Expert1의 실험 3 배치에 동의합니다.

## 6. 한 가지 위험 플래그: Percentile label의 NPY 생성 방식

Percentile bins를 구현할 때 **train/val/test split에서 leakage가 없는지 확인 필수**:

- 시점 t에서 200종목의 c2c_120을 cross-sectional percentile로 변환 → 이건 같은 시점의 다른 종목 정보를 사용
- **이건 look-ahead가 아닙니다** — 같은 시점 t의 cross-section이니까. 미래 정보 아님
- 단, **NPY 생성 시 train 기간의 percentile 통계가 val/test로 새지 않도록** 주의. 각 시점별로 독립 계산이면 문제 없음

## 이 회의의 핵심 교훈

> **"모델이 alpha가 아니라 beta를 학습하고 있었다."**

절대값 class_bins → 시장 방향성(beta)이 가장 강한 신호 → 모델이 beta를 열심히 학습 → long/short에서 beta 상쇄 → alpha ≈ 0.

이건 아키텍처를 바꿔도, loss를 바꿔도, 피처를 추가해도 해결 안 되는 **문제 정의의 오류**였습니다. Expert1이 코드를 직접 봐서 발견했고, Expert2가 이론적으로 확인했고, Researcher1이 금융 데이터 관점에서 메커니즘을 설명했습니다.
